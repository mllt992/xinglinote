# 04 双链、反向链接与跨工作区

## 1. 范围

管：`[[wikilink]]` 语法、解析、消歧、未创建链接、改名回写、反向链接、未链接提及、一层嵌入、局部图谱、跨区链接、公开场合如何渲染。  
不管：普通 URL 链接、搜索框（05）、分享 URL（07）。

核心合同：**源码存标题，库内绑 UUID。**

---

## 2. 对象与状态机

### 2.1 源码形态（写入 .md 的唯一合法形式）

```
[[标题]]
[[标题#章节]]
[[标题|显示名]]
[[标题#章节|显示名]]
[[路径/标题]]           # 可选消歧，路径用 / ，相对当前本或写 工作区slug/本slug/目录/标题
![[标题]]               # 嵌入笔记
![[标题#章节]]
![[附件.png]]           # 嵌入当前笔记或同本附件
```

不在源码里写 UUID。导出给 Obsidian 时保持上述形式。

### 2.2 Link 表（库内）

| 字段 | 说明 |
|---|---|
| from_note_id | |
| raw | 源码里的原文，如 `[[会议纪要#决议\|纪要]]` |
| target_note_id | 可空（未解析 / 已删 / 未创建） |
| target_heading | 可空 |
| display | 可空 |
| kind | `wiki` / `embed` / `embed_file` |
| state | `resolved` / `unresolved` / `trashed` / `invisible` |
| pos | 正文偏移，用于回写 |

一篇笔记保存后：**先删该篇全部 outgoing，再按解析结果插入**。反向链接 = 查 `target_note_id = me AND state in (resolved, invisible, trashed)`。

`invisible`：目标存在，但当前保存者解析时选中了它；其他读者按自己的 ACL 再决定看不看得见。库内仍绑 ID，避免「我看不见就当没链」。

### 2.3 标题索引

维护 `TitleIndex(workspace_id, notebook_id, folder_id, norm_title, note_id, is_alias)`。  
标题与 aliases 都登记。trash 的笔记移出活索引，进 `TitleIndexTrashed` 供状态 `trashed`。

## 3. 交互

### 3.1 输入补全

键入 `[[` 弹出：当前本匹配 → 本工作区 → 我的其他工作区。每条显示 `工作区 / 笔记本 / 路径 / 标题`。选中后源码只写入：

- 本本无歧义：`[[标题]]`
- 本区有歧义：`[[目录/标题]]` 或 `[[本slug/目录/标题]]`
- 跨区：`[[区slug/本slug/目录/标题]]`

用户也可不选，直接打字离开，按 5.2 消歧。

### 3.2 渲染（编辑器预览 / 已登录库内）

| 状态 | 样式 | 点击 |
|---|---|---|
| resolved 且 can_read | 正常内链 | 打开目标（跨区则切工作区） |
| unresolved | 虚线下划线 | 在当前目录创建该标题笔记并改本链为 resolved |
| trashed | 「已删除」 | 若能看回收站则提供恢复，否则无动作 |
| 目标存在但 !can_read | 「无权限」 | 无跳转，不暴露标题以外的正文；标题用用户写下的 raw 标题，不补官方现标题也可以，建议显示 raw |

### 3.3 反向链接抽屉

分组：本工作区 / 其他工作区。每条摘录所在句。`invisible` 对**当前读者**若不能读 from 笔记，则整条不出现（反向链接也走 `can_read(from)`）。

### 3.4 未链接提及

对当前笔记标题（及 aliases）在本工作区其他笔记正文中的字面出现，且未包在 `[[ ]]` 内。只读列表「提及但未链接」，提供「转成双链」按钮（改对方正文，需 `can_edit` 对方，否则只提示）。一期不做跨区未链接提及。

### 3.5 局部图谱

节点：本篇 + 所有 resolved 出链 + 所有 can_read 的入链。一层。点节点打开笔记。

### 3.6 嵌入

`![[笔记]]` 展开目标渲染后的一层 HTML。目标再有 `![[ ]]` 显示成普通双链，不继续展开。无权 / 已删 / 未解析：占位卡片，不把目标正文泄漏。循环 A↔B：两边都只展开一层，自然断开。

## 4. 业务规则

1. 代码块、行内代码、` ``` ` 围栏内不解析。
2. 大小写不敏感、Unicode NFKC。
3. 同目录活笔记标题不得重名（03 已保证），跨目录可以。
4. 改标题 / 改 alias / 移动：更新 TitleIndex，然后 **回写所有指向该 ID 的源码 raw 标题部分**，保留 `#节` 与 `|显示名`。
5. 回写是一次系统保存：`source=link_rewrite`，version+1，不把编辑器脏状态 silently 覆盖——若目标篇此时 dirty，等其保存后再回写或对打开者推「源码已更新请加载」。
6. 用户手动把 `[[A]]` 改成 `[[B]]`：按新标题重新解析，换 target id。
7. 未创建链接允许长期存在。点击创建时用 raw 标题，落在**点击时所在笔记的目录**。
8. 公开场合（文档站、分享、广场）规则见 5.4，宁可不做成链，不可链到未公开内容。
9. MCP `get_backlinks` 只返回 actor 能读的 from 笔记。

## 5. 算法

### 5.1 抽取

Markdown 词法扫描，跳过 fenced/inline code。匹配：

```
!?? [[  target  ( # heading )?  ( | display )?  ]]
target 可含 /
```

### 5.2 解析消歧 `resolve(raw_target, from_note, actor)`

`raw_target` 拆成可选前缀路径 + 标题。

```
candidates = TitleIndex where norm_title == norm(title) AND note not trashed

if raw 含路径:
    用 slug/目录 从左过滤 candidates
    若恰好 1 个: resolved
    若 0 个: unresolved
    若多个: 取最近（见下）仍多个则 unresolved 并在 UI 标歧义

if raw 无路径:
    1. 同笔记本 + 同目录
    2. 同笔记本
    3. 同工作区
    4. actor 其他工作区（仅当恰好 1 个命中；多个则不自动跨区，保持 unresolved，逼用户用补全）
    每一档若恰好 1 个: 采用
    每一档若多个: 不进入下一档，标歧义 unresolved
```

别名与标题同等参加匹配。  
解析在保存时以**作者**为 actor 绑定 ID。读者渲染时：已有 ID 则不再按标题找，只查 ID + 对该读者 `can_read`。

这是「源码标题、库内 ID」的关键：绑定之后改名不丢；读者也不因自己那边恰好有同名篇而串台。

### 5.3 改名回写

```
on title_changed(note, old, new):
  update TitleIndex
  for link in Link where target_note_id == note.id:
      解析 link.raw，替换标题段为 new（保留路径?）
      路径若仍正确（只改了标题）: [[路径/new#节|显示]]
      若用户源码无路径: [[new#节|显示]]
      写回 from.body 对应 pos
      批量保存 from，source=link_rewrite
```

移动目录不强制给源码加路径。只有原来带路径且路径失效时，才把路径改成新路径以免下次被人当纯标题重新解析错。

### 5.4 公开渲染 `render_wiki_for_public(link, target)`

目标可被公开看到，当且仅当下列之一：

- 目标 `published=true` 且所属笔记本当前「文档站已发布」
- 存在一条对目标笔记或祖先目录仍然有效的分享链接（不自动把分享 token 塞进 href，只当「是否公开」的证据——公开站内链到另一篇已发布篇，用文档站 URL；链到仅分享未发布的篇，显示纯文本，避免泄漏 `/p/token`）

否则：输出显示名或标题纯文本，无 href。

广场帖里的 `[[ ]]` 同样走这套。圈子帖里对成员走库内渲染。

### 5.5 附件嵌入

`![[foo.png]]`：先当前笔记附件，再同目录笔记附件。找到则 `<img>`。找不到当 unresolved。不跨区找附件，防误嵌私图。

## 6. 与其他功能的关联

| 方向 | 关系 |
|---|---|
| ← 03 | 保存/改名/移动触发；创建未命名不进标题索引直到有非空标题 |
| → 05 | 搜索结果里的高亮不负责解析双链 |
| → 07 | 文档站导航是目录树，正文双链走 5.4 |
| → 09 | 帖子正文复用抽取；公开用 5.4，圈子用库内 |
| → 10 | 向量切片用「解析后纯文本」，嵌入内容不重复切片（只在源笔记切） |
| → 11 | `get_note` 返回源码 + 已解析 links 数组（id、state），方便 Agent |
| → 12 | trash → 相关 Link.state=trashed；restore 再 resolved |

发出：随 `NoteUpserted` 重解析完成即可，不必单独事件。回写产生的保存也发 `NoteUpserted(change=content)`，索引订阅时注意防回环：`source=link_rewrite` 不再触发二次回写。
