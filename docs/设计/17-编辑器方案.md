# 17 编辑器方案

## 1. 范围

管：编辑器内核选型、渲染器归一、快捷键、外壳（折叠 / 大纲 / 状态栏）的落地口径。
不管：保存与冲突算法（03）、双链解析（04）、附件上传（06）。

---

## 2. 结论

| 层 | 选型 |
|---|---|
| 编辑器内核 | **CodeMirror 6**（`apps/web/src/editor/`） |
| 渲染器 | **markdown-it**，唯一实例在 `packages/shared/markdown` |
| 公式 | KaTeX，字体随包走，不连 CDN |
| 外壳 | 自研可折叠 / 可拖拽三栏，参照 VSCode |

选它是因为**源码是唯一事实源**这条约束。四个写入方（UI、MCP、AI、导入）共用同一份
Markdown，而这些既有机制全部建立在「字节不动」之上：

| 既有机制 | 约束 |
|---|---|
| `NoteVersion` 行级 diff（03 §3.6） | 编辑器不许重排文本，否则每次打开即产生满屏假 diff |
| `expected_version` 409（03 §5.2） | 归一化会让 Agent 与人反复互相冲突 |
| zip 导出回 Obsidian（规格 §9.4） | 往返保真是需求，不是偏好 |
| `[[wiki]]` / `$math$` 闭集（规格 §9.2） | CM6 里是装饰器；ProseMirror 里要自定义 node + serializer |

因此 **ProseMirror 系（Tiptap / Milkdown / BlockNote）与 Lexical 一律不用**：它们把文档
解析成 AST 再序列化回 Markdown，标记会被归一（`*` 变 `_`、表格补空格、软换行折行），
上表四条全破。Monaco 也不用：5MB 包体、面向代码而非散文、做不了 Live Preview。

真要所见即所得，只能作为**可选的第二模式**外挂，不能替换主线。

### 3.0 为什么画图是代码块

画图能力只加 ` ```mermaid `，不引 draw.io / Excalidraw 那种画布，理由和第 2 节同一条：

| 约束 | 代码块 | 独立画布格式 |
|---|---|---|
| 行级 diff、`expected_version` | 图就是几行文本，照常参与 | 要么整块二进制，要么另开一套版本 |
| 导回 Obsidian（规格 §9.4） | Obsidian 原生认 mermaid | 得靠插件，往返即丢 |
| 自托管不连 CDN | 渲染库随包走，按需加载 | `react-drawio` 默认打 `embed.diagrams.net`，自托管要另起一个容器 |
| AI 生成 | 源码可当场渲染验证，错了能把报错回喂给模型 | XML 生成不可靠，也没法在插入前校验 |

真要拖拽画布，只能作为**附件**外挂（画布文件存附件、正文嵌图片），不能替换代码块这条主线。

## 3.1 就地渲染口径

标记（`#`、`**`、`` ` ``、`[]()`、`[[]]`）平时藏起来只显示内容，光标凑近了才露出原文。
**两档粒度**，开关记在 `kb.layout.wysiwyg`，默认开即时渲染：

| 粒度 | 露出范围 | 像谁 |
|---|---|---|
| 整行 | 光标落在哪一行，那一行整行露出原文 | Obsidian |
| 元素（即时渲染） | 只有光标真正进到那个 `**粗体**` 里才露出星号，同行别的标记继续保持渲染态 | Typora |

即时渲染还额外做三件事：正文用比例字体（只有代码块与行内代码保持等宽）、
表格就地渲成真表格（光标进入表格范围才回源码）、引用左边条与代码块底色。

判定「光标凑近了」时贴边也算——不然刚打完 `**` 就立刻藏起来，想接着改还得倒回去。

就地渲染的：行内公式（KaTeX）、图片、任务复选框、无序列表圆点、分隔线、双链与链接的显示样式。
`$$` 块级公式也就地渲染，但**只在写了闭合的 `$$` 时才渲染**——不然刚敲下开头，
后面半篇文章会突然变成一坨公式。

**块级装饰（块级公式、表格）只能走 `StateField`**，不能放进 ViewPlugin：CodeMirror 明令
「Block decorations may not be specified via plugins」，跨行的替换同理，违反了直接抛异常。
所以 `live-preview.ts` 里块级与行内是两套构建，别再合回去。块级替换的范围还必须严格盖住整行，
对不齐就干脆不渲染。

藏起来的标记登记进 `EditorView.atomicRanges`，方向键一步跨过去，光标不会掉进看不见的字符里。

滚动同步靠 `data-line`：渲染器在 `env.sourceLines` 打开时给块级元素标上源码行号，
两侧互相对齐。刚被程序滚过的一侧会闭嘴 160ms，避免来回抖。

## 3.2 外壳

左侧两栏（笔记本、目录树）可折叠、可拖拽调宽，宽度与折叠状态记在 `localStorage`
（`kb.layout`），纯本机偏好，不进备份也不进 MCP。右栏（大纲 / 反向链接 / 附件 / 版本历史）
同理，见 `note-rail.tsx`。

编辑器全屏优先要浏览器真全屏（`requestFullscreen`），被拒就退化成「隐藏顶栏与左侧两栏、
编辑器占满窗口」，两种都靠 `Esc` 退出。

底栏放保存状态、只读标记、字数 / 字符数 / 行数、光标行列（规范 05 §3.1 要求保存状态在底栏；
顶栏离正文太远，写字时眼睛不会往那儿瞟）。

命令面板只放**动作**；找笔记是 `Ctrl/⌘+K` 的活，两者不重叠。

**大纲是双向的**：从大纲能跳进正文，光标在正文里动，大纲也要高亮当前落在哪一节
（`aria-current="location"` + 左边一道竖条）。只有单向的话，写长文时不知道自己在哪。
大纲那份 `outlineOf()` 是一次完整的 markdown-it parse，**要防抖**，否则每敲一个字全篇重解析一遍
——右栏页签记在 `localStorage` 里粘着，对常用大纲的人这是常态而不是偶发。

**正文栏宽**：编辑器与预览共用 `.editor-measure`（默认 1400px，全屏放宽到 1760px）。
栏内再分两档——正文（段落、标题、列表、引用）限在 `--measure`（46rem）保持易读行宽，
**表格、代码块、图片、图表可以占满整栏**。三者左边缘对齐同一条线，不要一个居中一个左对齐。

这条**两侧都要执行**：预览侧靠 `.markdown > :is(p, ul, …)`，编辑侧靠 `.cm-line`
（代码行 `.cm-md-code-line` 例外，块级小部件本来就不是 `.cm-line`，天然不受限）。
只限 `.cm-line` 不要去限 `.cm-content`——那样点右侧空白就落不到行尾了。

**宽栏开关**（`kb.layout` 的 `wide`，默认关）：上面这套的代价是，一篇没有表格也没有代码块的
笔记在宽屏上会把右边一大半空着——那片宽度是留给宽块的，没宽块时就纯是空，看着像布局坏了。
开关打开时给 `.editor-measure` 挂 `data-wide="1"`，把 `--measure` 整个置为 `none`，
正文行宽跟着编辑区走。默认仍然关着：易读行宽是默认值该有的样子，要长行的人自己开。

改 `--measure` 得点名三处：`.editor-measure`、`.markdown`、`[data-editor="markdown"]`。
后两者各自也写了一份 46rem（它们要能脱离编辑器单独用，比如文档站），
**元素自己写的自定义属性会盖掉从祖先继承来的值**，只改最外层那份是不生效的。

**字号**是本机偏好，四档（`0.875 / 1 / 1.125 / 1.25`）记在 `kb.layout.fontScale`，
通过 CSS 变量 `--editor-font-scale` 同时缩放编辑器与预览，**不改浏览器整页缩放**
（那会把侧栏一起放大）。

表格由渲染器套一层 `.table-scroll` 负责横向滚动，表格自己 `width: 100%; min-width: 34rem`。
**别给 `<table>` 直接加 `display: block; overflow-x: auto`**——那样它不再是表格盒，
列宽会被容器压扁，中文表头会被挤成一列一个字。窄栏下正确的行为是滚动，不是压扁。

打字机滚动（光标行钉在视口中间）默认关，命令面板里开，偏好同样记在 `kb.layout`。
它不在 updateListener 里同步 dispatch——CodeMirror 明令禁止那样做——而是下一帧再滚，
顺带把一次输入里的多个更新合并成一次滚动。

## 3.3 Vim keymap

默认**关**。这是少数人的强需求、多数人的灾难：手滑开了会发现打字全变成命令。
开关在命令面板与底栏，偏好记在 `kb.layout.vim`（本机偏好，不进备份、不进 MCP）。

- **按需加载**：`@replit/codemirror-vim` 约 200 KB，跟 KaTeX、mermaid 一样只在真开了才 import，
  关着的用户一个字节都不下载。加载失败就退回普通模式并提示，不让编辑器卡在半吊子状态。
- **谁赢**：Vim keymap 插在 `keymap.of(...)` 的**最前面**，所以 `hjkl`、`dd`、`:w` 归 Vim；
  但 `Ctrl/⌘+S`、`Ctrl/⌘+K`、`Ctrl/⌘+B` 这些应用级快捷键仍然优先——它们是宿主的约定，
  换个编辑器模式不该改变「保存」怎么按。`:w` 与 `:wq` 映射到同一个保存动作。
- **Esc 的归属**：Vim 模式下 `Esc` 先给 Vim（回 normal 模式），只有已经在 normal 模式时才冒泡出去
  退全屏 / 关浮层。否则想退插入模式会连编辑器全屏一起退掉。
- **底栏**显示当前模式（`NORMAL` / `INSERT` / `VISUAL`）与待定的命令串，与光标行列并排。
- 不做 `.vimrc`、不做自定义映射配置面板：那是另一个产品。

## 3.4 协同编辑与远端光标

**为什么必须引 CRDT。** 光标要有意义，前提是两个人看到的是同一份正文。只同步光标位置而不同步文本，
第二个人一敲字，第一个人的光标标记就指到错的地方去了——那比不显示更糟。

**分层。** CRDT 只做「在线这一层」，不当新的事实源：

| 层 | 是什么 | 谁在用 |
|---|---|---|
| 在线层 | 一个 `Y.Doc`，里面一个 `Y.Text`（键名 `body`） | 只有正开着这篇的浏览器 |
| 落库层 | 仍然是 `notes.body_md` + `note_versions` | 搜索、导出、MCP、行级 diff、`expected_version` |

所以 03 定的版本模型一个字都不用改，MCP 与 AI 的写入路径也不动。

**房间。**

- 一篇笔记一个房间，key 就是 `note_id`。第一个人连上时用 `notes.body_md` 初始化 `Y.Text`。
- 最后一个人断开后房间**再留 30 秒**——刷新页面不该把状态丢掉——然后落库并释放。
- 服务端把 Y 的文档快照存进 `note_collab`，重启后接着来。快照按更新次数压实
  （`Y.encodeStateAsUpdate` 重写一份），不无限追加。

**鉴权。** 升级 WebSocket 之前跑一次 `noteAccess(noteId, userId, 'edit')`：

- 能编辑 → `mode=write`。
- 只能读（viewer、只读笔记本、工作区冻结）→ `mode=read`：**收得到别人的光标，发不出自己的更新**。
  服务端直接丢弃只读连接的 update 消息，不靠前端自觉。
- 读都不能读 → 连接直接拒掉，且不透露这篇笔记是否存在。

**落库。**

- 有改动后 **3 秒静默**、或最多 **15 秒**，落一次；房间关闭时无条件再落一次。
- 走 §5.2 的同一条路径但 `force=true`——房间自己就是这段时间里唯一的写者，不存在覆盖别人。
- **版本合并**：同一篇、5 分钟内的连续协同落库复用同一条 `note_versions`，`source = collab`，
  `editor_id` 记最后动手的那个人。否则十分钟的协作能产生上百条版本，把版本抽屉淹掉。
  规则与 16 §4.3 的勾选合并同源。

**外部写要回灌。** MCP / AI / 恢复历史版本会直接改 `notes.body_md`，房间收不到任何通知，
所以只能自己盯着 `notes.version`：

- 开着的房间**每 5 秒探一次**版本号；落库前再兜底比对一次。
- 版本变了就比正文：若 DB 里那份既不等于房间当前文本、也不等于房间上次落的那一份，
  说明确实是外面改的，把差异**以文本 diff 的形式打进 `Y.Text`**。
- 不整段替换。整段替换会让正在打字的人丢光标，还会把他刚敲的半句一起冲掉。
- 房间自己写出去之后要记下新的 `version`，否则下一轮轮询会把自己的写当成外部写。

**光标（awareness）。**

- 每个连接广播 `{ user: { id, name, color }, cursor: { anchor, head } }`。
- 颜色由 `user_id` 哈希到一组固定的语义色，**同一个人在任何一篇里都是同一个颜色**，
  否则换篇笔记就要重新认人。
- 远端光标画成 1px 竖条 + 悬停才出现的名字标签；远端选区用同色低透明度底。
- **不抢焦点、不滚动视口**——别人在哪儿是信息，不是指令。
- 20 秒没有心跳的 awareness 条目自动清掉，避免「幽灵光标」。
- 03 §3.5 的在场从「张三在看」升级成头像组：正在编辑的人加一圈同色描边。

**撤销归属。** 协同一接管，**CodeMirror 自己的 `history()` 必须整个摘掉**，撤销改由
Y.UndoManager 的 keymap 接管（`collab.ts` 里那份 `yUndoManagerKeymap`），断开时再换回来。

理由是 `y-codemirror.next` 把远端改动推进编辑器时用的是普通事务、**没有标
`addToHistory: false`**。两套撤销并存的话，别人敲的字会进本地撤销栈，按一下 `Ctrl+Z`
撤的是同事的句子——而且撤销结果还会经 CRDT 广播出去，等于替所有人回滚。
Y.UndoManager 只认自己产生的改动，这才是协同下「撤销」该有的语义。

**降级。** 连不上、被拒、或浏览器不支持 WebSocket，编辑器**静默退回单机自动保存**
（原来那套 `expected_version`）。底栏标一行「离线编辑」，不弹窗、不拦人写字。
断线重连后按 CRDT 的语义合并，不需要用户做选择。

**入口。** 协同没有「开启协同」这个动作，也**不该**有——它跟着 ACL 走：对这篇有编辑权的人
同时打开，就在同一个房间里。但「没有动作」不等于「没有入口」：用户想跟人一起写的时候，
需要一个地方回答「谁能编这篇 / 怎么再拉一个人进来 / 此刻谁在」。

所以笔记页放一个**协作**入口（人形图标，紧挨着分享按钮），点开是一张卡片：

| 段 | 内容 |
|---|---|
| 此刻在这篇 | 头像组 + 名字，正在编辑的加同色描边；连接状态一行字（协同 / 正在连 / 离线编辑） |
| 谁能编这篇 | 按 [02](./02-工作区成员与ACL.md) 算出来的有效名单，标出各自是编辑还是只读，以及权限来自工作区角色还是笔记本授权 |
| 拉人进来 | 直达「工作区设置 → 成员 → 邀请成员」；个人工作区提示「个人工作区只有你自己，先建一个团队工作区」 |

**必须和分享区分开。** 现在这两件事在中文里都叫「分享」，而 UI 里只有只读那个有按钮，
于是「协同在哪分享」成了真实被问出来的问题。口径钉死：

- **协作**（这张卡片）= 站内、要登录、跟着 ACL、能写、进协同房间。
- **分享**（[07](./07-分享与文档站.md) 那个）= 站外、给链接、只读，访客能看能评论，**永远不进协同房间**。

分享弹窗里加一句指路，反过来协作卡片里也留一个「只想给人看？去分享」的出口。

**一期不做**：离线改完再合并（要持久化本地更新日志）、协作历史回放、把评论锚定到 CRDT 位置。

## 3.5 表格的可视化编辑

即时渲染下表格已经渲成真表格（§3.1）。这一节让它能直接改结构，**但改的仍然是 Markdown 源码**：

| 动作 | 结果 |
|---|---|
| hover 列头 | 出现「插入左列 / 插入右列 / 删除列」与对齐三选一 |
| hover 行首 | 出现「插入上行 / 插入下行 / 删除行」 |
| 拖列边界 | 改这一列的**显示**宽度 |

- 所有结构操作都归结为同一件事：把这张表读成单元格矩阵，改矩阵，再序列化回去。
  **只替换这张表占的那几行，表外一个字节都不动**——否则行级 diff 会出满屏假变更。
- 序列化补空格对齐列宽，与 `packages/shared/markdown` 的渲染口径一致；
  分隔行按对齐写 `:---` / `:---:` / `---:`。
- **列宽不进 Markdown**。Markdown 没有列宽这个概念，写进去就导不回 Obsidian 了。
  宽度记在 `kb.table-width`（键为「笔记 id + 表格起始行 + 列序号」），纯本机偏好，
  不进备份、不进 MCP。
- 只读态不显示任何把手。
- 只剩一列或只剩表头一行时不给删——表头是 Markdown 表格存在的前提，删了整张表就散了。
  按钮置灰并说明原因，而不是让人点了没反应。

## 3.6 粘贴

三件事，实现在 `paste.ts` / `paste-html.ts`：

| 场景 | 行为 |
|---|---|
| 剪贴板里带文件 | 走附件那条路（`attachments.ts` 排在前面先接走），本节不管 |
| 剪贴板里有 `text/html` | 转成**闭集内**的 Markdown 再插入 |
| `Ctrl/⌘+Shift+V` | 强制纯文本 |
| 选中一段 + 剪贴板是一条裸链接 | 变成 `[选中](链接)` |

**为什么不引 turndown**：它会吐闭集之外的东西（脚注、原样 HTML、各种 `<div>` 兜底），
而规格 §9.2 的闭集就那么几条。自己走一遍 DOM 只生成闭集内语法，比事后拿正则去洗它的产物可靠。

口径：

- 转换前先过 **DOMPurify**。剪贴板里的 HTML 带脚本与事件属性是常态，而我们要把它挂进真的
  DOM 节点里遍历——不消毒等于把别人页面上的脚本请进来。
- `javascript:` 一类的 `href` / `src` 直接丢掉，只留文字。
- Google Docs 那种 `<b style="font-weight:normal">` 包整篇的写法要认出来，否则全文变粗体。
- 转出来的东西比纯文本还短一半以上，说明源里基本没有结构，**放弃转换退回纯文本**——
  别拿一个更差的结果去换用户的原文。
- 转换产物是**普通输入**，进文档就是普通字节，与「装饰不改字节」那条铁律不冲突。

**附件上传期间，文档一个字节都不动。** 「上传中」是画在插入点上的一个**装饰**，
不是一段占位文本；传成功了才把 Markdown 作为一次普通输入插进去，位置随文档改动一起平移。

以前那版往正文里插 `[⏳ 上传中 1]()` 再替换回来，代价是：那一下就是一次普通文档改动，
`onChange` 照常触发 → 850ms 自动保存 → 占位符落进 `notes.body_md`，还可能单独占一条
`note_versions`；协同开着的话它会广播给房间里所有人；传到一半关掉标签页，这段占位符就
永久留在正文里了。而**任何一个真实文件都传不完 850ms**，所以这不是边角情况，是常态。

上传失败、或者传到一半用户换了篇笔记（编辑器已经拆了），一律什么都不插，把装饰收掉即可。

## 3.7 列表的悬挂缩进

软换行默认把折下来的那一行顶回第 0 列，于是一条三行长的列表项看起来像三条并列的段落，
中文长句尤其乱。给列表行加 `padding-left` 再用等量的负 `text-indent` 把首行拉回去：
首行原地不动，折行对齐到正文起点。

**只做列表，不做引用**：引用行已经由 `.cm-md-quote-line` 整行加了 padding，首行与折行本来就对齐；
再叠一层负缩进反而会把首行拽到左边条上去。代码块里的 `- ` 是代码不是列表，跳过。

## 3.8 移动端

- **格式工具条**：手机没有 `Ctrl+B`，而 `**` 要在系统键盘的符号页按两下。不给工具条，
  窄屏的「编辑」页基本只能打纯文本。
  - **只在键盘真起来时出现**（`visualViewport` 掉了一大截才算），平时白占一行还挡正文。
  - **按下不抢焦点**（`mousedown` 里 `preventDefault`），否则点一次按钮键盘就收一次。
  - 位置靠 `visualViewport` 算：iOS 上键盘不改变布局视口，光 `bottom: 0` 会被键盘整个盖住；
    Android 上布局视口会缩，算出来的偏移正好是 0。同一套代码两边都对。
- **输入属性**：CodeMirror 默认 `autocorrect="off"`、`autocapitalize="off"`——那是代码编辑器的默认。
  粗指针设备下改成 `on` / `sentences`。
- **跟随双链**见 §5：触摸设备单击即跟随。

## 3.9 无障碍

- `.cm-content` 补 `aria-label`。CodeMirror 只给了 `role="textbox"` 与 `aria-multiline`，没有名字。
- **Tab 不再无条件吞掉**。`indentWithTab` 是键盘无障碍里的经典陷阱：只用键盘的人进得来出不去。
  改成只在**确实有东西可缩进**时接管——光标在列表项里、在代码块里、或者选中了多行——
  其余情况放行让 Tab 移焦。
- **拼写检查默认开**（`kb.layout.spellcheck`）。CodeMirror 默认关掉它，那同样是代码编辑器的默认。

## 3.10 折叠

长文没有折叠就只能一路滚。两种可折的东西：

| 折什么 | 范围 |
|---|---|
| 标题 | 从标题行末折到**下一个同级或更高级标题之前**，中间的子标题一起收进去 |
| 围栏代码块 | 留下 ` ```lang ` 那一行，其余（含收尾围栏）折起来 |

- 折叠范围靠**语法树的兄弟节点**找，不是逐行扫全文——`foldGutter` 会对每一个可见行都问一次，
  逐行扫在长文里就是「可见行数 × 文档行数」。
- 把手在左边的折叠槽里，平时几乎透明，鼠标进了编辑器才浮出来；**已经折起来的那条一直可见**，
  否则用户会找不到自己折了什么。槽宽记在 `--fold-gutter`，标题输入框要让出同样一格，
  不然标题会比正文往左突出一截。
- 折叠是**纯显示**：折起来的还是原来那些字节，保存、行级 diff、导出都当它不存在。
- **折叠状态记得住**，存 `kb.fold`（最多 200 篇）。
  **按「折的是哪一行的原文」记，不按行号记**：MCP、AI、恢复历史版本都会在别处改正文，
  行号存下来隔一会儿就指到别的地方去了，一打开就折错段落，比不记还糟。标题重名时两处都折上。
  还原要**催一把解析再重试几次**——刚建视图那一刻语法树还没铺到，`foldable()` 一路回 null，
  只试一次会一条都折不上。
  另外这个重试的第一发用 `setTimeout` 而不是 `requestAnimationFrame`：**后者在不可见的标签页里根本不跑**，
  从「恢复上次会话」打开的一堆后台标签会全都折不上。

## 3.11 双链悬停卡片

鼠标在一条 `[[双链]]` 上停 350ms，出一张卡片：标题 + 所在笔记本 + 前 180 字摘要；
这篇还没创建就直说「这篇还没创建」。

- **解析规则必须和点击跳转同一套**，否则会出现「卡片里有、点开却跳不过去」。
- **卡片先摆出来再填内容**：等数据到齐了才返回 tooltip 的话，鼠标早移开了。
- 宿主侧缓存 20 秒：同一条链接来回悬停不该每次都打一趟接口，但也别缓存到看不见别人的新改动。

## 3.11.5 渲染项开关

就地渲染哪些东西是可以逐项关的：**图片 / 公式 / 表格 / 图表**，存 `kb.layout.render`，默认全开。
关掉的那项在编辑器里退回源码，预览栏不受影响。

这条是给「只想看源码但保留表格」那类需求准备的，不必为此把整个即时渲染关掉。
读偏好时**缺项一律当开**：以后再加一项渲染，老用户不该莫名其妙少一样东西。

## 3.12 光标与滚动位置的记忆

换一篇再回来，光标与滚动位置还原到上次离开时的地方。

**只活在这一次会话里**（内存里一张 Map，最多 60 篇），不进 `localStorage`：
位置是按字符偏移记的，而 MCP / AI / 恢复历史版本都会在别处改正文，存到下次打开就是一串错位的偏移。
还原前按当前正文长度夹一下。折叠状态能持久化是因为它按**文字**记（§3.10），偏移记不了。

## 3.13 图片与代码块的手势

| 在哪 | 图片 | 代码块 |
|---|---|---|
| 编辑器 | hover 出一个放大按钮；**裸单击仍然是「把光标放到这儿」**，和双链同一条口径（§5） | 源码就在眼前，不加装饰 |
| 预览 / 分享页 / 文档站 | 直接点图放大 | 右上角浮出语言标签 + 复制按钮 |

- 放大层全站只有一个（`ImageLightbox`），编辑器里的图片小部件拿不到 React 上下文，
  所以走一个模块级的单订阅通道喊它，而不是给小部件硬塞一条 props。
- 代码块那两样是**宿主在客户端补的**，不改渲染器的输出（架构 05 §5：解析器只有一个）。
  复制先走 `navigator.clipboard`，非安全上下文（http 的自托管实例）退回 `execCommand`，
  两条都不行就把「复制失败」写在按钮上——别假装成功。
- ` ```mermaid ` 已经被图块接走了，不再挂这套工具条。

## 3.14 Callout、脚注、`==高亮==`

规格 §9.2 把这三样收进闭集之后，渲染器与编辑器要一起认。

**Callout** 就是打了标记的引用块：`> [!NOTE] 可选标题`。

- 渲染成 `<blockquote class="callout callout-note" data-callout="note">` + 一个标题 `<div>`。
  **仍然是 blockquote**，这是它能进闭集的前提——不认这套语法的工具照常渲染成普通引用，内容不丢。
- 类型认不出来的（`> [!随便]`）**不抢普通引用**，老老实实当引用渲染。
- 折叠写法 `> [!NOTE]-` 的 `+/-` 只识别不折叠：渲染结果要同时供文档站、分享页、MCP 使用，
  不能假设有 JS。
- 编辑器里整块跟着类型上色，配色和预览侧共用同一套派生规则（`--callout`）；
  **`[!NOTE]` 标记不藏**——它是源码，人得看得见也改得动。

**脚注**支持的是一个子集（规格 §9.2 列了口径）。实现上两条值得记：

- 定义行**不产生 token**，只往 `env` 里记；正文里不该出现它。
- 定义内容的行内解析放在**文末汇总那一步**手动跑 `md.inline.parse`，
  因为定义是块规则收的、引用是行内规则发的，编号又要按引用顺序——放在别处会绕进循环依赖。

**`==高亮==`** 两侧都走**定界符**机制（markdown-it 与 @lezer/markdown 各自照抄自带的删除线），
不是自己扫一段就 `addElement`——那样内容不会再被解析，`==**粗的高亮**==` 里的星号会变成字面量，
编辑器和预览就对不上了。编辑器侧底色只能走 CSS：`HighlightStyle` 改得了字色改不了底色。

**顺带修掉的一个老毛病**：lezer 会给**任何一段方括号文字**发一个 `Link` 节点——
`[草稿] 会议纪要`、`> [!NOTE] 小心` 都算。原来的装饰照单把方括号藏掉，于是正文里所有
「`[方括号]`开头」的写法在即时渲染下都莫名其妙少一对括号，而它们既不是链接也点不开。
现在**只有真的带地址**（有 `](` 后面那个目标 `URL`）才藏标记、才画成链接样式。
标签里被 Autolink 认成 `URL` 的那段是显示文本（`[https://…](https://…)` 很常见），
把它也藏掉的话，光标一离开链接就什么都不剩。

## 4. 业务规则

1. **文档内容永远是原始 Markdown。** 着色、装饰、折叠只影响显示，任何特性都不许改写用户
   没碰过的字节。新增装饰前先想清楚它是不是 view-only。

   **小部件的根节点绝对不能被换掉。** CodeMirror 认的就是 `toDOM()` 返回的那个根，
   把它 `replaceWith` 掉，DOM 观察器会以为是用户在编辑，转头把新节点的文字**读回文档**。
   踩过一次：图片加载失败时把 `<img>` 换成一块错误提示，`![封面](…)` 就被原地改成了
   「图片加载失败：封面」——源码真的被改了。要换内容就**在根节点里面换**（外面套一层壳），
   或者只改根节点里子元素的类名。异步填充内容的公式、图表、表格都是这么做的。
2. **渲染器只有一个。** App 预览、文档站、分享页、广场帖、问知识库回答、MCP 返回都走
   `renderMarkdown()`。任何地方再 `new MarkdownIt()` 视为 bug（架构 05 §5）。
3. 渲染出的 HTML **调用方必须自行 sanitize**；浏览器端统一 DOMPurify，配置见
   `apps/web/src/MarkdownView.tsx`。
4. 编辑器配色**全部走 CSS 变量**，不许出现写死颜色，否则主题包（15）换肤会掉队。
   代码块着色板是 `--code-*`，明暗两套都在 `styles.css` 里。
5. 任务列表勾选走 `toggleTaskAt()`：就地翻一个字符，其余字节不动，然后当一次普通保存
   提交（03 §4.7）。
6. **公式是两段式的**：`renderMarkdown()` 只吐占位元素
   `<span class="math" data-math="源码">$源码$</span>`，真正排版由宿主调 `hydrateMath()`
   在客户端补，KaTeX 因此可以按需加载（整包 261 KB JS + 30 KB CSS，而多数笔记一条公式都没有）。
   占位元素里放的就是源码，所以没加载完、加载失败、或公式本身写错时，看到的都是源码而不是空白，
   也不会整页崩（03 §4.6）。将来若要服务端渲染 HTML，记得那一步也得跑 KaTeX。
7. Viewer / frozen 工作区传 `readOnly`，编辑器进只读态，不是靠藏按钮。
