# 17 编辑器方案

## 1. 范围

管：编辑器内核选型、渲染器归一、快捷键、外壳（折叠 / 大纲 / 状态栏）的落地口径。
不管：保存与冲突算法（03）、双链解析（04）、附件上传（06）。

---

## 2. 结论

| 层 | 选型 |
|---|---|
| 编辑器内核 | **CodeMirror 6**（`apps/web/src/editor/`） |
| 渲染器 | **markdown-it**，唯一实例在 `packages/shared/markdown` |
| 公式 | KaTeX，字体随包走，不连 CDN |
| 外壳 | 自研可折叠 / 可拖拽三栏，参照 VSCode |

选它是因为**源码是唯一事实源**这条约束。四个写入方（UI、MCP、AI、导入）共用同一份
Markdown，而这些既有机制全部建立在「字节不动」之上：

| 既有机制 | 约束 |
|---|---|
| `NoteVersion` 行级 diff（03 §3.6） | 编辑器不许重排文本，否则每次打开即产生满屏假 diff |
| `expected_version` 409（03 §5.2） | 归一化会让 Agent 与人反复互相冲突 |
| zip 导出回 Obsidian（规格 §9.4） | 往返保真是需求，不是偏好 |
| `[[wiki]]` / `$math$` 闭集（规格 §9.2） | CM6 里是装饰器；ProseMirror 里要自定义 node + serializer |

因此 **ProseMirror 系（Tiptap / Milkdown / BlockNote）与 Lexical 一律不用**：它们把文档
解析成 AST 再序列化回 Markdown，标记会被归一（`*` 变 `_`、表格补空格、软换行折行），
上表四条全破。Monaco 也不用：5MB 包体、面向代码而非散文、做不了 Live Preview。

真要所见即所得，只能作为**可选的第二模式**外挂，不能替换主线。

### 3.0 为什么画图是代码块

画图能力只加 ` ```mermaid `，不引 draw.io / Excalidraw 那种画布，理由和第 2 节同一条：

| 约束 | 代码块 | 独立画布格式 |
|---|---|---|
| 行级 diff、`expected_version` | 图就是几行文本，照常参与 | 要么整块二进制，要么另开一套版本 |
| 导回 Obsidian（规格 §9.4） | Obsidian 原生认 mermaid | 得靠插件，往返即丢 |
| 自托管不连 CDN | 渲染库随包走，按需加载 | `react-drawio` 默认打 `embed.diagrams.net`，自托管要另起一个容器 |
| AI 生成 | 源码可当场渲染验证，错了能把报错回喂给模型 | XML 生成不可靠，也没法在插入前校验 |

真要拖拽画布，只能作为**附件**外挂（画布文件存附件、正文嵌图片），不能替换代码块这条主线。

## 3.1 就地渲染口径

标记（`#`、`**`、`` ` ``、`[]()`、`[[]]`）平时藏起来只显示内容，光标凑近了才露出原文。
**两档粒度**，开关记在 `kb.layout.wysiwyg`，默认开即时渲染：

| 粒度 | 露出范围 | 像谁 |
|---|---|---|
| 整行 | 光标落在哪一行，那一行整行露出原文 | Obsidian |
| 元素（即时渲染） | 只有光标真正进到那个 `**粗体**` 里才露出星号，同行别的标记继续保持渲染态 | Typora |

即时渲染还额外做三件事：正文用比例字体（只有代码块与行内代码保持等宽）、
表格就地渲成真表格（光标进入表格范围才回源码）、引用左边条与代码块底色。

判定「光标凑近了」时贴边也算——不然刚打完 `**` 就立刻藏起来，想接着改还得倒回去。

就地渲染的：行内公式（KaTeX）、图片、任务复选框、无序列表圆点、分隔线、双链与链接的显示样式。
`$$` 块级公式也就地渲染，但**只在写了闭合的 `$$` 时才渲染**——不然刚敲下开头，
后面半篇文章会突然变成一坨公式。

**块级装饰（块级公式、表格）只能走 `StateField`**，不能放进 ViewPlugin：CodeMirror 明令
「Block decorations may not be specified via plugins」，跨行的替换同理，违反了直接抛异常。
所以 `live-preview.ts` 里块级与行内是两套构建，别再合回去。块级替换的范围还必须严格盖住整行，
对不齐就干脆不渲染。

藏起来的标记登记进 `EditorView.atomicRanges`，方向键一步跨过去，光标不会掉进看不见的字符里。

滚动同步靠 `data-line`：渲染器在 `env.sourceLines` 打开时给块级元素标上源码行号，
两侧互相对齐。刚被程序滚过的一侧会闭嘴 160ms，避免来回抖。

## 3.2 外壳

左侧两栏（笔记本、目录树）可折叠、可拖拽调宽，宽度与折叠状态记在 `localStorage`
（`kb.layout`），纯本机偏好，不进备份也不进 MCP。右栏（大纲 / 反向链接 / 附件 / 版本历史）
同理，见 `note-rail.tsx`。

编辑器全屏优先要浏览器真全屏（`requestFullscreen`），被拒就退化成「隐藏顶栏与左侧两栏、
编辑器占满窗口」，两种都靠 `Esc` 退出。

底栏放保存状态、只读标记、字数 / 字符数 / 行数、光标行列（规范 05 §3.1 要求保存状态在底栏；
顶栏离正文太远，写字时眼睛不会往那儿瞟）。

命令面板只放**动作**；找笔记是 `Ctrl/⌘+K` 的活，两者不重叠。

**正文栏宽**：编辑器与预览共用 `.editor-measure`（默认 1400px，全屏放宽到 1760px）。
栏内再分两档——正文（段落、标题、列表、引用）限在 `--measure`（46rem）保持易读行宽，
**表格、代码块、图片、图表可以占满整栏**。三者左边缘对齐同一条线，不要一个居中一个左对齐。

表格由渲染器套一层 `.table-scroll` 负责横向滚动，表格自己 `width: 100%; min-width: 34rem`。
**别给 `<table>` 直接加 `display: block; overflow-x: auto`**——那样它不再是表格盒，
列宽会被容器压扁，中文表头会被挤成一列一个字。窄栏下正确的行为是滚动，不是压扁。

打字机滚动（光标行钉在视口中间）默认关，命令面板里开，偏好同样记在 `kb.layout`。
它不在 updateListener 里同步 dispatch——CodeMirror 明令禁止那样做——而是下一帧再滚，
顺带把一次输入里的多个更新合并成一次滚动。

## 3.3 Vim keymap

默认**关**。这是少数人的强需求、多数人的灾难：手滑开了会发现打字全变成命令。
开关在命令面板与底栏，偏好记在 `kb.layout.vim`（本机偏好，不进备份、不进 MCP）。

- **按需加载**：`@replit/codemirror-vim` 约 200 KB，跟 KaTeX、mermaid 一样只在真开了才 import，
  关着的用户一个字节都不下载。加载失败就退回普通模式并提示，不让编辑器卡在半吊子状态。
- **谁赢**：Vim keymap 插在 `keymap.of(...)` 的**最前面**，所以 `hjkl`、`dd`、`:w` 归 Vim；
  但 `Ctrl/⌘+S`、`Ctrl/⌘+K`、`Ctrl/⌘+B` 这些应用级快捷键仍然优先——它们是宿主的约定，
  换个编辑器模式不该改变「保存」怎么按。`:w` 与 `:wq` 映射到同一个保存动作。
- **Esc 的归属**：Vim 模式下 `Esc` 先给 Vim（回 normal 模式），只有已经在 normal 模式时才冒泡出去
  退全屏 / 关浮层。否则想退插入模式会连编辑器全屏一起退掉。
- **底栏**显示当前模式（`NORMAL` / `INSERT` / `VISUAL`）与待定的命令串，与光标行列并排。
- 不做 `.vimrc`、不做自定义映射配置面板：那是另一个产品。

## 3.4 协同编辑与远端光标

**为什么必须引 CRDT。** 光标要有意义，前提是两个人看到的是同一份正文。只同步光标位置而不同步文本，
第二个人一敲字，第一个人的光标标记就指到错的地方去了——那比不显示更糟。

**分层。** CRDT 只做「在线这一层」，不当新的事实源：

| 层 | 是什么 | 谁在用 |
|---|---|---|
| 在线层 | 一个 `Y.Doc`，里面一个 `Y.Text`（键名 `body`） | 只有正开着这篇的浏览器 |
| 落库层 | 仍然是 `notes.body_md` + `note_versions` | 搜索、导出、MCP、行级 diff、`expected_version` |

所以 03 定的版本模型一个字都不用改，MCP 与 AI 的写入路径也不动。

**房间。**

- 一篇笔记一个房间，key 就是 `note_id`。第一个人连上时用 `notes.body_md` 初始化 `Y.Text`。
- 最后一个人断开后房间**再留 30 秒**——刷新页面不该把状态丢掉——然后落库并释放。
- 服务端把 Y 的文档快照存进 `note_collab`，重启后接着来。快照按更新次数压实
  （`Y.encodeStateAsUpdate` 重写一份），不无限追加。

**鉴权。** 升级 WebSocket 之前跑一次 `noteAccess(noteId, userId, 'edit')`：

- 能编辑 → `mode=write`。
- 只能读（viewer、只读笔记本、工作区冻结）→ `mode=read`：**收得到别人的光标，发不出自己的更新**。
  服务端直接丢弃只读连接的 update 消息，不靠前端自觉。
- 读都不能读 → 连接直接拒掉，且不透露这篇笔记是否存在。

**落库。**

- 有改动后 **3 秒静默**、或最多 **15 秒**，落一次；房间关闭时无条件再落一次。
- 走 §5.2 的同一条路径但 `force=true`——房间自己就是这段时间里唯一的写者，不存在覆盖别人。
- **版本合并**：同一篇、5 分钟内的连续协同落库复用同一条 `note_versions`，`source = collab`，
  `editor_id` 记最后动手的那个人。否则十分钟的协作能产生上百条版本，把版本抽屉淹掉。
  规则与 16 §4.3 的勾选合并同源。

**外部写要回灌。** MCP / AI / 恢复历史版本会直接改 `notes.body_md`，房间收不到任何通知，
所以只能自己盯着 `notes.version`：

- 开着的房间**每 5 秒探一次**版本号；落库前再兜底比对一次。
- 版本变了就比正文：若 DB 里那份既不等于房间当前文本、也不等于房间上次落的那一份，
  说明确实是外面改的，把差异**以文本 diff 的形式打进 `Y.Text`**。
- 不整段替换。整段替换会让正在打字的人丢光标，还会把他刚敲的半句一起冲掉。
- 房间自己写出去之后要记下新的 `version`，否则下一轮轮询会把自己的写当成外部写。

**光标（awareness）。**

- 每个连接广播 `{ user: { id, name, color }, cursor: { anchor, head } }`。
- 颜色由 `user_id` 哈希到一组固定的语义色，**同一个人在任何一篇里都是同一个颜色**，
  否则换篇笔记就要重新认人。
- 远端光标画成 1px 竖条 + 悬停才出现的名字标签；远端选区用同色低透明度底。
- **不抢焦点、不滚动视口**——别人在哪儿是信息，不是指令。
- 20 秒没有心跳的 awareness 条目自动清掉，避免「幽灵光标」。
- 03 §3.5 的在场从「张三在看」升级成头像组：正在编辑的人加一圈同色描边。

**降级。** 连不上、被拒、或浏览器不支持 WebSocket，编辑器**静默退回单机自动保存**
（原来那套 `expected_version`）。底栏标一行「离线编辑」，不弹窗、不拦人写字。
断线重连后按 CRDT 的语义合并，不需要用户做选择。

**一期不做**：离线改完再合并（要持久化本地更新日志）、协作历史回放、把评论锚定到 CRDT 位置。

## 3.5 表格的可视化编辑

即时渲染下表格已经渲成真表格（§3.1）。这一节让它能直接改结构，**但改的仍然是 Markdown 源码**：

| 动作 | 结果 |
|---|---|
| hover 列头 | 出现「插入左列 / 插入右列 / 删除列」与对齐三选一 |
| hover 行首 | 出现「插入上行 / 插入下行 / 删除行」 |
| 拖列边界 | 改这一列的**显示**宽度 |

- 所有结构操作都归结为同一件事：把这张表读成单元格矩阵，改矩阵，再序列化回去。
  **只替换这张表占的那几行，表外一个字节都不动**——否则行级 diff 会出满屏假变更。
- 序列化补空格对齐列宽，与 `packages/shared/markdown` 的渲染口径一致；
  分隔行按对齐写 `:---` / `:---:` / `---:`。
- **列宽不进 Markdown**。Markdown 没有列宽这个概念，写进去就导不回 Obsidian 了。
  宽度记在 `kb.table-width`（键为「笔记 id + 表格起始行 + 列序号」），纯本机偏好，
  不进备份、不进 MCP。
- 只读态不显示任何把手。
- 只剩一列或只剩表头一行时不给删——表头是 Markdown 表格存在的前提，删了整张表就散了。
  按钮置灰并说明原因，而不是让人点了没反应。

## 4. 业务规则

1. **文档内容永远是原始 Markdown。** 着色、装饰、折叠只影响显示，任何特性都不许改写用户
   没碰过的字节。新增装饰前先想清楚它是不是 view-only。
2. **渲染器只有一个。** App 预览、文档站、分享页、广场帖、MCP 返回都走
   `renderMarkdown()`。任何地方再 `new MarkdownIt()` 视为 bug（架构 05 §5）。
3. 渲染出的 HTML **调用方必须自行 sanitize**；浏览器端统一 DOMPurify，配置见
   `apps/web/src/MarkdownView.tsx`。
4. 编辑器配色**全部走 CSS 变量**，不许出现写死颜色，否则主题包（15）换肤会掉队。
   代码块着色板是 `--code-*`，明暗两套都在 `styles.css` 里。
5. 任务列表勾选走 `toggleTaskAt()`：就地翻一个字符，其余字节不动，然后当一次普通保存
   提交（03 §4.7）。
6. **公式是两段式的**：`renderMarkdown()` 只吐占位元素
   `<span class="math" data-math="源码">$源码$</span>`，真正排版由宿主调 `hydrateMath()`
   在客户端补，KaTeX 因此可以按需加载（整包 261 KB JS + 30 KB CSS，而多数笔记一条公式都没有）。
   占位元素里放的就是源码，所以没加载完、加载失败、或公式本身写错时，看到的都是源码而不是空白，
   也不会整页崩（03 §4.6）。将来若要服务端渲染 HTML，记得那一步也得跑 KaTeX。
7. Viewer / frozen 工作区传 `readOnly`，编辑器进只读态，不是靠藏按钮。

## 5. 快捷键

| 键 | 作用 |
|---|---|
| `Ctrl/⌘+S` | 立刻保存（不等 850ms debounce） |
| `Ctrl/⌘+B` / `I` / `E` | 粗体 / 斜体 / 行内代码 |
| `Ctrl/⌘+Shift+X` | 删除线 |
| `Ctrl/⌘+Shift+K` / `L` | 插入链接 / 双链 |
| `Ctrl/⌘+Shift+O` / `U` | 引用 / 无序列表 |
| `Ctrl/⌘+Shift+Enter` | 任务项开关 |
| `Ctrl/⌘+F` | 文内查找替换 |
| `Enter` | 列表 / 引用 / 任务自动续行 |
| `[[` | 触发笔记标题补全；空查询给最近打开过的 |
| `Ctrl/⌘ + 单击` | 打开双链或链接。裸单击留给「点一下改字」，想读去右边预览栏 |
| 粘贴 / 拖入文件 | 存成当前笔记的附件，正文插链接（规格 §9.3） |
| `/` | 斜杠菜单，**只在行首触发**（标题 / 列表 / 表格 / 代码块 / 公式 / 日期…） |
| `Ctrl/⌘+Shift+P` | 命令面板（只放动作） |
| `Ctrl/⌘+\` | 折叠 / 展开左侧两栏 |
| `Esc` | 退出编辑器全屏（Vim 模式下先给 Vim，见 §3.3） |

注：`Ctrl+B` 在编辑器内是粗体，所以侧栏折叠没有照抄 VSCode 的 `Ctrl+B`，改用 `Ctrl+\`。
