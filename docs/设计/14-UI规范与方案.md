## 1. 产品给 UI 的硬约束（所有方案都遵守）

来自规格与界面架构，不因风格改变：

| 约束 | 含义 |
|---|---|
| 三套壳 | 广场 Public、文档站/分享 Site、登录后三栏 App |
| 登录后主场是笔记 | 不能做成「社交 App 里藏了个编辑器」 |
| 长时间阅读写作 | 正文对比度、行宽、字号优先于装饰 |
| 信息密 | 三栏 + 树 + Markdown，不能靠大留白撑场面 |
| 中文优先 | 字体必须有可靠中文；英文几何无衬线不能单独上场 |
| 家庭 + 小团队 | 不要赛博霓虹、不要加密货币落地页、不要过度玻璃拟态 |
| 三态可辨 | 库 / 站 / 流皮肤不同，但看得出是同一个产品 |

共同禁区（候选方案和最终方案都禁）：

- 纯黑字配纯白底无层次
- 超过 2 个强调色
- 圆角大于 16px 的大卡片堆叠
- 正文用细灰（对比不足）
- 文档站再引一套和编辑器不一样的 Markdown 样式
- 广场做成短视频/推荐流

共同基线：

- 间距 4 的倍数：4 / 8 / 12 / 16 / 24 / 32
- 正文阅读列宽 68–78 字
- 可聚焦环、不只靠颜色区分状态
- 浅色 / 深色两套语义 token；**默认跟方案走，可再改系统偏好**

## 2. 历史候选方案

以下四套是选型阶段的对照稿，保留作为主题包参考；产品出厂方案已锁定为第 7 节「现代墨白」，不再并行维护多套组件规范。

| 方案 | 一句话 | 像谁 | 适合你若更在意 |
|---|---|---|---|

| C 青瓷 | 温和的家庭文档 | 语雀 / 飞书文档 / 即刻 | 家人好接受、亲和 |
| D 夜航 | 开发者的第二大脑 | Obsidian / Cursor / GitHub | MCP、深色、密度 |

## 3. 方案 A · 纸墨 Editorial

**气质：** 纸、墨、一点点朱砂。像把笔记本摊在桌面上，而不是打开一个 SaaS。

**原始色**

| Token | Light | Dark |
|---|---|---|
| paper | `#F6F1E7` | `#1C1915` |
| ink | `#1C1917` | `#F3EDE3` |
| ink-2 | `#57534E` | `#A8A29E` |
| line | `#E7E0D4` | `#3F3A33` |
| accent | `#9A3412` 朱砂 | `#FDBA74` |
| accent-soft | `#FFEDD5` | `#431407` |
| good | `#3F6212` | `#A3E635` |

**字体：** 标题 `Source Han Serif SC` / `Noto Serif SC`；界面与正文 `Source Han Sans SC`；代码 `IBM Plex Mono`。  
**圆角：** 6px（按钮、输入），卡片 8px。阴影极弱，靠纸色分层。  
**密度：** 中。中栏树行高 28px，正文 16/28。

**三套壳**

- App：米色工作区，左栏略深一号的纸色；编辑器像一张纸，预览无卡片框。
- Site：更像文章站，标题衬线，无侧栏也可读。
- 广场：时间线仍是纸色，帖子不像推特蓝气泡，像短笺。

**优点：** 最符合「笔记 / 知识」心智，读得久不累。  
**风险：** 广场不像社交；有人会觉得「老气」。家人里年轻人可能嫌素。

## 4. 方案 B · 石墨 Workbench

**气质：** 中性灰 + 一条靛蓝。工具先于个性，十年后也不尴尬。

**原始色**

| Token | Light | Dark |
|---|---|---|
| paper | `#FAFAF9` | `#0C0E12` |
| ink | `#18181B` | `#F4F4F5` |
| ink-2 | `#52525B` | `#A1A1AA` |
| line | `#E4E4E7` | `#27272A` |
| accent | `#4F46E5` 靛蓝 | `#818CF8` |
| accent-soft | `#EEF2FF` | `#1E1B4B` |
| good | `#047857` | `#34D399` |

**字体：** 界面 `Inter` + `Source Han Sans SC`；正文同样；标题不加衬线；代码 `JetBrains Mono`。  
**圆角：** 8px。细边框 1px，几乎不用投影。  
**密度：** 中高。树行高 26px，正文 15/26。更接近 Notion。

**三套壳**

- App：白底灰线三栏，选中项淡靛蓝。属性芯片小、方。
- Site：标准文档站（Outline/VitePress 味），左导航右正文。
- 广场：卡片弱、分割线强，像论坛时间线而不是媒体 feed。

**优点：** 最不容易选错；设置页、表格、MCP 钥匙列表天生好看。  
**风险：** 辨识度低，容易「又一个笔记 SaaS」。

## 5. 方案 C · 青瓷 Soft Product

**气质：** 浅茶白 + 青瓷绿。语雀 / 飞书文档那一路，家庭成员学习成本最低。

**原始色**

| Token | Light | Dark |
|---|---|---|
| paper | `#F7F8F5` | `#121614` |
| ink | `#1A211C` | `#E8EEE9` |
| ink-2 | `#5B6B60` | `#9AA89E` |
| line | `#E3E8E2` | `#2A322C` |
| accent | `#0F766E` 青瓷 | `#2DD4BF` |
| accent-soft | `#CCFBF1` | `#134E4A` |
| good | `#15803D` | `#4ADE80` |

**字体：** `Plus Jakarta Sans` 不硬套中文；中文用 `Source Han Sans SC`。标题稍粗、字距略松。  
**圆角：** 10–12px。按钮更「胶囊」。轻阴影可以有一点。  
**密度：** 中低。树行高 32px，正文 16/28。点击区域更大。

**三套壳**

- App：圆角树节点、柔和悬停；空状态插画可以有，但克制。
- Site：友好文档，目录带浅青选中条。
- 广场：最像「社区」，帖卡圆角、头像大一点。

**优点：** 给父母 / 亲戚看不吓人；公开首页更像产品而不是 IDE。  
**风险：** 专业用户会觉得软；高密三栏略浪费空间。

## 6. 方案 D · 夜航 Dark IDE

**气质：** 默认深色，细线，密度高。Cursor 旁边那个大脑该长这样。

**原始色**

| Token | Light（次要） | Dark（默认） |
|---|---|---|
| paper | `#F4F4F5` | `#0E1116` |
| ink | `#18181B` | `#E6EDF3` |
| ink-2 | `#52525B` | `#8B949E` |
| line | `#E4E4E7` | `#21262D` |
| accent | `#2563EB` | `#58A6FF` |
| accent-soft | `#DBEAFE` | `#12283F` |
| good | `#059669` | `#3FB950` |

**字体：** `IBM Plex Sans` + `Source Han Sans SC`；代码 `IBM Plex Mono` 或 `Cascadia`。  
**圆角：** 4–6px。强调 1px 边框和字重，不靠阴影。  
**密度：** 高。树行高 24px，正文 14/24。侧栏可更窄。

**三套壳**

- App：深色三栏，活跃笔记左边一条亮线；源码模式是一等公民。
- Site：深色文档，代码块漂亮；非技术读者可能嫌暗。
- 广场：像 GitHub feed / 论坛，而不是微博。

**优点：** 和 MCP / Cursor 用户心智一致；夜间好用。  
**风险：** 家庭场景不友好；打印/投影文档站较差。必须认真做浅色，不能敷衍。

## 7. 锁定方案 · 现代墨白

**气质：** Vercel / Linear 去掉彩色之后的那一档。黑白灰分层，活力来自对比、字重、字距和实心选中，不来自渐变或插画。

**原则**

- 颜色预算：95% 黑白灰，强调色只用于当前选中、主按钮、焦点环和双链。
- 出厂强调色为浅色黑、深色白；用户可改为「一线蓝」或其他合规主题色。
- 圆角基准 8px，细线 1px，常规容器不用投影；浮层仅用克制阴影。
- 标题字距收紧，正文优先保证中文长文阅读。
- 树行高 30–32px，密度中等，不走 IDE 极限紧凑路线。
- 明暗默认跟随系统，并允许用户固定浅色或深色。

**出厂原始色（浅 / 深）**

| Token | Light | Dark |
|---|---|---|
| paper | `#FAFAFA` | `#0A0A0A` |
| paper-2 | `#F4F4F5` | `#141414` |
| ink | `#0A0A0A` | `#F5F5F5` |
| muted | `#525252` | `#A3A3A3` |
| line | `#E5E5E5` | `#262626` |
| accent 默认 | `#0A0A0A` | `#F5F5F5` |
| accent 一线蓝 | `#2563EB` | `#60A5FA` |

**字体：** 界面与标题使用 `Inter, "PingFang SC", "Microsoft YaHei", "Source Han Sans SC", sans-serif`；代码使用 `ui-monospace, "Cascadia Mono", "JetBrains Mono", Consolas, monospace`。标题不使用衬线体。

## 8. 前端 UI 技术方案（锁定）

采用 **Tailwind CSS + shadcn/ui + Radix UI**，三者职责不可混淆：

| 层 | 职责 | 使用规则 |
|---|---|---|
| Tailwind CSS | 布局、响应式、状态样式、设计 token 映射 | 页面和组件优先使用语义 utility；禁止散落任意 hex、任意字号和无依据的 arbitrary value |
| shadcn/ui | Button、Input、Dialog、Sheet、Dropdown、Tabs、Tooltip 等基础组件源码 | 组件源码纳入仓库统一维护，不把 shadcn 当不可修改的黑盒依赖 |
| Radix UI | Dialog、Popover、Menu、Select、Tabs 等复杂行为与无障碍原语 | 优先通过 shadcn 封装使用；只有缺少所需能力时才直接组合 Radix Primitive |
| Lucide React | 统一图标 | 默认 `16px`、`strokeWidth=1.75`；同一操作不得混用 emoji、字符图标和其他图标库 |
| CVA | 组件尺寸与视觉变体 | Button、Badge、Alert 等多变体组件必须集中声明 variant |
| `clsx` + `tailwind-merge` | 条件类名和冲突消解 | 统一通过 `cn()` 辅助函数，不手工拼接复杂 class 字符串 |

### 8.1 采用边界

- shadcn/ui 是**起点**，不是最终视觉规范；引入后必须映射本项目 token、尺寸和交互规则。
- 页面不得直接依赖 Radix 的 DOM 结构或 `data-*` 状态来写全局脆弱选择器；状态样式留在组件封装内。
- 业务代码优先引用项目组件（如 `@/components/ui/button`），不在页面重复实现按钮、输入框、弹窗、菜单和提示。
- 不再引入 Ant Design、MUI 等第二套完整组件体系，避免 token、交互和包体重复。
- CodeMirror、Markdown 内容区、复杂目录树可以使用专用实现，但颜色、边框、字号、焦点态必须消费同一套语义 token。
- 复杂数据表格未来按需引入 TanStack Table；复杂表单按需采用 React Hook Form + Zod，不作为基础首屏依赖。

### 8.2 推荐目录

```text
apps/web/src/
  components/
    ui/                 # shadcn 基础组件及项目级改造
    app/                # 三栏、目录树、编辑器工具栏等 App 组件
    site/               # 文档站与分享页组件
    public/             # 广场组件
  features/             # 按业务域组织的组合组件与逻辑
  lib/
    utils.ts            # cn()
  styles/
    globals.css         # Tailwind 入口、语义 token、基础层
    markdown.css        # 唯一 Markdown 皮肤
  theme/                # ResolvedTheme 注入与明暗模式
```

业务目录可随实现演进，但 `components/ui` 只放无业务语义的基础组件；禁止把 API 请求和权限逻辑塞入其中。

## 9. Token 与 Tailwind 映射

主题系统仍以 [15-主题系统](./15-主题系统.md) 的 CSS 变量为唯一运行时来源。Tailwind 只负责将变量暴露为语义类，不复制一套固定色板。

推荐语义映射：

| 语义 | CSS 变量 | Tailwind 用法示例 |
|---|---|---|
| 页面背景 | `--bg` | `bg-background` |
| 次级背景 | `--bg-subtle` | `bg-muted/50` 或项目定义的 `bg-subtle` |
| 控件/代码底 | `--bg-muted` | `bg-muted` |
| 主文字 | `--fg` | `text-foreground` |
| 次文字 | `--fg-muted` | `text-muted-foreground` |
| 边框 | `--border` | `border-border` |
| 主题色 | `--accent` | `bg-primary`、`text-primary` |
| 主题色前景 | `--accent-fg` | `text-primary-foreground` |
| 选中浅底 | `--accent-soft` | `bg-accent` |
| 成功/危险/警告 | `--good` / `--danger` / `--warning` | 项目语义类或 CSS 变量 utility |
| 圆角 | `--radius` | `rounded-md` 作为基准 |

规则：

1. 业务组件不得写死 `#2563EB`、`zinc-500` 等视觉值；原始色只在出厂主题定义中出现。
2. 透明度可以通过语义颜色叠加，但不可让正文对比度跌破 WCAG AA。
3. shadcn 默认的 `background`、`foreground`、`primary`、`muted`、`border`、`ring` 等变量应桥接到本项目 token，不维护两套主题状态。
4. `dark` 类只负责选择模式；实际色值仍来自 ResolvedTheme。避免在组件里堆叠大量 `dark:` 固定颜色。
5. 用户切换主题或 accent 后，组件无需重新渲染颜色逻辑，只更新根节点 CSS 变量。

## 10. 排版、间距与布局

### 10.1 字号与行高

| 用途 | 字号 / 行高 | 字重 |
|---|---|---|
| 辅助标签 | 12 / 16 | 500 |
| 紧凑控件、树节点 | 13 / 20 | 400–500 |
| 默认界面正文 | 14 / 22 | 400 |
| Markdown 正文 | 16 / 27 | 400 |
| 小标题 | 18 / 26 | 600 |
| 页面标题 | 24 / 32 | 650–700 |
| 展示标题 | 32 / 40 | 700 |

- 中文正文不得用过轻字重；主正文最低 `400`。
- 页面标题字距可用 `-0.025em`，仅展示级标题可收紧至 `-0.04em`。
- 不用全大写承载中文层级；英文微标签若全大写需增加字距。

### 10.2 间距与尺寸

- 基础间距阶：`4 / 8 / 12 / 16 / 24 / 32 / 48`。
- 控件高度：紧凑 `28px`、默认 `36px`、突出操作 `40px`；触屏窄屏主要操作点击区不小于 `44px`。
- 图标尺寸：行内 `14px`，常规操作 `16px`，空状态 `24–32px`。
- 三栏桌面基线：笔记本栏 `220px`、目录栏 `260px`、编辑器自适应；侧栏允许拖动并保存宽度。
- Markdown 阅读列 `max-width: 720px`（约 68–78 个中文字符的视觉宽度），居中但不做悬浮大卡片。
- 窄屏侧栏使用 shadcn `Sheet` / Radix Dialog 语义抽屉；不得简单把三栏压缩到不可读。

### 10.3 圆角、边框和阴影

- `--radius = 8px` 为默认基准；小控件 6px，常规控件 8px，Dialog/Sheet 最多 12px。
- Badge 可用胶囊圆角；大容器和每个列表项禁止无差别胶囊化。
- 静态层级优先使用背景差与 1px 边框，不用阴影。
- Dropdown、Popover、Dialog 可使用单层柔和阴影；禁止彩色光晕和多层拟物阴影。

## 11. 组件规范

### 11.1 Button

- 变体限定为 `default / secondary / outline / ghost / destructive / link`，业务不得临时新增同义变体。
- 一个视区或 Dialog Footer 通常只有一个实心主按钮。
- 仅图标按钮必须带可访问名称，并在陌生图标上提供 Tooltip。
- Loading 时保持原宽，禁用重复提交，同时用文字或 spinner 表达状态。

### 11.2 表单控件

- Label 永远可见；placeholder 只给例子，不代替标签。
- 错误信息紧邻字段，并用文字 + 图标/边框表达，不能只变红。
- 默认输入高度 36px；长文本、Markdown 源码和搜索框按场景单独定义。
- 表单提交失败后聚焦或滚动到第一个错误字段。

### 11.3 Dialog、Sheet、Popover、Menu

- **任何弹窗、确认和提示都禁止使用浏览器原生 `alert()`、`confirm()`、`prompt()` 或 `beforeunload` 默认提示作为产品交互。**
- 普通确认或短表单统一使用基于 shadcn/ui + Radix UI 的 Dialog / AlertDialog；移动侧栏和复杂辅助面板用 Sheet；轻量上下文操作用 Popover / Dropdown Menu；短暂结果提示用统一 Toast。
- 离开未保存页面应使用应用内 Dialog；只有浏览器关闭、刷新或跨站离开且确有数据丢失风险时，才允许将 `beforeunload` 作为最后一道保护。受浏览器安全限制，此时原生离站提示是唯一例外，不得用它承载自定义文案或常规业务确认。
- 使用 Radix 的焦点锁定、返回焦点、Esc 关闭和键盘导航，不自行模拟。
- 破坏性确认必须写明对象和后果；不可只写「确定吗」。
- Tooltip 不承载必须阅读的信息，也不放交互控件。

### 11.4 状态反馈

每个异步页面或组件必须覆盖：`loading / empty / error / success`，编辑器额外覆盖 `dirty / saving / saved / conflict / read-only`。

- 首次加载用 Skeleton；局部提交用按钮 loading，不让整页闪烁。
- Toast 用于短暂结果，不替代字段错误或必须处理的冲突。
- 空状态说明「为什么为空」并提供至多一个主行动。
- 删除、冲突、权限不足等状态必须有明确文字，不只依靠颜色。

### 11.5 目录树与高密列表

- 树节点默认高 30–32px，缩进步长 16px。
- 行尾操作默认弱化，hover、focus-within 或选中时出现；键盘聚焦时必须可见。
- 当前项、hover、focus 三态必须不同；当前项不能只用文字加粗表示。
- 拖放必须有落点指示，并提供非拖放替代操作。

## 12. Markdown 与编辑器规范

- App 预览、Site、Share 和公开内容复用同一 `.markdown` 皮肤与解析链，只通过容器宽度和少量壳 token 调整。
- Markdown 正文 16/1.7；段落间距 0.85em；标题上方留白大于下方，形成内容分组。
- 链接与 wikilink 使用 `--wiki`；未解析双链用 `--wiki-unresolved` + 虚线下划线，不只换颜色。
- 行内代码使用 `--bg-muted`；代码块与正文边界清楚，支持横向滚动，不强制折行破坏源码。
- 表格在窄屏允许横向滚动；不得压缩到文字逐字换行。
- 编辑器源码区使用等宽字体，但工具栏、状态栏仍使用 UI 字体。
- CodeMirror 的 selection、caret、gutter、active line、诊断颜色必须桥接语义 token。

## 13. 交互、动效与无障碍

- Hover / focus 过渡 `120–160ms`，Sheet / Dialog `180–220ms`；只动画 `opacity` 和 `transform`，避免布局抖动。
- 尊重 `prefers-reduced-motion`，关闭非必要位移和缩放。
- 所有可操作元素必须可键盘访问；不要用带 `onClick` 的 `div` 冒充按钮。
- 焦点环统一使用 `ring` 语义色，`focus-visible` 下清晰可见，不能全局 `outline: none`。
- 正文与背景至少 4.5:1，建议 7:1；大字至少 3:1；状态色与相邻颜色也需可辨。
- 图标按钮、折叠开关、树节点、Dialog 标题必须有正确的 accessible name / description。
- 快捷键只作加速，不得成为唯一入口；`Ctrl+K` 等提示需兼顾 macOS 键位显示。

## 14. 响应式与三套壳

| 断点意图 | 规则 |
|---|---|
| `< 768px` | 单主栏；导航和目录进 Sheet；阅读与编辑优先，不展示永久三栏 |
| `768–1199px` | 保留一个侧栏，另一侧栏按需抽屉；编辑区最小可用宽度优先 |
| `≥ 1200px` | 完整三栏；支持侧栏拖动、折叠和宽度持久化 |

- Public：顶栏和时间线克制，内容不是营销卡片墙。
- Site / Share：阅读优先，站点目录可固定或抽屉化；无工作区切换器。
- App：高密工作台；三栏、命令面板、辅助抽屉共享同一组件规范。
- Settings：见 §14.1。
- Auth / Admin 复用同一 token 和基础组件，但可以使用独立页面壳。

### 14.1 Settings 壳（设置与管理类页面）

工作区设置、回收站、AI 与 MCP、外观这些「不是在写笔记，是在配东西」的页面共用一套壳，实现在
`apps/web/src/components/settings-shell.tsx`，**不允许再各自搭一套页面骨架**。

结构固定为：

```
顶栏（sticky）：返回工作区 | 面包屑「工作区名 › 当前页」 | 冻结徽章 | 打开工作区
左栏 264px（sticky）：身份卡（工作区首字母 + 名称 + 类型·角色）+ 分组导航
主栏：H1 text-2xl tracking-[-.035em] + 一句说明 + 内容
```

- 导航分四组，**回收站 / 圈子动态 / AI 与 MCP 是一等条目，不是脚注式的「相关页面」**：
  工作区（概览、成员与邀请、分享与外链、备份、导入与导出、审计日志、内容审核）、
  内容（回收站、圈子动态、AI 与 MCP）、账号（外观）、危险区（冻结与注销）。
- 只有 owner / admin 能看的条目标 `managerOnly`，角色不够时不渲染，不做灰显。
- 同一路由内换页签用 `replace`，跨路由用 push——避免在设置里点几下就退不出去。
- 卡片一律 `rounded-xl border border-border bg-background`（壳导出的 `cardCls`）。
  底色是 `bg-muted/25`，卡片不带 `bg-background` 会糊成一片，这是硬要求不是偏好。
- 三态（loading 骨架 / empty / error 重试）由壳统一提供，页面不再各写各的。

## 15. 工程约束与验收清单

### 15.1 工程约束

- 新增基础交互前先检查 `components/ui`；已有组件通过 variant 扩展，避免复制。
- 禁止在 JSX 中写大段重复 Tailwind 类；重复两处以上且有稳定语义时抽组件或 variant。
- arbitrary value 仅用于确有产品依据的布局尺寸，并在附近注释或集中成 token。
- 不允许用 `!important` 常态覆盖 shadcn；冲突应在组件源或 token 映射层解决。
- 第三方组件必须经过主题、暗色、键盘和可访问性适配后才能进入页面。
- 禁止新增 `window.alert` / `alert`、`window.confirm` / `confirm`、`window.prompt` / `prompt`；这条已由根目录 `eslint.config.mjs`（`no-alert` + `no-restricted-properties`）强制，`pnpm lint` 会直接报错，不再依赖人工 review。
- 业务确认、输入和反馈统一走这四个组件，页面里不再各自写 `{msg && <p>}`（§8.1「不在页面重复实现提示」）：
  - 破坏性确认 → `useConfirm()`；收一段输入 → `usePrompt()`（同在 `components/ui/confirm.tsx`，底层 `components/ui/alert-dialog.tsx`）。`useConfirm` 支持 `requireText`，用于要求逐字输入名称才放行的高危操作。
  - **一次性结果**（保存成功、删除成功、某个动作失败）→ `useToast()`（`components/ui/toast.tsx`）。
  - **表单与字段级错误**（提交校验失败、密码错误）→ `<FormError>`（`components/ui/form-error.tsx`），必须渲染在对应表单/对话框内部、紧邻出错的字段，不能用 Toast 代替。
  - 编辑器的 `dirty / saving / saved / conflict / read-only` 留在编辑器状态条里，冲突与保存失败要和「已保存」在视觉上区分开。
- 初期允许旧 CSS 与新体系并存，但新增页面和重做组件不得继续扩展旧的全局视觉类；迁移完成后删除无引用样式。
