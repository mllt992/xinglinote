## 1. 范围

### 1.1 一句话

**日历是知识库的时间面，不是塞进来的第二个待办 App。**

同一份内容有两种打开方式：按结构打开是「笔记本 / 目录 / 笔记」，按时间打开是日历。日历上的每一条，都必须能追回到库里的某个东西——某篇笔记的某一行、某篇日记、某次编辑。凭空存在、跟笔记毫无关系的条目，只允许出现在一个地方：收件箱（见 §3.3）。

### 1.2 三层内容

日历同时叠三层，用户可分层开关。**默认只开前两层**：

| 层 | 对象 | 可勾选 | 来源 | 说明 |
|---|---|---|---|---|
| 任务层 Task | 待办 | 是 | 笔记正文的任务列表行、收件箱、MCP、AI | 有 `due_at` 才上日历；无期限的只在收件箱 |
| 日程层 Event | 事件 | 否 | 手动创建、ICS 订阅 | 有起止时间，可全天、可跨天、可重复 |
| 足迹层 Footprint | 只读痕迹 | 否 | 笔记 `created_at` / `updated_at`、日记笔记 | 「我这天写了什么」，不可编辑、不可拖拽 |

足迹层是知识库独有的东西，参考产品只在日期格上放了一个笔记数角标。我们把它做成可展开的当日时间轴，并支撑「去年今日」。

**但它默认关。** 这条改过一次：原来三层默认全开，结果是重度使用的人一天建十几篇笔记，日期格被笔记标题挤满，日程反而看不见了——日历首先得能回答「我今天要干什么」，其次才是「我这天写了什么」。所以足迹层收成一个左下角的数字角标，点角标才展开当日笔记；角标本身也归这个开关管，关掉就彻底不占格子。想回看写作痕迹的人开一次，开关记在 URL 的 `layers` 上，下次进来还在。

### 1.3 与参考产品（ideaShell）对照

对照的意义是划出我们必须赢的地方，不是抄清单。

| 维度 | 参考产品现状 | 我们 | 优先级 |
|---|---|---|---|
| 视图 | 日 / 周 / 月 | 日 / 周 / 月 / **议程（Agenda）** | P0 |
| 笔记 ↔ 待办 | 笔记能生成待办，看不出勾选是否回写正文 | **双向同步**：日历勾选回写正文 `- [x]`，正文勾选即时上日历；靠块锚定位，改文案 / 移动行不丢关联（§5.1） | P0 |
| 改期 | 未见拖拽 | 拖拽改期、拉伸改时长、收件箱拖进日期格、Alt 拖拽复制 | P0 |
| 撤销 | 未见 | 所有位移与破坏性操作出 toast 带「撤销」，`Ctrl/Cmd+Z` 生效 | P0 |
| 重复日程 | 未见 | RRULE 子集 + 单次例外（改期 / 跳过 / 单独完成） | P1 |
| 提醒 | 条目上有时间标记 | 站内铃铛 + 邮件，多提醒点（提前 N 分钟 / 绝对时刻），复用现有 `notifications` 与 `mail.send` | P0（站内）/ P1（邮件） |
| 与系统日历互通 | 未见 | 订阅外部 ICS（只读）+ 导出自己的 ICS 订阅地址（token 化） | P1 |
| 日记 | 未见 | 按模板落到固定笔记本与路径。**入口在格子右键菜单与顶栏「⋯」，不占日期格的主位**——日期格是建日程的地方，见 §3.2 | P0 |
| AI / MCP | 未见 | `list_tasks` / `create_task` / `complete_task` 进 MCP；AI 能答「我这周要做什么」 | P1 |
| 时区 | 顶栏显示 GMT+8 | 显式时区，跨时区与夏令时按 §4.2 规则，不做「本地时间存字符串」 | P0 |
| 视图状态 | 在 URL 上（`?view=day`） | 同样进 URL（`view` + `date` + `layers`），刷新与分享保持 | P0 |
| 键盘 | 未见 | 全键盘可达，见 §3.6 | P0 |

### 1.4 一期不做

CalDAV 双向同步、跨工作区聚合大日历、甘特图与看板、日程冲突自动排期、AI 自动规划一天、独立移动 App、共享日程的邀请与出席回执（RSVP）、按人力排产。

## 2. 对象与状态机

### 2.1 对象

统一一张表 `calendar_items` 装 task 与 event。理由：两者的视图、拖拽、提醒、权限、ICS 导出逻辑几乎重合，拆两张表会立刻长出两套查询与两套前端。用 `kind` 区分，用 CHECK 约束各自的必填字段。

```
calendar_items
  id                uuid pk
  workspace_id      uuid  not null            -- 权限的锚点，跟工作区走
  kind              text  not null            -- task | event
  title             text  not null
  body_md           text  default ''          -- 短备注，不是笔记正文
  all_day           boolean default false
  starts_at         timestamptz               -- event 必填；task 可空
  ends_at           timestamptz               -- event 必填
  due_at            timestamptz               -- task 用；为空 = 只在收件箱
  timezone          text  not null            -- IANA，创建时的时区，见 §4.2
  status            text  not null default 'open'    -- open | done | cancelled
  done_at           timestamptz
  done_by           uuid
  priority          smallint default 0        -- 0 无 / 1 低 / 2 中 / 3 高
  color             text                      -- 语义色 token 名，不存 hex
  rrule             text                      -- RFC5545 子集，见 §4.4
  rrule_until       timestamptz
  source            text  not null default 'manual'  -- manual | note | ics | mcp | ai
  source_note_id    uuid                      -- source=note
  source_anchor     text                      -- 块锚，见 §5.1
  source_sub_id     uuid                      -- source=ics 时指向订阅
  link_state        text  not null default 'linked'  -- linked | detached
  notebook_id       uuid                      -- 冗余自来源笔记，供 ACL 快速过滤
  assignee_user_id  uuid                      -- 团队工作区可指派
  created_by / updated_by / created_at / updated_at
  trashed_at        timestamptz               -- 走现有回收站语义
```

```
calendar_overrides            -- 重复项的单次例外
  id, item_id, occurrence_start (原始时刻，唯一键的一半)
  action        text          -- moved | cancelled | done
  new_start, new_end, done_at, done_by

calendar_reminders
  id, item_id
  kind          text          -- relative | absolute
  offset_min    integer       -- relative：负数表示提前
  absolute_at   timestamptz
  channel       text          -- inapp | email | push
  status        text          -- pending | scheduled | fired | skipped
  fired_at      timestamptz

calendar_subscriptions        -- 外部 ICS 只读订阅
  id, workspace_id, name, url, color, enabled
  etag, last_sync_at, last_error, created_by

calendar_feed_tokens          -- 对外导出 ICS 的订阅地址
  id, workspace_id, user_id, token (32B url-safe，不可枚举)
  scope         text          -- mine | workspace
  status        text          -- active | revoked
  last_used_at

calendar_templates            -- 一组相对时间的条目，套到某一天（§3.12）
  id, workspace_id, name, description
  scope         text          -- workspace | private
  items         jsonb         -- [{kind,title,body_md,all_day,offset_days,start_min,duration_min,priority,reminders:[offset_min]}]
  created_by, created_at, updated_at

push_subscriptions            -- Web Push 端点，一人多设备（§5.7）
  id, user_id
  endpoint      text unique   -- 浏览器给的推送端点
  p256dh, auth  text          -- RFC 8291 的客户端公钥与鉴权密钥
  user_agent    text
  status        text          -- active | gone
  fail_count    integer
  last_ok_at, created_at
```

索引至少：`(workspace_id, starts_at)`、`(workspace_id, due_at)`、`(source_note_id)`、`(assignee_user_id, status)`、`calendar_reminders(status, 触发时刻)`、`push_subscriptions(user_id, status)`。

### 2.2 状态机

**任务**

```
open ──勾选──▶ done ──取消勾选──▶ open
  │                                  ▲
  └──────── cancelled ───恢复────────┘
```

- `done` 只是状态，不删除；日历上保留但降级显示（删除线 + 弱化色）。
- 来源笔记进回收站：任务跟着隐藏（不是删除），笔记恢复则一起回来。走 [12-回收站](./12-回收站与身份生命周期.md) 的批次语义。

**来源锚**

```
linked ──源行被删 / 锚丢失──▶ detached
detached ──用户「重新关联」或锚重现──▶ linked
```

`detached` 不静默删除条目。日历上打「已脱离原文」标记，面板里给两个动作：转为独立任务 / 删除。静默消失比留个断链更糟。

**提醒**

```
pending ──worker 入队──▶ scheduled ──到点──▶ fired
                                   └──条目已完成 / 取消 / 改期──▶ skipped
```

**重复实例**：不落库。只在查询时按 `rrule` 展开，命中 `calendar_overrides` 才覆盖（§5.2）。

## 3. 交互

### 3.1 入口与路由

| 路径 | 说明 |
|---|---|
| `/w/:wsId/calendar` | 日历主页面，query：`view=day\|week\|month\|agenda`、`date=YYYY-MM-DD`、`layers=task,event,note`（默认 `task,event`，足迹层不在内） |
| `/w/:wsId/today` | 今天：今日待办 + 今日日程 + 今天改过的笔记 + 去年今日 |

左栏在「笔记 / 已分享」之间插入「日历」一级项，与参考产品一致。App 壳保持三栏心智：**左栏不变，中栏变成日历网格，右栏变成任务面板**，不新开一套壳。这样从笔记切到日历，左树不重排、不闪。

### 3.2 四个视图

统一顶栏分三区，只放高频的：

| 区 | 内容 |
|---|---|
| 左 | 返回笔记 + 月份标题（点开迷你月历跳转） |
| 中 | 日 / 周 / 月 / 议程 段控 |
| 右 | `‹ 今天 ›` · 「+ 新建」 · 订阅图标 · 右栏开关 · 「⋯」 |

层开关、模板、今天页、写日记、时区标注全部收进「⋯」菜单或右栏，**顶栏一行不超过 8 个可点目标**。这条也是改过的：原来把十几个控件平铺在一行（四个视图 + 三个层 + 时区 + 翻页三件 + 今天页 + 模板 + 订阅 + 新建 + 待办），每个都是 12px 无边框小字，结果是没有主次——最该被看见的「+ 新建」和最不该被误触的「模板」长得一模一样，而分层开关小到没人发现它存在。

- **日**：单日时间轴，左侧时刻列显式标注时区（`GMT+8`）。当前时间红线，每分钟走；首次进入滚到「当前时间 − 2 小时」。全天区固定在顶部。
- **周**：七列。今日列头高亮，非本周弱化。跨天事件在全天区横条贯通。
- **月**：每格按格高自适应显示条数（不写死 3 条），溢出**不是死的「还有 N 项」**——悬停出浮层列全部，点击则该行整行原地展开（不跳视图、不弹模态）。格右上角是日期。**点格子空白处 = 就地建日程**，弹一张小卡片填标题与时间，回车即存，和日 / 周视图划时段建日程落到同一个组件、同一套手感。左下角的当日笔记数角标只在足迹层开着时出现，点角标展开当天写了什么。
- **议程**：按天分组的纵向列表，密度最高，天然适配窄屏与键盘流。参考产品没有，但这是「一次看完接下来两周」最快的视图。

### 3.3 右侧任务面板

结构沿用参考产品的两段式，但明确语义：

- **收件箱**：无 `due_at` 的任务。这是唯一允许「和笔记无关」的地方，用来接住随手记。支持一行一条快速录入。
- **按来源笔记分组**：每组标题是笔记标题，右侧一个「跳到原文」箭头。组内条目显示提醒时刻。这与参考产品截图一致，但每条多两件事：hover 出「改期 / 设提醒 / 指派」，以及可以拖到左边日历格。

面板顶部加筛选条：`我的 / 全部 / 逾期 / 本周`，逾期数量做红点。逾期任务在日历上**停在原位**并标红，不自动搬到今天——自动搬家会让人失去「我欠了什么」的感知。

**面板默认常驻**，不是点一下才出来的抽屉：收件箱要能随手接住想法、随手拖上历，藏起来就等于没有。开合状态与宽度记在本地，下次进来照旧。窄屏下退回抽屉（§3.9）。

### 3.4 快速添加

一个输入框吃自然语言，`n` 键唤起：

```
明天下午3点 和销售团队对齐季度数据 !高 30分钟
每周五 17:00 周报
8/25 交房租
```

解析结果以**芯片形式回显在输入框下方**（日期芯片、时长芯片、优先级芯片），点芯片可改，不满意可整个丢弃回退成纯文本标题。绝不静默猜错时间就写库。

**边界：自然语言解析只用在这个输入框，不用在笔记正文。** 正文只认严格语法（§5.1），否则用户写「上周三讨论的方案」会平白多出一条待办，这类误报会直接毁掉信任。

### 3.5 拖拽

| 操作 | 结果 |
|---|---|
| 拖条目到另一格 / 另一时段 | 改期，保持时长 |
| 拖条目上下边缘 | 改时长，15 分钟吸附；按住 `Shift` 关掉吸附 |
| 在周 / 日视图空白处按住拖拽 | 划出时段并就地建日程，回车即存 |
| 在月视图空白处单击 | 就地建日程（同一张卡片，默认当天 09:00，时长 1 小时） |
| 从右侧收件箱拖到日期格 | 设置 `due_at`，任务上历 |
| 从日历拖回收件箱 | 清空 `due_at`，落回收件箱 |
| 按住 `Alt` 拖拽 | 复制一份 |
| 拖重复项 | 先问「仅此一次 / 此后全部」，不默认 |

拖拽全程乐观更新，落点用虚影预览；请求失败**回到原位**并出错误 toast，不留在错误位置。

### 3.6 键盘

| 键 | 动作 |
|---|---|
| `d` `w` `m` `a` | 切日 / 周 / 月 / 议程 |
| `t` | 今天 |
| `←` `→` / `j` `k` | 上一段 / 下一段时间 |
| `n` | 快速添加 |
| 方向键（无选中时） | 在网格里移动焦点格 |
| `Enter` | 打开焦点条目 / 在焦点格新建 |
| `Space` | 勾选 / 取消勾选焦点任务 |
| `Backspace` | 删除焦点条目（进回收站，可撤销） |
| `[` `]` | 焦点条目前移 / 后移一天 |
| `Ctrl/Cmd+Z` | 撤销上一次改期、勾选、删除 |
| `/` | 面板内筛选 |
| `Esc` | 关闭浮层 / 取消拖拽 |

不与全局 `Ctrl+K` 搜索、`Ctrl+S` 保存冲突。

### 3.7 反馈与撤销

- 改期、勾选、删除、批量改，一律出 toast：`已改到 8月20日 15:00 · 撤销`。撤销窗口 8 秒，`Ctrl/Cmd+Z` 在窗口内等价。
- 撤销栈只保留当前会话最近 20 步，服务端不做长期反向日志——但每步都写 `audit_logs`。
- 勾选一条来自笔记的任务：条目上短暂显示「已同步到《笔记标题》」，让回写这件事**可见**。回写失败时条目角标变黄并可重试；绝不允许「日历打了勾、笔记里还是空框」却无人知晓。

### 3.8 加载、空、错

- 加载：网格骨架（保持行列结构，不用转圈），已缓存的月份直接渲染再后台刷新。
- 空：月视图空态一句话 + 两个动作「写今天的日记」「新建日程」；收件箱空态提示可以从笔记里勾。
- 错：整月加载失败只在网格上方挂条形错误并给「重试」，**不清空已渲染内容**。
- 越界：`date` 超出合理范围（1970 前 / 2100 后）夹回今天，不白屏。

### 3.9 窄屏

窄屏默认落到**议程视图**；月视图退化为「迷你月历 + 当日列表」上下布局；右侧面板改为底部抽屉。不做独立移动 App（与 05 一致）。

### 3.10 无障碍

网格用 `role="grid"` / `gridcell`，日期格 `aria-label` 念完整日期与条目数；条目状态不只靠颜色（逾期加图标、完成加删除线）；拖拽必须有等价键盘路径（`[` `]` 与「改期」菜单）；焦点环遵循 14 的可聚焦环规范。

### 3.11 批量选择与操作

批量是给「周一早上收拾上周欠账」用的，不是给管理员做数据维护用的，所以入口在日历与面板里，不在设置页。

- **进入**：条目上 `Ctrl/⌘ + 点击` 加选，`Shift + 点击` 按当前视图的排列顺序连选；面板顶部换成「已选 N 项」工具条。`Esc` 或点空白退出。
- **动作**：完成 / 取消完成、改期（+1 天 / +7 天 / 指定日期 / 清除期限）、指派、改优先级、删除、恢复。
- **一次提交一批，逐条鉴权**：服务端对每条单独跑 `can_edit_calendar_item`，返回逐条结果 `{id, ok, code}`。整批**不因为其中一条没权限而回滚**——那会让用户完全不知道是哪条卡住了。toast 报「已改 8 项，3 项没动」，展开看明细。
- **重复条目**：批量只作用于**整条序列**，不作用于单次实例。要改单次仍走「仅此一次 / 此后全部」那条路径，批量条上明示这一点。
- **撤销**：同 §3.7，一次批量在撤销栈里算一步，撤销即反向批量；删除走回收站，恢复即撤销。
- **上限**：一次最多 200 条。再多就该先筛选再分批，而不是让一个请求跑几分钟。
- 每条各写一行 `audit_logs`，`details.batch` 记同批次 id，事后能追。

### 3.12 日历模板

模板解决的是「每次出差 / 每次迭代 / 每次带新人，都要手敲同一组条目」。

- **存**：多选一组条目 →「存为模板」。存的是**相对结构**：以选中条目里最早的那天为第 0 天，每条记 `offset_days` + 当地起始分钟 + 时长 + 优先级 + 提醒偏移。绝不存绝对日期，否则模板只能用一次。
- **用**：选一个日期「套用」，先预览落几条、分别落在哪天，确认才写库。套出来的条目 `source=manual`，与模板**此后无关联**——模板改了不追溯已落地的条目。追溯会让「上周排好的日程今天自己变了」。
- **范围**：`scope=private` 只有自己看得见；`scope=workspace` 全工作区可用，只有 owner / admin 能建与改。
- 模板不含来源笔记、不含指派人（换个项目就换人了），套用后再指派。
- 单工作区最多 50 个模板，单模板最多 100 条。

## 4. 业务规则

### 4.1 权限

1. 日历项属于工作区，读写一律走 [00 §5](./00-索引与约定.md) 的统一入口，新增两个：`can_read_calendar_item`、`can_edit_calendar_item`。
2. `source=note` 的条目，可见性**完全继承来源笔记**：`can_read_note(actor, note) == false` 则该条目对其不存在（不是灰显，是不返回）。私密笔记本里的待办不能从日历漏出去。
3. `source=manual` 的条目：默认工作区全体成员可见；创建者可标「仅自己」。
4. Viewer 角色：只读日历，无新建、无勾选、无拖拽。
5. 个人工作区无指派（`assignee` 隐藏），与个人区无邀请一致。
6. 实例管理员进他人工作区，不出现「我能看私密条目」的假入口。

### 4.2 时区

- 全部时刻列 `timestamptz`，落库即 UTC。
- 每条存创建时的 IANA `timezone`；**全天条目按其 `timezone` 的当地日历日判归属**，不按 UTC 日切，否则 GMT+8 用户的「8月18日全天」会在 UTC 下漂到 17 日。
- 渲染时区 = 用户设置 > 工作区默认 > 浏览器。顶栏显式标注当前渲染时区（参考产品的 `GMT+8` 做法，保留）。
- 重复规则按**当地时间**展开再转 UTC，跨夏令时保持「每天 9:00」而不是「每 24 小时」。
- 用户改时区：不改任何已存数据，只改渲染。

### 4.3 笔记勾选与版本（对 [03](./03-笔记目录编辑器与版本.md) §7 的补充）

03 定下「任务列表勾选算一次保存」。日历会把勾选频率放大，若一勾一版，版本历史会被待办淹没。

**规则：** `notes.version` 仍然单调递增（否则编辑器里开着的那一份会拿旧版本盖掉勾选结果），但**版本历史条目合并**：同一篇笔记、同一作者、5 分钟内的连续勾选复用同一条 `note_versions` 记录，只把它的 `version` / 正文更新到最新，`source = task_toggle`；期间若发生正文编辑，立即封版，之后正常走 `manual`。回写产生的保存**不触发** `note.rewrite_links`（与 `link_rewrite` 的防环规则同源），只触发 `note.index` / `note.embed`。

### 4.4 重复

一期只支持 RRULE 子集，UI 上表现为固定选项 + 一个「自定义间隔」：

```
FREQ=DAILY|WEEKLY|MONTHLY|YEARLY
INTERVAL=n
BYDAY=MO,TU,...      (WEEKLY)
BYMONTHDAY=n         (MONTHLY)
UNTIL / COUNT
```

不支持 `BYSETPOS`、农历、复杂例外表达式。展开上限：单次查询窗口内最多 500 个实例，超出截断并提示。改重复项一律先问「仅此一次 / 此后全部」；选「此后全部」= 原序列在该时刻前 `UNTIL` 截断 + 新建后续序列，不原地改历史。

### 4.5 提醒

- 每条最多 5 个提醒点。默认：定时日程提前 10 分钟，全天条目当日 09:00，任务**不默认加提醒**（避免噪音）。
- 条目改期 → 相关 `pending/scheduled` 提醒重算；条目完成 / 取消 / 删除 → 未触发的提醒置 `skipped`。
- 同一条目同一渠道 10 分钟内只发一次（去重键 `item_id + channel + 触发时刻取整`），防止 worker 重试导致轰炸。
- 站内提醒写现有 `notifications` 表（`type=calendar.reminder`，`href` 指向 `/w/:ws/calendar?date=...&item=...`）；邮件走现有 `mail.send`，受邮件限速约束。
- 服务器停机错过的提醒：重启后只补发**过去 2 小时内**的，更早的直接 `skipped`，并在铃铛里合并成一条「有 N 条提醒已过期」。补发一整天的历史提醒是灾难。
- **Web Push**（`channel=push`）：浏览器订阅制，一人多设备。发送**不经任何第三方服务**——自托管实例自己签 VAPID、自己加密载荷，直连浏览器厂商的推送网关（§5.7）。实例没配 VAPID 时前端不显示这个渠道，已存的 push 提醒降级成站内。
- 推送载荷只放标题与时刻，**不放正文**：内容虽是端到端加密的，但通知会显示在锁屏上。

### 4.6 ICS

- **订阅（入）**：只读。每工作区最多 5 个订阅，最小同步间隔 30 分钟，用 ETag / Last-Modified 条件请求。订阅内容不可编辑、不可勾选、不写回。URL 只允许 http/https，禁止内网地址与重定向到内网（SSRF：解析后校验 IP 不在私有段）。
- **导出（出）**：`/api/v1/calendar/feed/:token.ics`，token 32 字节不可枚举、可吊销、可轮换，语义与 `share_links` 一致。默认 `scope=mine`。导出内容**不含笔记正文**，只含标题、时间与指向本实例的链接。
- 导出地址是对外泄露面：创建时明确提示「知道这个地址的人可以看到你的日程标题」，并在 `/shares` 页一并管理与吊销。

### 4.7 配额与限速

单工作区 `calendar_items` 上限 5 万条（超出拒绝写并提示清理）；快速添加限速 30 次 / 分钟；ICS 同步连续失败 5 次自动停用订阅并通知创建者。批量操作单次 200 条、10 次 / 分钟；AI 提取待办 10 次 / 分钟；Web Push 订阅每人最多 10 个端点。

### 4.8 去年今日与回顾

两者都是**只读的回看**，不产生任何写操作，也不发通知——一旦它们会推送，就变成了新的打扰源。

- **去年今日**：今天页的一段。取往年同一月日（默认回看 5 年）在本工作区创建的笔记，以及那天的日历条目。按年倒序分组，每年最多 5 条。2 月 29 日在平年落到 2 月 28 日。
- **回顾**：按周，入口在今天页顶部。给四个数：完成的任务数、动过的笔记数、日程占用时长合计、逾期未清条数；外加「完成最多的那天」与按笔记本的分布。
- 统计只算**调用者可见**的条目，所以同一周两个人看到的回顾可以不一样——这是对的，回顾是个人的。
- 不做同比 / 环比，不给评分。知识库不是打卡机。

## 5. 算法

### 5.1 笔记任务解析与块锚

**识别**：Markdown 任务列表行 `- [ ]` / `- [x]`（含嵌套）。在任务行内识别严格语法：

| 语法 | 含义 |
|---|---|
| `@2026-08-20` / `@2026-08-20 15:00` | 到期时刻 |
| `@2026-08-20 15:00-16:00` | 起止（按日程渲染，但仍可勾选） |
| `!高` / `!中` / `!低` | 优先级 |
| `~每周五` / `~FREQ=WEEKLY;BYDAY=FR` | 重复 |
| `+@handle` | 指派（团队工作区） |
| `^tk-a1b2c3d4` | 块锚（系统写入） |

代码块、行内代码、引用块内的任务行**不解析**（与 03「代码块内的 `[[` 不当链接」同一条原则）。

**锚定**：首次解析出一条任务时，生成 8 位块锚并**回写到该行末尾**，同时写 `calendar_items.source_anchor`。之后无论用户改文案、改缩进、上下移动行，靠锚都能找回。

```
- [ ] 交周报 @2026-08-20 15:00 !高 ^tk-a1b2c3d4
```

回写会动正文，因此给笔记本一个开关「不写块锚」。关掉时降级为 `(行内容归一化后的 hash, 行号)` 模糊匹配：先按 hash 找，找不到则在 ±5 行内找最相似的一行（相似度阈值 0.8），再找不到就置 `detached`。**默认开启写锚**——稳定性比正文洁癖重要，且锚的形态与 Obsidian 一致，导出后仍是合法 Markdown。

**解析时机**：在现有 `note.reparse` 之后新增 `note.tasks` job（按 note_id 串行，与双链重解析同队列语义）。做**差量**：新增插入、消失标 `detached`、内容变更更新，**不整表删重建**（否则 `done_at`、提醒、指派全丢）。

### 5.2 展开重复

```
输入：workspace, 窗口 [from, to], layers, actor
1. 取窗口内的非重复条目：starts_at / due_at 落在窗口内
2. 取所有 rrule 非空且 (rrule_until 为空 或 >= from) 的条目
3. 对每条按当地时区展开 rrule 到窗口内，上限 500
4. 用 calendar_overrides 覆盖：cancelled 剔除、moved 改时刻、done 标完成
5. 合并两部分，按 ACL 过滤（source=note 的先过 can_read_note）
6. 按 starts_at 排序返回；每个虚拟实例带 (item_id, occurrence_start) 复合标识
```

前端拿到的每个实例都带 `occurrence_start`，写操作必须带回，服务端才知道改的是哪一次。

### 5.3 勾选回写

```
用户在日历勾选 task(source=note)
1. 乐观置 done，UI 立即变
2. POST /calendar/items/:id/complete { occurrenceStart? }
3. 服务端：查笔记 → 按 source_anchor 定位行 → [ ] 改 [x]
4. 找不到锚：置 link_state=detached，条目仍标 done，返回 warning
5. 命中：按 §4.3 合并版本写入，enqueue note.index / note.embed
6. 写 audit_logs(action=calendar.task.complete)
7. 失败：返回错误，前端回滚勾选并给「重试」
```

反向（在编辑器里勾选）：正常保存 → `note.tasks` job → 条目状态跟着变；日历页开着时靠现有通知 / 轮询刷新。

### 5.4 提醒调度

不引新组件，复用 `background_jobs.run_after`：

```
条目创建 / 改期 → 计算每个 reminder 的绝对触发时刻
  → upsert background_jobs(type='calendar.reminder', run_after=触发时刻,
                           payload={reminderId, itemId, occurrenceStart})
  → reminders.status = scheduled
worker 到点执行：
  1. 重新校验条目仍存在、未完成、时间未变（变了则 skipped，新 job 已入队）
  2. 去重键命中则 skipped
  3. 写 notifications；channel=email 再 enqueue mail.send
  4. reminders.status = fired
```

重复条目不预生成所有提醒：只为「下一个未来实例」排一条，触发后再排下一条。否则一条「每天 9 点」会往 jobs 表里灌几千行。

### 5.5 ICS 同步

`calendar.ics_sync` job，每订阅串行：条件请求 → 未变则只更新 `last_sync_at` → 变了则解析 VEVENT，按 `UID` upsert，本地已消失的 UID 标删除。解析失败不清空既有数据，只记 `last_error`。

### 5.6 并发与冲突

日历项不做笔记那种 `expected_version` 强冲突（粒度太小，体验太重），改用 `updated_at` 弱校验：请求带 `ifUnmodifiedSince`，服务端发现已被他人改过则返回 409 + 最新对象，前端出「这条刚被 XX 改过」并给「用我的 / 用他的」，不静默覆盖。

### 5.7 Web Push 的加密与失效

自实现，不引第三方库、不经第三方服务（与 ICS、zip、备份加密同一条路子）：

1. **VAPID**：实例首次开启推送时生成一对 P-256 密钥，公钥明文存 `instance_settings`，私钥走 `secrets.seal`。每次发送签一个 ES256 JWT（`aud` = 推送端点的 origin，`exp` ≤ 12 小时，`sub` = 实例的 `mailto:`），放进 `Authorization: vapid t=<jwt>, k=<公钥>`。
2. **载荷加密**（RFC 8291 `aes128gcm`）：临时生成一对 P-256 密钥与 16 字节 salt → 与订阅的 `p256dh` 做 ECDH → 以 `auth` 为 salt 的 HKDF 导出 IKM（info `WebPush: info\0 <客户端公钥> <服务端公钥>`）→ 再导出 CEK（16B，info `Content-Encoding: aes128gcm\0`）与 nonce（12B，info `Content-Encoding: nonce\0`）→ 明文补 `0x02` 分隔符后 AES-128-GCM → 前面拼 salt(16) + rs(4) + idlen(1) + 服务端公钥(65) 的头。
3. **失效**：端点返回 404 / 410 即 `status=gone`，立刻停用、不重试。其余错误累计 `fail_count`，连续 5 次停用并在铃铛里提示「某台设备的推送已停」。
4. 一条提醒发多台设备：**任一台成功即算 `fired`**，不因为其中一台掉线而整条重发。

| 工具 | 档位 | 说明 |
|---|---|---|
| `list_tasks` | 读 | 按窗口 / 状态 / 指派人列任务，返回来源笔记链接 |
| `list_events` | 读 | 同上，日程 |
| `create_task` | 写 | 只能建 `source=mcp` 的独立任务，**不允许直接改笔记正文** |

### 6.4 AI（[10](./10-AI与ai_index.md)）

- 问答语料加入「用户可见的未来 14 天日程 + 未完成任务」，让「我这周要做什么」「上次跟销售对齐是什么时候」可答。
- 受 `ai_index` 约束：来源笔记 `ai_index=false` 的任务不进 AI 上下文。
- **从纪要提取待办**：入口在日历面板与笔记页。服务端把正文交给模型，要求只输出 JSON 数组；**接口只返回候选，一条都不写库**。前端逐条勾选、可就地改标题与时间，确认后才走批量创建（`source=ai`）。
  - 受 `can_read_note` 与 AI 三开关约束。`ai_index=false` 的笔记同样能用——这是用户对着自己打开的那篇主动发起的，不是检索——但仍受工作区 AI 总开关。
  - 已经是任务行（`- [ ]`）的不重复提取；已从这篇笔记同步过来的任务按标题去重。
  - 模型抽风时**宁可少给**：解析不出 JSON 就报「没能提取出待办」，不做正则兜底猜测。
  - 正文按 [10](./10-AI与ai_index.md) 的防注入约定包裹，笔记里写「忽略以上指令」不生效。

## 7. 分期与验收

### 7.1 分期

| 期 | 内容 | 判断标准 |
|---|---|---|
| **P0** | 数据模型 + 月/周/日/议程四视图 + 笔记任务双向同步（含块锚）+ 收件箱 + 拖拽改期 + 撤销 + 站内提醒 + 时区 + 日记入口 + 键盘 | 一个人能用日历管完自己的一周，且笔记与日历永不打架 |
| **P1** | 重复规则与例外 + 邮件提醒 + ICS 订阅与导出 + 指派与团队视图 + MCP 四个工具 | 能替掉系统日历的一部分；AI 能回答日程问题 |
| **P2** | Web Push + 去年今日 / 回顾 + AI 从纪要提取待办（人确认）+ 批量操作 + 日历模板 | 加分项，不影响主线 |

### 7.1.1 落地进度
