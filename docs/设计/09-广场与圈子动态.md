# 09 广场与圈子动态

## 1. 范围

管：Post 双时间线、发帖编辑删除、点赞、公开主页、摘发与转正、圈子公开到广场的泄漏检查。  
不管：关注推荐转发（不做）、评论细节（08）。

---

## 2. 对象与状态机

### 2.1 Post

| 字段 | 说明 |
|---|---|
| scope | `instance` / `workspace` |
| workspace_id | 圈子必填；广场空 |
| body_md | ≤ 5000 字，闭集 Markdown 的子集：无嵌入笔记展开，允许 `[[ ]]`、图、任务 |
| reply_to_id | 可空，一层回复当「评论式回复」也可只用 08 的 Comment。一期：**回复用 Comment，Post 不做盖楼转发。** `reply_to` 保留但不在 UI 暴露，减少两套楼。 |
| linked_note_ids[] | 解析自 `[[ ]]` 且 resolved 的 id |
| edited_at | |
| deleted_at | 软删 |
| like_count | |

### 2.2 Like

`(post_id, user_id)` 唯一。访客不能赞。

### 2.3 公开主页

`/u/{handle}`：未软删的广场帖 + 该用户作为创建者或 Admin 的、已发布文档站列表（只列站，不列私密本）。被封禁：主页 404。

## 3. 交互

### 3.1 `/` 广场

未登录只读。登录可在顶上发帖（图最多 9）。时间线倒序。关广场时：访客看「广场已关闭」；登录仍能进工作区。

发帖框不出现在笔记三栏里。顶栏「广场」进出。

登录后从广场点 Logo/「我的库」回个人工作区。

### 3.2 工作区 `/w/{id}/feed`

成员可见。Viewer 只读。Editor+ 可发。可关 `feed_enabled`。  
`[[私密笔记]]` 对成员按 04 库内渲染。

### 3.3 「发到动态」

笔记选区或整篇摘要 → 选广场或某圈子 → 预览将发出的文本（默认取选区，可改）→ 正文末尾带「来自笔记《标题》」。  
公开到广场时跑 5.1 泄漏检查。

### 3.4 「转正为笔记」

帖子菜单：选工作区（须 can_edit 某本）+ 笔记本 + 目录。新建笔记，正文=帖子 md + 文首引用原帖。`ai_index` 跟本默认。

### 3.5 圈子→广场

「公开到广场」= **复制**一条新的 instance Post，不是改 scope（避免圈子里消失）。复制前 5.1。私链变纯文本。

---

## 4. 业务规则

1. 实例可关广场；工作区可关圈子。已有帖保留，只是入口 404/隐藏。
2. 作者可编辑（标已编辑）、软删。实例管理员可藏广场帖。工作区 Admin 可藏圈子帖。
3. 动态默认不进笔记搜索、不进 AI 索引、不进 MCP，除非钥匙开了 `feed.*`（11）。
4. `#tag` 按搜索词处理：点标签 = 搜含该词的帖。无话题页。
5. handle 规则见 01。改 handle 主页旧址 30 天跳转。
6. 发广场：任何 `active` 用户。实例以后可加「需开通」，一期不加。
7. 图计入用户附件配额（06）。

## 5. 算法

### 5.1 公开泄漏检查

```
for each resolved [[link]] in body:
    if not publicly_visible(target):  # 04 的 5.4 同一函数
        mark leak
if leak and dest == square:
    UI 列出将被打成纯文本的标题
    用户确认后：这些 [[ ]] 写成普通标题文本再发布
圈子内发帖: 不检查，成员自己有 ACL
```

`publicly_visible` = 文档站已发布且该篇 published，**不包括**「仅有分享链接」（避免把 /p/token 间接暴露到广场）。

### 5.2 时间线

`ORDER BY created_at DESC LIMIT 20`。无算法推荐。被封禁用户的帖 `deleted_at` 或单独 `hidden_by_ban`，解封不自动恢复展示（规格：封禁隐藏；解封后是否恢复——**解封恢复展示**，更符合「停用账号」而不是「删除内容」）。在 12 对齐：封禁隐藏，解封恢复广场帖。
