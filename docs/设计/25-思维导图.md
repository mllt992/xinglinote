## 1. 范围

### 1.1 一句话

**笔记本下可以放两种「板」：思维导图和 draw.io 画板。都能关联笔记、有历史版本、删了进回收站、能被搜索和 MCP 读写。**

二期的原则（来自使用反馈）：不在乎体积，功能要齐全、体验要好。

### 1.2 思维导图

编辑器从 mind-elixir 换成 [simple-mind-map](https://github.com/wanglin2/mind-map)（MIT）：它自带 14 种结构、概要、关联线、外框、主题、小地图、搜索替换、演示模式、XMind 导入导出等插件，一期要补的东西大多能直接用，自己写的部分集中在界面和数据安全上。

- 编辑：加子节点（Tab）/ 同级（Enter）/ 上级（Shift+Tab）/ 删除、F2 或双击改字、拖动节点、多选（框选 / Ctrl+点击）、格式刷、撤销 / 重做（Ctrl+Z / Ctrl+Y / Ctrl+Shift+Z）
- 顶部工具栏 + 节点右键菜单 + 画布右键菜单（键盘可操作）；「快捷键」面板列出全部快捷键
- 结构：思维导图（两侧）、逻辑图（左 / 右）、组织结构图、目录组织图、时间轴 ×5、鱼骨图 ×4
- 主题：「跟随站点」（读取站点 CSS 变量，切换浅色 / 深色或站点主题时即时刷新）、经典，以及插件自带的浅色 / 深色主题
- 样式面板：节点填充 / 文字颜色、字号、粗体、斜体、形状、边框；整张图的连线风格、线宽、箭头、背景色
- 概要、关联线（可加文字）、外框、图标、标签、备注（悬停显示）、节点图片（上传前压缩）、超链接、关联笔记（`#note:` 站内跳转）
- 折叠 / 展开（按层级展开）、图内搜索与替换、小地图（可拖动定位）、适应画布、回到中心、缩放百分比、全屏、演示模式
- 大纲视图：右侧可编辑的 Markdown 大纲，与导图双向同步；同名节点保留原有样式、图片、备注等
- 导入：Markdown 大纲、XMind（.xmind）、OPML、FreeMind（.mm）、JSON（本站导出 / simple-mind-map .smm / 一期格式）；可「新建为导图」也可「替换当前导图」
- 导出：PNG、SVG、PDF、Markdown、XMind、OPML、JSON
- AI：从笔记生成（一期）、按一句话描述生成、选中节点「AI 展开」（先预览，勾选后再插入）

### 1.3 画板（draw.io）

- 新建时选「画板」；编辑器是嵌入的 draw.io（`proto=json` 协议），跟随浅色 / 深色、中文界面，只读成员看到的是无工具栏的查看模式
- 自动保存到服务端，版本历史与导图共用
- 导出 PNG / SVG（由 draw.io 渲染）和 `.drawio` 源文件；全屏
- 「关联笔记」侧栏：画板级别关联多篇笔记，笔记右栏同样列出
- AI 对话（参考 next-ai-draw-io）：用自然语言让 AI 新画或修改当前图，AI 返回完整的 mxGraph XML，前端载入；侧栏有「撤回 AI 修改」栈
- 编辑器来源由 `DRAWIO_URL` 决定，默认 `https://embed.diagrams.net`，可自建 `jgraph/drawio`，`off` 关闭（见[部署](../部署.md)）

### 1.4 公共能力

- 列表页：按类型筛选（全部 / 思维导图 / 画板）、按标题过滤、按笔记本分组；改名、复制、移动到其他笔记本、删除
- 历史版本：列表 + 预览（导图为缩略渲染，画板为文字摘要）+ 恢复；恢复前的内容本身也会留一版
- 回收站：删除进回收站（「思维导图与画板」分组），可恢复、可彻底删除，30 天后由 worker 清理
- 全站搜索、快速打开（Ctrl+K）里出现导图 / 画板结果
- MCP 工具：`list_mind_maps` / `get_mind_map` / `create_mind_map` / `update_mind_map` / `trash_mind_map`

### 1.5 仍然不做

实时多人协同（同一张图两人同时编辑时靠版本号冲突提示）、分享 / 发布到文档站、富文本节点（见 §2.2）、导图数据计入存储配额。

## 2. 数据

### 2.1 形状

| kind | data |
|---|---|
| `mindmap` | `{ format: 2, layout, root, theme: { template, config } }`，节点是 simple-mind-map 的 `{ data, children }` |
| `drawio` | `{ format: "drawio", xml, noteIds }`，`xml` 是 draw.io 的 mxfile / mxGraphModel |

一期数据（`{ nodeData, direction }`）读到时由 `@kb/shared` 自动转换；`push.ts` 的 `backfillBoards` 会一次性把库里的一期导图转成新格式，并补 `search_text`、写一条 `source="migrate"` 的历史版本。重复执行时已转换的跳过。

### 2.2 清洗（`sanitizeMindMap` / `sanitizeDrawio`）

导图会在同笔记本其他成员的浏览器里渲染，库里有几处会走 innerHTML / 拼 SVG，所以入库前一律白名单：

- 丢弃 `richText`（库的富文本模式用 innerHTML）及其他运行时字段；节点文字一律纯文本
- 样式键只收白名单，值拒绝 `< > ; { }`、`url(`、`expression(`、`javascript:`
- `hyperlink` 只收 http(s) 与 `#note:<uuid>`；`hyperlinkTitle`、关联线文字去掉 `<>&"'`
- 图片只收 `data:image/(png|jpeg|gif|webp);base64`
- 重复或非法的节点 uid 静默重新生成（导入别处的文件常见）
- 前端粘贴 simple-mind-map 剪贴板数据时同样走清洗；备注悬停框由 React 渲染
- 上限：5000 节点、深度 50、单节点文字 2000 字、备注 2 万字、单图 1.5 MB（data URL）、整图 12 MB
- 画板：XML 必须以 `<mxfile` / `<mxGraphModel` 开头、不超过 8 MB；它只在 draw.io 的 iframe（另一个源）里渲染，本站页面从不把它当 HTML 插入

### 2.3 表

| 表 | 说明 |
|---|---|
| `mind_maps` | id, notebook_id, **kind**, title, data, **search_text**, version, created_by, updated_by, created_at, updated_at, **trashed_at, trashed_by** |
| `mind_map_versions` | mind_map_id, version, title, data, editor_id, source（edit / restore / import / ai / migrate …）。同一人 5 分钟内的连续编辑合并为一版；恢复、导入、AI 修改总是单独成版。保留最近 100 版，更早的按天保留 90 天 |
| `mind_map_note_links` | 派生表，保存时按 data 重建。导图取节点上的 `#note:`，画板取 `noteIds`（`node_id` 为空） |

## 3. 权限

完全跟随所属笔记本（`notebookAccess`）：能读笔记本就能看，能编辑笔记本才能新建 / 保存 / 改名 / 删除 / 恢复版本 / 用 AI。回收站里的恢复与彻底删除：查看者不行；编辑者只能处理自己删的；管理员可以处理全部。笔记本在回收站里时导图随之不可访问。搜索、笔记右栏、MCP 只返回当前用户读得到的。

## 4. 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/workspaces/:id/mindmaps` | 可见笔记本与导图 / 画板列表，附 `drawioEnabled` |
| POST | `/api/v1/notebooks/:id/mindmaps` | `{title, kind?, data?, source?}` 新建（`source=import` 用于导入） |
| POST | `/api/v1/notebooks/:id/mindmaps/ai` | `{prompt}` 按描述用 AI 生成导图 |
| GET | `/api/v1/mindmaps/:id` | 内容 + 所属笔记本 + canEdit + `drawioUrl` |
| PATCH | `/api/v1/mindmaps/:id` | `{expectedVersion, title?, data?, notebookId?, source?: edit \| import \| ai}`（移动笔记本只能在同一工作区内）；版本不符返回 `CONFLICT_VERSION` |
| DELETE | `/api/v1/mindmaps/:id` | 移到回收站 |
| POST | `/api/v1/mindmaps/:id/duplicate` | 复制一份 |
| GET | `/api/v1/mindmaps/:id/versions`、`/versions/:version` | 历史版本列表 / 单版内容 |
| POST | `/api/v1/mindmaps/:id/versions/:version/restore` | 恢复到该版本 |
| POST / DELETE | `/api/v1/trash/mindmap/:id/restore`、`/api/v1/trash/mindmap/:id` | 从回收站恢复 / 彻底删除 |
| GET | `/api/v1/mindmaps/:id/outline` | Markdown 大纲 |
| POST | `/api/v1/mindmaps/:id/ai/expand` | `{path, existing, count?, instruction?}` → `{items}` 子节点建议（不直接写库，前端预览勾选后插入） |
| POST | `/api/v1/mindmaps/:id/ai/drawio` | `{messages, xml}` → `{xml, reply}`，画板 AI 对话 |
| GET / POST | `/api/v1/notes/:id/mindmaps` | 引用该笔记的导图 / 画板；从笔记生成（`mode: outline \| ai`） |

`GET /api/v1/search` 额外返回 `mindMaps`（按标题、节点文字、备注匹配）；只想要笔记的调用方传 `boards=0`。`GET /api/v1/trash` 返回 `mindMaps`。

AI 全部复用现有服务商与开关（实例 + 工作区都要开启），未配置时返回 `AI_NOT_CONFIGURED`；用量分别记为 `mindmap:generate` / `mindmap:prompt` / `mindmap:expand` / `drawio:chat`。

## 5. MCP

遵循现有省 token 约定：`list_mind_maps` 只回元数据和一行摘要；`get_mind_map` 默认回 Markdown 大纲（`format=json` 才回完整数据，画板回 XML）；`update_mind_map` 传整份 `outline_md`（同名节点保留样式）或 `xml`，必须带 `expected_version`；写操作支持 `client_request_id` 幂等重试；`trash_mind_map` 只是移入回收站。

## 6. 备份

实例 / 工作区备份包含 `mind_maps`（含 kind、回收站状态）与 `mind_map_versions`；恢复时换新 id，把导图里的 `#note:` 链接和画板的 `noteIds` 映射到恢复后的笔记 id，再重建 `mind_map_note_links`。老备份包缺这些字段时按一期数据 / 无历史处理。

## 7. 安全备注

- CSP 的 `frame-src` 只放行 `'self'` 与 `DRAWIO_URL` 的来源；前端只接受来自该来源、且 `source` 是自己 iframe 的 postMessage
- iframe 使用 `referrerPolicy=no-referrer`，画板内容不经过本站以外的服务器存储
