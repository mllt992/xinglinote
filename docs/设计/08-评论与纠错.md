# 08 评论与纠错

## 1. 范围

管：挂载在分享页 / 文档站 / 动态上的评论；文档与分享上的纠错；待审队列；接受打补丁。  
不管：笔记正文里的行内批注（不做）。

---

## 2. 对象与状态机

### 2.1 Comment

| 字段 | 说明 |
|---|---|
| target_type | `post` / `note` / `heading` |
| target_id | |
| share_id / site_notebook_id | 来源通道，便于权限 |
| parent_id | 只允许一层：parent 必须是根评 |
| author_user_id | 登录用户 |
| guest_name / guest_email | 访客 |
| body | ≤ 2000 字，纯文本；允许自动链接 URL |
| status | `visible` / `pending` / `rejected` / `hidden` |
| created_at, edited_at | |

```
登录用户: 创建即 visible
访客: pending → visible | rejected
作者/管理: visible ⇄ hidden
作者 5 分钟内: 可改 body，记 edited_at
之后: 只能 hidden，不能改
```

`hidden` 是软删，不是收起评论区。作者本人和版主在楼里仍能看见已隐藏的评论（标「已隐藏」），可以取消隐藏。其他人当它不存在。公开计数只算 `visible`。

### 2.2 Correction

| 字段 | 说明 |
|---|---|
| note_id, heading_anchor? | |
| original_excerpt | 提交时的原文片段 |
| original_hash | 规范化后哈希，用于过期判定 |
| suggested | 建议替换成 |
| comment | 说明 |
| author 同评论 | |
| status | `pending` / `accepted` / `rejected` / `stale` |

**所有人提交都是 pending**（含登录用户）。

## 3. 交互

### 3.1 阅读页底栏

评论列表（只显示 visible）+ 发表框。未登录且允许访客：昵称、邮箱、验证码。  
关闭了评论或关了访客：相应藏入口。

纠错：选中一段文字出现「建议修改」。弹出原文只读、建议框、说明。提交后提示「等待作者审核」。

### 3.2 待审（笔记编辑者 / 站 Admin）

工作区设置「互动」：待审评论、待审纠错。可从公开页登录后的顶栏进。  
评论：通过 / 拒绝。纠错：并排原文与建议，接受 / 拒绝（理由）/ 标过期。

### 3.3 动态下的评论

广场 / 圈子卡片点「评论」展开评论区。登录用户直发 `visible`；广场访客走昵称 + 验证码，先 `pending`。圈子帖只有成员看得到，所以没有访客通道。

展开状态记在本页会话里，刷新不丢；通知链到 `/posts/{id}` 或 `/w/{id}/feed/{postId}`，旧的 `?post=` 会跳到详情页。折叠时若有评论，卡片下留一行「查看 N 条评论」，避免看起来像评论消失了。点评论按钮再次收起——收起是折叠整楼，不是把某条评论藏起来。已展开的楼会定时合并新回复。

「对所有人隐藏」放在评论的「更多」里，二次确认。不要做成卡片右上角的关闭钮，免得被当成收起。隐藏后作者 / 版主仍看得到，可取消隐藏。

谁审：广场 = 帖作者 + 实例管理员；圈子 = 帖作者 + 该工作区 Owner/Admin。作者在自己的帖下能看见待审评论，就地通过 / 拒绝。别人只看见 `visible`。

正文里 @ 了智能体：发表成功后 toast 说明「已叫到 @handle」；该楼立刻出现「正在回复…」占位，每几秒重拉本帖评论，直到回复落地或任务失败。失败不塞假回复，占位改成「这次没回上」。细则见 [20](./20-智能体.md)。

### 3.4 通知（最小）

一期站内信即可：你的篇有新待审；你的纠错被接受/拒绝。邮件可选。规格把通道留给架构，但**必须有收件箱入口**，否则队列无人知道。入口放顶栏铃铛。

## 4. 业务规则

1. 谁能审评论：`can_edit` 该笔记；圈子帖=工作区 Admin/Owner + 帖作者；广场帖=作者 + 实例管理员。
2. 谁能接受纠错：`can_edit_note`。
3. 访客验证码失败不建记录。同一 IP 10 分钟最多 5 条待审。  
   一期验证码 = 服务端签发的一道加法题（`GET /public/captcha` 返回题面与 HMAC 签名的 token，10 分钟过期），不落库、不引第三方。
4. 登录用户对同一 target 1 分钟最多 10 条评论。
5. 纠错 `original_excerpt` 必须能在当前正文找到；找不到当场拒绝提交。
6. 接受时再找一次：找不到或 hash 变了 → 标 `stale`，不写库。
7. 接受 = 普通保存算法，`source=correction`，expected_version 用当前版；409 则标 stale 请刷新再审。
8. 替换范围 = 第一次出现的 excerpt（若多次出现，提交时应用周围 20 字上下文；仍多则要求用户多选一点）。
9. 文档站关纠错则分享页仍按分享自己的 `corrections_enabled`。
10. 注销用户：visible 评论作者显示「已注销用户」，body 保留。pending 访客评保留待审。

## 5. 算法

### 5.1 打补丁

```
body = note.body
idx = find_unique(body, excerpt_with_context)
if idx < 0: mark stale; return
new_body = body[:idx] + suggested + body[idx+len(excerpt):]
save(note, new_body, expected_version, source=correction)
status = accepted
```

不跑复杂 diff3，避免误改。

### 5.2 过期检测（打开待审时也可批量）

```
if hash(current_excerpt_context) != original_hash: stale
```
