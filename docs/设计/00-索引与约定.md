## 2. 统一术语

| 术语 | 含义 |
|---|---|
| 实例 Instance | 一次自托管部署 |
| 工作区 Workspace | 权限与笔记本的容器。分个人工作区、普通工作区 |
| 笔记本 Notebook | 一棵目录树的根 |
| 目录 Folder | 树节点，可空 |
| 笔记 Note | 一篇 Markdown + frontmatter + 附件 |
| 稳定 ID | 笔记 UUID，分享 / 双链索引 / MCP 都绑它 |
| 三开关 | ACL 可见性、`published`、`ai_index` |
| 分享链接 ShareLink | 对外只读通道，与文档站生命周期独立 |
| 文档站 Site | 某笔记本的实时只读投影 |
| 广场 / 圈子 | `Post.scope = instance \| workspace` |
| 钥匙 Token | 绑定「用户 + 一个工作区」的 MCP 凭证 |
| 跟随权限 / 指定笔记本 | 钥匙的两种笔记本范围 |

## 3. ID 与路径约定

| 对象 | ID | 对外标识 |
|---|---|---|
| User | UUID | `handle`：`^[a-z][a-z0-9_]{2,31}$`，全局唯一 |
| Workspace | UUID | `slug` 实例内唯一，可改，旧 slug 30 天重定向 |
| Notebook | UUID | 工作区内 `slug` |
| Folder / Note | UUID | 工作区内逻辑路径 `笔记本slug/目录/标题`，仅展示与导出 |
| ShareLink | 不可枚举的 32 字节 url-safe 随机串 | `/p/{token}` |
| McpToken | UUID + 独立 secret | secret 只创建时显示一次 |
| Post / Comment / Correction | UUID | — |

笔记源文件建议落盘：

```
data/workspaces/{workspace_id}/notes/{notebook_id}/{note_id}.md
data/workspaces/{workspace_id}/files/{note_id}/{filename}
```

目录树、标题、排序只存在数据库。这样改名 / 移动不必改文件名，双链回写只改 md 正文里的 `[[标题]]`。导出 zip 时再按「笔记本/目录/标题.md」生成给人看的树。

## 4. 领域事件（跨模块唯一合同）

实现可用队列或进程内总线，但事件名与载荷必须稳定。订阅关系写在各文档「关联」节。

| 事件 | 关键载荷 | 主要订阅方 |
|---|---|---|
| `UserRegistered` | userId, isFirstUser | 工作区（建个人区）、实例（授管理员） |
| `UserBanned` / `UserUnbanned` | userId | 会话、MCP、广场 |
| `UserDeletionRequested` | userId, graceUntil | 工作区、评论、广场、MCP |
| `WorkspaceMemberAdded` / `Removed` | workspaceId, userId, role | ACL 缓存、MCP 范围、邀请 |
| `NotebookAclChanged` | notebookId | 搜索可见性、MCP、文档站导航 |
| `NoteUpserted` | noteId, change: content\|title\|path\|flags | 双链重解析、搜索/向量索引、文档站缓存 |
| `NoteTrashed` / `NoteRestored` / `NotePurged` | noteId | 双链状态、分享、文档站、索引 |
| `ShareRevoked` | shareId | 公开访问 |
| `SiteUnpublished` | notebookId | `/s/...` |
| `CorrectionAccepted` | correctionId, noteId | 笔记版本、文档站 |
| `McpTokenRevoked` | tokenId | MCP 鉴权缓存 |

## 5. 权限判定的统一入口

所有人机界面、分享页、MCP、AI 检索，必须调用同一套函数，禁止各写各的 if。

```
can_read_note(actor, note) -> bool
can_edit_note(actor, note) -> bool
can_ai_read_note(actor, note, token?) -> bool
can_publish_notebook(actor, notebook) -> bool
can_create_share(actor, target) -> bool
```

`actor` 可以是：登录用户、访客、MCP 钥匙（内含 user + workspace + 减权）。  
算法细节见 [02](./02-工作区成员与ACL.md) 与 [11](./11-MCP.md)。

## 6. 错误码（跨 API / MCP 共用）

| 码 | HTTP | 含义 |
|---|---|---|
| `UNAUTHENTICATED` | 401 | 未登录或钥匙无效 |
| `FORBIDDEN` | 403 | 已认证但 ACL / 钥匙不够 |
| `NOT_FOUND` | 404 | 不存在，或无权且需隐藏存在性的对象（分享、私密笔记对外） |
| `EXISTS_INVISIBLE` | 403 | 双链/嵌入：对象存在但当前 actor 不可见 |
| `CONFLICT_VERSION` | 409 | `expected_version` 不匹配 |
| `GONE_TRASHED` | 410 | 在回收站 |
| `EXPIRED` | 410 | 分享过期、纠错过期、钥匙过期 |
| `QUOTA` | 413 | 附件或字数超限 |
| `VALIDATION` | 422 | 参数/Markdown/重名 |
| `RATE_LIMIT` | 429 | 注册、评论、MCP、AI |

对外分享与文档站对「无权 / 不存在 / 已删」一律回同一套文案「内容不存在或已失效」，避免侧信道。

## 7. 写作约定

每篇设计文档固定六节（可增不可缺）：

1. **范围**
2. **对象与状态机**
3. **交互**
4. **业务规则**
5. **算法**
6. **与其他功能的关联**

涉及「存在性泄露」的，必须写清对外文案。涉及写库的，必须写清版本与审计。
