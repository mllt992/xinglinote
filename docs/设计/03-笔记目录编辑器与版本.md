# 03 笔记、目录、编辑器与版本

## 1. 范围

管：三栏交互、笔记本/目录/笔记 CRUD、排序、重名、frontmatter、Markdown 闭集、自动保存、版本、冲突、在场、标签/收藏/最近。  
不管：双链解析（04）、附件二进制（06）、回收站销毁（12）。

## 2. 对象与状态机

### 2.1 Notebook

| 字段 | 说明 |
|---|---|
| title, slug | 工作区内 slug 唯一 |
| visibility / default_ai_index | 默认 `open` / `true` |
| sort_key | 侧栏顺序 |
| site_* | 文档站配置，见 07 |
| created_by | 私有本归属 |

### 2.2 Folder

| 字段 | 说明 |
|---|---|
| id, notebook_id, parent_id | parent 空 = 本根下 |
| title | 同父目录下唯一（大小写不敏感） |
| sort_key | |

空目录必须可查询、可显示。

### 2.3 Note

| 字段 | 说明 |
|---|---|
| id | 稳定 UUID，永不改 |
| notebook_id, folder_id | folder 空 = 本根 |
| title | 同目录下唯一（大小写不敏感） |
| aliases[] | 双链别名 |
| body_md | 不含 frontmatter 的正文，或含，二选一；建议库内分离 |
| published | 默认 false |
| ai_index | 创建时 = 当时笔记本 `default_ai_index`（默认 true） |
| version | 单调递增整数，从 1 |
| word_count / updated_by / updated_at | |
| trashed_at | 空 = 活着 |

frontmatter 写入文件时由系统生成，用户乱改 id 以库为准并在下次保存覆盖回去。

### 2.4 NoteVersion

`notes.version` 每次成功保存单调 +1。历史行记 version、editor、source（`ui`/`mcp`/`collab`/`task_toggle`/`ai`/`import`/`correction`/`restore`）、body 快照、title，以及可选的用户命名 `name`（和当时笔记标题无关，用来认出有意义的快照；空 = 没起名）。

**快照合并（与 16 §4.3、17 §3.4 同源）：** 同一篇、同一 `source`、5 分钟内、上一条的 version 等于本次写入前的 `notes.version`，则复用那条 `note_versions`，只更新正文 / 标题 / 时间 / 编辑者。`ui` / `mcp` / `task_toggle` 还要求同一编辑者；`collab` 不限人（房间里本来就是一处落库）。中间插进别的 source（MCP、恢复、纠错、AI 接受）立刻封版，下次另起一条。**该条已有非空 `name` 也立刻封版**——自动保存不得覆盖用户钉住的快照。

保留策略：最近 100 版全留；再往前每天留一版，留 90 天。用户命名的快照不参与裁剪。超出由 worker `prune_versions` 裁剪。合并是为了不让自动保存把抽屉淹掉，不是靠少保存来省空间。

### 2.5 保存状态（编辑器）

```
clean → dirty（本地已改）→ saving → clean
                         ↘ conflict（409）→ 用户选覆盖或重载
```

## 3. 交互

### 3.1 三栏

左：工作区切换、笔记本列表、一级项「已分享 / 日历 / 今天」、全局搜索入口、广场入口。  
中：当前笔记本的目录树、新建笔记/目录、拖拽。进「已分享」时换成收到列表或该通道只读树（[21](./21-收到的分享.md)）。  
中栏是一棵树：点目录展开或收起，其它笔记仍留在树上。点目录**不会**把中栏切成「只看这个目录」的扁平列表。  
右：标题、面包屑（工作区 / 本 / 路径）、状态芯片（已发布 / AI 可读 / 有分享）、源码|预览分屏、底栏保存状态与 version。进「已分享」时换成只读正文。  
右侧抽屉：反向链接、版本、AI。默认不打开。

不要把广场时间线、成员管理嵌进中栏。

**两处列表都能排序**，共用一套口径（`sortNotes`）：

| 列表 | 三档 | 偏好存在哪 | 默认 |
|---|---|---|---|
| 左栏的笔记本 | 创建时间 / 名称 / 自定义（拖） | `kb.workspace-notebook-sort`，按工作区 | 自定义 |
| 中栏的笔记 | 同上 | `kb.notebook-note-sort`，按笔记本 | 创建时间 |

- 笔记本默认「自定义」：侧栏是人自己摆出来的秩序，不该被创建时间冲掉；
  笔记默认「创建时间」，因为新写的那篇最该在手边。
- **自定义顺序是服务端状态**（`notebooks.sort_key` / `notes.sort_key` / `folders.sort_key`），
  一个人拖了所有人都跟着变；排序**模式**才是本机偏好。
- 拖笔记本改的是整个工作区的侧栏，所以只给管理员，和「谁能建、谁能删笔记本」同一条线；
  拖笔记、拖目录要的是这本的 `edit`。
- 中栏目录跟笔记共用同一个排序开关，但目录没有「创建时间」这一档：按创建时间排笔记时，
  目录仍按 `sort_key`；按名称排时目录跟笔记一起按名。拖目录到另一条的上 / 下边缘 = 改同级顺序，
  拖到中间 = 移入。右键「上移 / 下移」给不方便拖的人。
- 落库都是**整串重写 `sort_key`**，不做增量插值——插值省的那点写入换来的是
  「排久了 key 挤在一起要重排」的隐患。新建的排在最后（`nextSortKey`）。

#### 3.1.1 多标签与并列窗格

右栏是一个笔记工作台，不再只记住当前一篇：

- 打开笔记会加入标签；已有标签只取得焦点，不重复创建。标签可关闭、拖动排序，状态按工作区保存在本机。
- URL `/w/:wsId/n/:noteId` 始终表示**当前取得编辑焦点的笔记**，保证刷新、复制链接与前进后退仍可预测；
  标签和窗格布局不是服务端知识，不进备份、MCP 或分享。
- 取得焦点时，左栏笔记本与中栏目录树必须立刻跟随该笔记：先用标签保存的 `notebook_id` 切本，
  再以 `GET /notes/:id` 的结果校正；目录树展开到该笔记所在目录并高亮该笔记。
- 桌面端最多并列三篇。标签可拖到目标窗格来加入、替换或调整窗格顺序；相邻窗格分隔线可拖动并保存比例。
  窄屏只显示焦点窗格，标签切换仍可用，不把多个正文硬压进手机宽度。
- 同一时刻只有焦点窗格挂载可编辑 CodeMirror、自动保存计时器与协同房间；其他窗格显示同源 Markdown
  只读预览。点击其他窗格标题取得焦点后，该窗格升级为完整编辑器，原焦点降为预览。
- 切换焦点、关闭当前标签或离开页面，都沿用 §3.3 的切篇保存：先冲掉未到点的自动保存，再卸载编辑器。
  非焦点预览保留最后加载或最后编辑的内容，取得焦点时重新从服务端读取并做版本校验。
- 笔记被移到其他笔记本时更新标签的 `notebook_id`；移入回收站或失去读取权限时从标签和窗格移除，
  焦点落到相邻标签；没有标签则回到工作台空状态。

键盘与无障碍：标签使用 `tablist/tab` 语义；关闭按钮有笔记名；拖拽只是增强，加入/移出并列窗格必须同时有按钮入口。

### 3.2 新建

- `N` 或按钮：在当前目录新建「未命名」。若重名自动 `未命名 2`。
- 新建目录：允许空。
- 落点 = 当前选中的目录；选中笔记则用其所在目录。

### 3.3 编辑与保存

- 默认分屏：左源码右预览。可只源码。
- 本地停键 **1.5s** 自动保存（不要短于 1.5s、不要长于 2s）；失焦、切篇、关页 `beforeunload`、`Ctrl/⌘+S` 立即保存。
- 请求带 `expected_version`。成功返回新 version，正文以服务端为准（防时钟）。
- 409：停自动保存，禁止拿旧 version 连打。横幅「{他人} 刚保存了更新」。操作：加载对方版本（丢本地）、强制覆盖（再提交且 `force=true`，仍先把对方版推进历史）。409 必须带当前 `version`、`updatedBy`、`title`、`bodyMd`，前端才画得出横幅。
- 粘贴/拖图：见 06，成功后插入 `![](./files/{filename})`。
- **页内刷新**：编辑器工具条与命令面板各有一个「刷新这篇」。正文、反向链接、附件、目录树
  一起重新拉一遍，**不刷浏览器**——MCP、AI、别的设备、恢复历史版本都会绕过这个页面改正文，
  而整页刷新会连带丢掉侧栏折叠、滚动位置和刚打开的面板。
  - 还有没落库的改动时先问一声：刷新是用服务端那份盖掉本地的，盖掉找不回来。
  - 协同接管期间只换元数据，**不拿服务端快照去盖房里的正文**（设计 17 §3.4），
    否则会把别人刚敲的字冲掉。

### 3.4 移动 / 重命名

树拖拽或命令面板。拖笔记到目录上即改 `folder_id`；拖到「全部笔记」即回到本根。右键 / 命令面板「移动到目录…」是给不方便拖的人的替代操作。
拖目录到另一目录中间即改 parent；拖到上 / 下边缘即改同级 `sort_key`（必要时一并改 parent）。成环或超过深度上限的落点直接拒绝。

跨笔记本：右键 / 命令面板「移动到其他笔记本…」，或把笔记拖到左侧另一本笔记本上。须目标本 `can_edit`。没指定目录时落到目标本根上；目标目录已有同名笔记则拒绝。换本不改 note id，双链、分享链接、附件跟着走。跨工作区一期允许，等同导出再导入但保留 note id（须两端都有权）。

标题输入框改标题 = 重命名，触发双链回写（04）。

同目录重名：保存拒绝，输入框红字。

### 3.4.1 整本笔记本换工作区

侧栏右键或「笔记本操作」里的**移动到其他工作区**。整本连同目录、笔记（含回收站里的）、
附件、分享链接、日历上由它的笔记生成的任务一起走。

**权限两头都要 owner / admin**，不走「笔记本创建者」那条：搬走等于从一个工作区拿掉一整块内容、
再往另一个塞进一块，是两个工作区之间的事，不是一本笔记本内部的事。两端冻结都拦。

搬迁必须把所有带 `workspace_id` 的行一起改掉——笔记、目录、附件、分享、日历条目、向量块
各自存了一份，漏掉哪张表哪张表就变孤儿：搜索里搜不到、附件读不出来、回收站恢复出来落在别的区。

跟着一起处理的几件事：

| 项 | 处理 | 为什么 |
|---|---|---|
| 文档站地址 | `/s/{work区slug}/{s本slug}` 变化，旧地址失效；目标区已有同名 slug 时换新的 | `(workspace_id, slug)` 是唯一键，而每个工作区的第一本都叫 `inbox` |
| 分享链接 | 照旧可用，只改 `workspace_id` | 分享是按 token 认的，不认工作区 |
| 白名单成员 | 不是目标工作区成员的条目摘掉 | 白名单只能由本区成员组成（02） |
| 私密 / 指定成员本 | 创建者不在目标区就**拒绝搬** | 否则搬过去对谁都不可见，等于凭空消失 |
| AI 向量块 | 删掉重排队，由目标区自己的模型重建 | 向量是原区那套 embedding 算的，跨区比距离没有意义（10） |
| 双链 | 断开跨区的链接行，两边各自重解析（04） | 反向链接不做逐条鉴权，留着会跨区漏标题 |
| 原区圈子动态 | 挂着这些笔记的动态解除回链 | 动态列表不做鉴权直接显标题（09） |
| 原区 MCP 钥匙 | 白名单里摘掉这本 | 否则钥匙面板上留一本点不开的幽灵笔记本（11） |

落盘顺序是「先复制文件 → 再提交事务 → 最后删旧文件」。三步都不原子，这个顺序保证任何一步失败时
**库里指的路径上都有文件**：最多留下几个没人引用的副本，不会出现行已经指向新工作区、文件还在老目录。
走 `blob_store` 的附件本身按哈希寻址、不挂工作区目录，搬迁只改 `attachments.workspace_id`，不拷、不删物理文件。老路径 `attachments/{ws}/{uuid-name}` 仍按上面三步搬。

### 3.5 在场

打开一篇向服务器 heartbeat 20s。他人打开同篇时顶栏显示「张三在看」。**不锁**。

同时开着协同房间时，这一段升级成头像组 + 远端光标，口径见 [17 §3.4](./17-编辑器方案.md)。
心跳这条路照旧保留：它不依赖 WebSocket，协同连不上时在场仍然显示得出来。

### 3.6 版本抽屉

列表：自定义名字（没有则显示当时标题）、时间、来源。点开 diff（行级）。可改名字、可删除该条历史。恢复 = 把该版 body/title 存为新 version，不是删除中间历史。删除历史快照只去掉 `note_versions` 那一行，不动当前笔记。

### 3.7 标签 / 收藏 / 最近

- 标签属于工作区，笔记多对多。侧栏可筛。改名、合并一期做改名即可。
- 收藏、最近是用户级，不进 MCP、不进双链、不进备份的「知识」核心也可进备份。
- 最近：打开或保存写入，保留 50 条。

## 4. 业务规则

1. Markdown 闭集见规格 9.2。预览、文档站、分享页、MCP `get_note` 的渲染 HTML 必须同一套解析器。禁止用户 HTML。代码块内的 `[[` 不当链接。
2. 单篇 body ≤ 2MB。超限拒绝保存。
3. 删除走回收站，不在本篇做硬删。
4. `published` / `ai_index` 在文首开关或属性面板改，立刻保存并发 `NoteUpserted(flags)`。
5. 改 `default_ai_index` 只影响之后新建，弹确认说明这一点。
6. 预览数学用同一 KaTeX/等价库；失败显示源码不明文崩溃。
7. 任务列表勾选算一次保存。
8. Viewer 打开只读编辑器，无保存、无属性写。
9. frozen 工作区同只读。
10. 笔记本换工作区两端都要 owner / admin；私密 / 指定成员的本，创建者必须先是目标区成员（§3.4.1）。

## 5. 算法

### 5.1 同目录唯一标题

```
normalize(title) = unicode_nfkc + trim + collapse_space + casefold
unique among siblings where trashed_at is null
```

回收站里的同名不挡活着的标题。恢复时若撞名，见 12。

### 5.2 自动保存并发

```
on save(note, body, expected_version, force=false, source=ui):
  row = lock note
  if row.version != expected_version and not force:
      return CONFLICT_VERSION, server_body, server_version, last_editor
  if force and row.version != expected_version:
      insert version snapshot of current   # 对方的不会丢
  row.body = body
  row.version += 1
  if mergeable(last history, source, editor, 5min):
      update that history row to new version/body
  else:
      insert version (source)
  emit NoteUpserted
```

MCP `update_note` 禁止 `force`，只能 409 让 Agent 重读。Agent 必须用返回的 `current_version` 再 `get_note`，禁止自己 `+1` 猜下一版。

**协同房间是个例外**：房间落库时用 `force=true`，因为它自己就是这段时间里唯一的写者
（所有人的输入都先在 CRDT 里合过一遍了），不存在覆盖别人。反过来，MCP / AI 从外面改了正文，
房间会在下一次落库前把差异回灌进 CRDT——细节见 [17 §3.4](./17-编辑器方案.md)。

### 5.3 面包屑与树

树按 `parent_id` + `sort_key` + `title` 排。拖拽只改 parent 与 sort_key。深度一期上限 8。循环 parent 用更新前的祖先检查拒绝。

## 6. 与其他功能的关联

| 方向 | 关系 |
|---|---|
| ← 02 | 所有写前 `can_edit_note` |
| → 04 | 标题/正文/移动 触发重解析与回写 |
| → 05、10 | `NoteUpserted` 重建关键词与向量索引 |
| → 06 | 图与导入创建笔记走同一唯一标题算法 |
| → 07 | `published` 变化文档站即时见；进回收站投影消失 |
| → 08 | 纠错接受 = 一次 `source=correction` 的保存 |
| → 09 | 转正为笔记走创建；摘发读选区 |
| → 11 | MCP CRUD 复用本文保存算法 |
| → 12 | 删 = trash |

发出：`NoteUpserted`、`NoteMoved`（也可并入 Upserted 的 change=path）。
