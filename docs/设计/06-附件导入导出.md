# 06 附件、导入、导出

## 1. 范围

管：附件存储与限额、粘贴拖拽图、PDF 抽文本、md/zip/Obsidian/Notion/语雀迁移、docx/html 通用导入、单篇/整本/工作区导出。
不管：S3 主存储（二期）、印象笔记 ENEX/有道专用格式（二期）、备份打包（13 会复用导出器但不含密钥）。

---

## 2. 对象与状态机

### 2.1 Attachment

| 字段 | 说明 |
|---|---|
| id, note_id | 归属一篇笔记 |
| filename | 展示名，同笔记内唯一 |
| sha256, bytes, mime | 内容哈希用 **SHA256**（不用 MD5：有碰撞攻击） |
| stored_name | 指向 `blob_store.path`；老数据仍是 `attachments/{ws}/{uuid-name}` |
| extracted_text | PDF 成功才有 |
| extract_status | `none` / `ok` / `failed` / `pending` |

物理文件按内容寻址，实例内去重：

```
data/blobs/{sha256前两位}/{sha256}
```

`attachments` / `post_assets` 只是引用行，同一 sha256 多笔记、多动态共享一份。
正文引用仍走附件 id：`![](/api/v1/attachments/{id})` 或导入后的 `![[filename]]`。
导出 zip 再展开成「标题.附件/filename」，不把哈希路径暴露给用户。

### 2.2 限额（实例可配，默认见规格）

检查顺序：单文件 → 单篇 md 大小 → 用户合计 → 工作区合计。任一失败整次上传回滚。
用户合计的配额来源与申请 / 分配见 [22](./22-用户服务与配额.md)。

动态附件走 Post 自己的限额（合计最多 9 个：图 5MB / 视频 50MB / 其他文件 25MB），计入用户合计，不计入某篇笔记。细则见 [09 §2.2](./09-广场与圈子动态.md)。

## 3. 交互

### 3.1 上传

编辑器拖入/粘贴：立即上传当前篇，插入相对路径。失败 toast 原因（超限/类型）。
类型一期允许：常见图片、pdf、zip（仅导入入口）、txt、音频视频常见容器。可执行文件、html 带脚本拒绝。

### 3.2 导入向导

工作区或笔记本菜单「导入」：

1. 选目标笔记本（须 can_edit）+ 可选根目录
2. 上传 `.md` / `.markdown` / `.csv` / `.docx` / `.html` / `.htm` 或 `.zip`，也可粘贴 HTML；选择自动识别 / Notion / 语雀 / 通用来源
3. 预览将创建的树、重名策略（跳过 / 重命名加后缀 / 覆盖——覆盖走版本历史）
4. 确认后执行，完成后刷新目标本并展示逐项报告（成功 / 跳过 / 降级 / 失败）；报告保留原始路径以便定位重试

zip 识别：

- 有一堆 md + 相对资源：按相对路径建 Folder
- 含 `.obsidian`：忽略配置，只收 md 与附件；`[[wikilink]]` 原样进正文，导入后再全量重解析（04）

单 md 的 frontmatter `title` 优先，否则用文件名。外来 `id` **丢弃**，总是发新 UUID，避免和本库碰撞。

### 3.2.1 迁移格式与安全边界（#74）

- Notion：接受官方 Markdown & CSV 导出 ZIP；文件/目录尾部 32 位页面 ID 从展示标题和目录名去掉，保留真实层级、正文标题、待办、相对图片与附件。CSV 数据库落为 Markdown 表格，报告标明关系/公式/视图无法还原。链接能对应到本批页面时改为内部笔记链接；不能对应则保留或明确降级。
- 语雀：接受按知识库目录组织的 Markdown ZIP 或多文件；保留目录、正文和包内附件。不申请 API 权限、不联网拉取知识库。
- DOCX：转换标题、段落、列表、表格和内嵌图片；复杂排版/不支持元素给出降级提醒。HTML 文件/粘贴：先消毒再转 Markdown，删除脚本、事件属性、iframe、危险 URL；不执行页面、不下载任何远程图片（包括内网地址），远程图片保留普通链接并记降级。
- ZIP 仅接受 store/deflate，拒绝绝对路径、父级穿越、反斜杠穿越、加密、软链接、ZIP64、多卷与不支持压缩方式；解压前检查目录信息，解压时强制上限。每批最多 500 篇、2000 个包内条目、100 MB 解压总量，每个附件 25 MB、单篇正文 2 MB；超限或不可信包整体拒绝，不写库。
- 预览只解析与读取目标树，不创建笔记/目录/附件。确认重新核对输入计划；同名策略继续使用跳过/自动改名/覆盖（覆盖进版本历史），放入已有目录由目标文件夹选项控制。
- 每篇的正文、版本、目录和附件引用在同一数据库事务提交；失败篇回滚，其余成功篇保留。附件按 SHA256 写入 blob_store，计入实际引用者的用户配额；覆盖按正文差量计算配额，同篇同名同内容附件复用。存储或版本冲突应定位到原始路径，不能留下半篇或悬空附件引用。整批完成后重解析链接，使前向页面链接可识别。
- 验证使用标注为合成数据的官方导出布局样本（至少 50 页且含图片），不能冒充真实用户导出。真实样本验收需另有用户提供的脱敏导出包。

### 3.3 导出

- 笔记「更多」菜单提供三种带走方式：复制 Markdown 正文、复制解析后的富文本、导出这篇笔记
- 两种复制都只复制正文，不混入标题或系统 frontmatter；富文本与 App 预览共用解析、消毒链，同时写入 `text/html` 与纯文本降级
- 单篇：该 md（系统 frontmatter + 正文）+ 同目录附件 zip
- 整本 / 工作区：给人看的树 `笔记本/目录/标题.md`，附件按相对路径；**不含**他人 `!can_read` 的笔记；不含 MCP 钥匙、成员邮箱、分享 token 明文
- 进行中大导出后台任务，完成后限时下载

## 4. 业务规则

1. 笔记进回收站，附件跟着不可被分享直链下载；恢复后恢复。
2. 笔记硬销毁 / 附件过期清盘：对 `blob_store.refcount` 减一，到 0 再删物理文件。软删（进回收站、动态下架）不减引用，恢复后文件还在。同一篇里再传「同内容 + 同文件名」直接复用原行，不占新引用。
3. PDF 抽文本失败仍保留文件，搜索没有正文命中，AI 也只知道文件名。
4. 导入任务失败要可重试且不留下半棵不可见脏树：每篇沿用普通创建的 ACL / 配额 / 版本规则并在独立事务中写入，失败记日志与报告，已成功的保留。
5. 图片压缩一期不做。
6. 导出的 `[[标题]]` 保持源码，不把 ID 写进去。

## 5. 算法

### 5.1 文件名安全

```
basename, strip path
拒绝 .. \ /
NFKC
重名: name, name-1, name-2 + 保留扩展名
```

### 5.2 限额

```
if file.bytes > limit_file: QUOTA
if user_usage + bytes > limit_user: QUOTA
if ws_usage + bytes > limit_ws: QUOTA
```

并发用数据库原子增加 usage，失败回滚文件。

### 5.3 PDF 抽取

异步。文本截断到 200k 字进 extracted_text。完成后 `NoteUpserted` 以便搜索/向量更新。

### 5.4 Obsidian 导入后链接

导入批次结束后对该批 note_id 跑一遍保存重解析。此时标题已在 TitleIndex，消歧按 04。跨库同名可能变 unresolved，用户用补全修。不在导入期自动跨工作区乱绑。

### 转换资源与并发护栏

所有顶层 ZIP 与嵌套 DOCX 共用剩余解压字节和中央目录条目预算，在 inflate 前扣除。DOCX 的 XML 预检限制单个 2 MB、合计 8 MB、50000 个节点、128 层；图片回调串行读取，重复内容复用一份二进制资源，累计图片读取/编码工作量另受 100 MB 上限约束。HTML 不接受嵌套表格，超过结构/深度预算的文件在预览报告中明确失败，不进入递归转换。

逐篇事务持有锁时，配额与 blob 引用操作必须共用该事务连接；不得从全局连接池再借连接。数据库失败自动回滚引用，不对已经回滚的引用重复释放。失败后留在磁盘上的无引用哈希文件可被后续相同内容复用；不能为清理垃圾而冒险删除并发操作正在使用的物理文件。
