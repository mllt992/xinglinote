## 1. 范围

### 1.1 一句话

**项目是知识库的交付面，不是塞进来的第二个 Jira。**

日历回答「今天要干什么」，项目回答「这件事什么时候交、卡在哪、实际花了多久」。同一份工作可以同时出现在两边：日历管日期，项目管交付。项目里的任务**不回写笔记正文**，避免和设计 16 的块锚抢同一行。

### 1.2 和日历的边界

| | 日历（16） | 项目（本文） |
|---|---|---|
| 入口 | 左栏「日历 / 今天」 | 顶栏「项目」，在笔记后、广场前 |
| 对象 | 日程 + 笔记待办 | 有起止、估时、实耗、指派的交付任务 |
| 甘特 / 看板 | 一期明确不做 | 一等视图 |
| 用时 | 不记 | 计时器 + 手工补录 |
| 与笔记 | 正文 `- [ ]` 双向同步 | 可选挂一篇笔记，只作入口 |

### 1.3 一期做

- 工作区级项目：规划 / 进行 / 暂停 / 完成 / 归档
- 任务：待办列、优先级、估时、起止、指派、一层子任务、挂笔记
- 看板（拖列）、甘特（拖条改期）、计时、洞察
- 健康度：逾期、停滞、估时被打穿、临期进度不够
- 私有项目：仅创建者可见；其余成员看见工作区项目
- 跨工作区项目总览；创建时明确选择归属工作区；有权限时可把整个项目移动到其他工作区

### 1.4 一期不做

跨工作区项目组合（一个项目同时属于多个工作区）、关键路径自动排期、工时审批、对外客户门户、把项目任务写回笔记 `- [ ]`。

## 2. 对象

```
projects
  id, workspace_id
  title, description
  status          planning | active | paused | done | archived
  color           语义 token：ink | accent | good | warn | muted
  start_at, due_at
  visibility      workspace | private
  sort_key
  created_by, updated_by, created_at, updated_at
  archived_at

project_tasks
  id, project_id, workspace_id
  title, body_md
  status          backlog | todo | doing | review | done | cancelled
  priority        0 无 / 1 低 / 2 中 / 3 高
  start_at, due_at
  estimate_min
  assignee_user_id
  parent_id                 -- 只允许一层
  sort_key
  source_note_id
  created_by, updated_by, created_at, updated_at
  completed_at, completed_by

project_time_entries
  id, project_id, task_id, user_id
  started_at
  ended_at                  -- 空 = 正在跑
  seconds
  note
  created_at

project_milestones
  id, project_id
  title, due_at
  done
  sort_key
```

约束：

1. 每区最多 200 个未归档项目；每项目最多 2000 条任务；每任务最多 20 条子任务。
2. 同一用户同一时刻只能跑一只计时器。再按开始，先停上一只。
3. `parent_id` 不得再指向子任务。
4. Viewer / 冻结工作区只读。
5. `visibility=private` 的项目，非创建者当不存在（404），不灰显。

## 3. 健康度

分数从 100 起扣，夹在 0–100：

| 条件 | 扣分 |
|---|---|
| 每条未完成且已逾期 | 12 |
| 每条 `doing` 超过 7 天未动 | 8 |
| 距截止 ≤ 3 天且完成率 < 50% | 20 |
| 实耗 > 估时 × 1.3（有估时才算） | 10 |

`≥ 75` 稳、`≥ 45` 紧、其余险。列表和总览都带这个数，不另做一套「红黄绿」主观标签。

## 4. 交互

### 4.1 入口与路由

顶栏顺序：**笔记 · 项目 · 广场 · 圈子 · 导航**。

| 路径 | 说明 |
|---|---|
| `/w/:wsId/projects` | 总览：卡片 + 本周节奏 |
| `/w/:wsId/projects/:id` | 单个项目；`?view=board\|gantt\|time\|pulse` |

从广场点「项目」回到最后待过的工作区，规则与「笔记 / 圈子」相同。

总览顶部必须有工作区范围选择，默认当前工作区，也可切到「所有工作区」。所有工作区视图按工作区分组，卡片明确显示归属，支持按项目名搜索和按状态筛选；点击卡片一律使用项目真实的 `workspace_id` 生成路径。详情 URL 中的 `wsId` 与项目实际归属不一致时，前端立即替换成正确路径，不能继续制造错误上下文。

新建项目弹窗必须把「归属工作区」作为显式字段，即使从某个工作区进入也不能隐藏。默认当前工作区；只列出当前用户可写且未冻结的工作区。提交后以用户最终选择的工作区为准并进入正确详情页。

### 4.2 四个视图

- **看板**：`backlog / todo / doing / review / done`。取消的不占列，收进任务详情。拖到列末或两卡之间改 `status` + `sort_key`。任务详情必须列出子任务（标题 + 勾完成），不能只显示 `0/n` 计数。
- **甘特**：按任务起止画条；没起止的不进图，右侧给「补上日期」。拖条平移，拖两端改时长。今天一条竖线。周末格子弱化。里程碑是菱形。
- **计时**：当前在跑的一只、今日合计、按任务补录。停表才落 `seconds`。
- **脉搏**：状态环、估时对实耗、近 14 日完成数与分钟、逾期与停滞名单。

顶栏一行：返回项目列表 · 项目名 · 四视图 · 「+ 任务」· 计时芯片 · 「⋯」（编辑 / 归档）。

「⋯」中在有目标工作区时提供「移动到其他工作区…」。移动保持 project id 不变，任务、里程碑、历史工时和旧链接一起保留；`project_tasks.workspace_id` 与项目同步改到目标区。移动是两头的权限操作：操作者须能归档源项目，并能写目标工作区，两边都不得冻结。目标区未归档项目上限照常检查；有正在运行的计时器时先拒绝移动，避免把其他成员正在跑的表移出其权限。目标区不存在的任务指派人会被清空，并在结果中回报数量。源、目标工作区各记一条审计。

### 4.3 空状态

没有项目：一句话「项目是交付面，不是第二个待办」+ 「建第一个项目」。  
项目里没有任务：看板中央「写下第一件要交的事」，回车即建。

## 5. 权限

读：工作区成员；私有项目仅创建者。  
写：非 Viewer，且工作区未冻结。  
归档 / 改可见性：创建者或 Admin / Owner。

所有写记 `audit_logs`，`target_type=project` 或 `project_task`。

---

## 6. 验收

1. 顶栏从左到右是 笔记、项目、广场、圈子、导航（广场或导航关掉则少那一项）。
2. 能建项目、建任务、拖看板改状态、拖甘特改期。任务详情列出子任务标题，能勾完成，不能只显示 `0/n`。
3. 开始 / 停止计时后，洞察里的实耗增加；同一人不能两只表同时跑。
4. Viewer 写接口 403；私有项目对其他成员 404。
5. 归档后默认列表不再出现，详情仍能打开只读。
6. 能在「所有工作区」查看自己可见的项目；私有项目仍只有创建者可见。创建弹窗明确显示归属，详情路径不会停留在错误工作区。
7. 有权时能把项目移到另一个可写工作区，项目 id、任务、里程碑和历史工时不变；无权限、冻结、超上限或有运行中计时时拒绝，跨区无效的指派被清空并回报。
