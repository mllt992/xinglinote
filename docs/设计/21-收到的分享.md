# 21 收到的分享

## 1. 范围

管：登录用户打开他人分享页 / 文档站后，把这条通道收进自己的笔记管理；在左栏「已分享」里回看、打开、移出。  
不管：创建 / 撤销 / 改密 / 续期（仍是 [07](./07-分享与文档站.md)）；把分享正文复制成自己的笔记（那是导入 / 动态转正，见 06、09）；协同房间（17）；日历 ICS（16）。

一句话：**已分享 = 我打开过的对外通道的个人目录，不是副本，也不是 ACL。**

现有系统只有「我发出的链接」（`/shares`、工作区「分享与外链」）。对方点开之后，链接在发出者那边，接收者这边没有任何落点——下次只能靠浏览器历史或再问一遍链接。本文补这一半。

---

## 2. 对象与状态机

### 2.1 SavedShare（收到的分享）

一条记录 = 「这个用户收下了这一条对外通道」。不存正文、不存密码、不把笔记搬进个人工作区。

| 字段 | 说明 |
|---|---|
| id | UUID |
| user_id | 收下的人。个人资产，**不属于任何工作区** |
| source | `share` / `site` |
| share_id | `source=share` 时指向 `share_links.id` |
| site_notebook_id | `source=site` 时指向已发布笔记本 |
| last_note_id | 目录 / 整本 / 文档站里上次读到的篇；单篇 / 单节 / 附件为空 |
| title_snapshot | 收下或最后一次成功打开时的标题。源失效后列表仍靠它认人 |
| kind_snapshot | `note` / `heading` / `folder` / `attachment` / `notebook` / `site` |
| author_name_snapshot | 当时能看到的分享者 / 站名，源失效后仍显示 |
| status | `active` / `dismissed` |
| created_at | 第一次收下 |
| last_opened_at | 最近一次成功打开（含自动收下那一次） |
| dismissed_at | 用户点「移出」的时间 |

唯一约束：

- `(user_id, share_id)` 在 `share_id` 非空时唯一
- `(user_id, site_notebook_id)` 在 `site_notebook_id` 非空时唯一

同一条通道对同一用户永远只有一行，用 `status` 区分「在列表里」和「我不要了」。

### 2.2 状态

```
（无行）
   │  已登录且成功打开对外通道
   │  且当时不能靠工作区 ACL 读到源
   ▼
 active  ←———— 用户点「重新保存」————  dismissed
   │                                      ▲
   │  再次打开（更新 last_opened_at）        │
   │  用户点「移出」  ——————————————————————┘
   ▼
 源失效：行仍是 active，列表标「已失效」
 用户注销：行物理删
```

`dismissed` **不会**被再次打开自动救活。否则「移出」等于没移。要回来只能在原页或列表里点「重新保存」。

源被撤销 / 过期 / 进回收站 / 文档站下线：**不删行、不改 status**。列表继续在，打开得到和对外页同一套「不存在或已失效」。用户自己移出。

### 2.3 这不是什么

| 不是 | 为什么 |
|---|---|
| 笔记副本 | 正文仍是 07 的实时投影。作者一改，下次打开就是新的 |
| 工作区成员 | 收下不等于进组，没有 `can_read` / `can_edit` |
| 收藏星标 | 星标是自己库里的篇（03）。已分享是别人的对外通道 |
| 「我发出的」 | `/shares` 管自己建的链接：改密、续期、撤销。两边不要合成一张表 |
| 转存 / 转正 | 用户明确要一份自己的 Markdown 时，走导入或动态转正，另开动作 |

## 3. 交互

### 3.1 自动收下

发生在**已经成功读到内容**之后，由公开接口服务端顺手 upsert，不靠前端再打一枪（关 JS、中途断网也不会漏）。

会触发：

1. 已登录用户打开 `/p/{token}`，token 有效，密码（若有）已过。
2. 已登录用户打开 `/s/{ws}/{nb}`，文档站已上线。

不触发：

- 未登录
- 还停在密码门（猜错、没输）
- 404 / 已撤销 / 已过期 / 源在回收站 / 站未发布
- 当前用户已经能靠工作区 ACL 读到这个目标（自己的笔记、同区成员、白名单）。这种人左边已经有本子，再塞一份是噪音
- 该 `(user, 通道)` 已是 `dismissed`

目录 / 整本 / 文档站：整条通道收一次，不按里面每一篇拆行。在树里点不同篇只更新 `last_note_id`。

同一通道反复打开：已是 `active` 就只碰 `last_opened_at`、快照标题、`last_note_id`。

公开页成功收下后，本会话同一条只 toast 一次：「已保存到左侧「已分享」」。顶栏常驻一枚安静芯片「已保存」，点进 `/w/{当前或个人区}/received`。不要每翻一篇就弹一次。

未登录的公开页不提「登录后自动保存」——避免把「这里会记一笔」做成追踪暗示。登录回跳本来就会落到原 URL（01 §3.3），回来那一次再收下。

### 3.2 左栏「已分享」

这是接收者的主入口，挂在笔记管理里，不是设置页。

左栏笔记本列表底下、日历之上，加一级项「已分享」（[16](./16-日历与任务.md) 已按这个位置预留）。  
**每个工作区左栏都有，列表内容相同**——它是用户资产，URL 里的 `wsId` 只是还停在哪个区的壳。

```
左：笔记本… / 已分享 / 日历 / 今天
中：收到的列表；点进整本 / 目录 / 站后，中栏换成该通道的只读树，顶上「← 已分享」
右：只读正文（公开渲染规则，设计 04 §5.4）
```

路由：

| 路径 | 中栏 | 右栏 |
|---|---|---|
| `/w/:wsId/received` | 收到列表 | 空状态：「从列表挑一条」 |
| `/w/:wsId/received/:id` | 列表（单篇 / 单节 / 附件）或该通道的树 | 正文 / 附件预览 |
| `/w/:wsId/received/:id?noteId=` | 树，高亮该篇 | 该篇 |

列表行：快照标题、类型芯片、来源名、上次打开时间；失效的加「已失效」。  
操作：打开、移出。不要「复制链接」「改密码」——那是发出者的事。

排序：默认 `last_opened_at` 新到旧。不提供拖拽自定义，这不是笔记本。

空列表：「打开别人发给你的分享链接或文档站，登录后会自动出现在这里。」

右栏只读：无编辑器、无 AI、无协同、无「分享」按钮、无星标。顶栏：面包屑「已分享 / 标题」、失效芯片、「打开原页」、「移出」。评论和纠错不去三栏里重做一套，点「打开原页」回 `/p/...` 或 `/s/...`。

打开原页：服务端 302 到当前有效的 `/p/{token}` 或 `/s/{ws}/{nb}`。前端列表接口**不回 token 明文**。

### 3.3 公开页上的回看与反悔

已登录且这条是 `active`：顶栏芯片「已保存」+「移出」。  
已登录且这条是 `dismissed`：芯片「保存到已分享」。  
已登录但因「ACL 已能读」没自动收：仍给「保存到已分享」，方便自己给公开页留个入口。  
未登录：什么都不加。

移出用 `useConfirm()`：「从你的「已分享」拿掉？原链接还在，不影响分享者。」确认文案「移出」。成功 toast，带 10 秒「撤销」——撤销 = 重新保存。

### 3.4 `/shares` 仍只管发出的

`/shares` 与工作区设置「分享与外链」继续只列**我建的 / 本区的**链接。  
不要在那张表上加「收到的」页签。发出是凭证管理，收到是阅读目录，混在一起会把「撤销链接」和「移出已分享」搞混。

账号菜单可加一项「我发出的分享」进 `/shares`（该页落地时再做）；「已分享」只走左栏。

### 3.5 从已分享再打开密码门

自动收下发生在密码已经通过之后。之后从左栏打开：

- 分享仍有效，且该用户对此 `share_id` 有过成功打开（行还在，含 `dismissed`）：**不再要密码**。他们已经证明拿得到内容；密码是挡匿名持链的人，不是挡已经收下的账号。
- 行被物理删（注销）或换了账号：按匿名持链走，有密码就再问。
- 分享者改了密码：已收下的账号仍然能从左栏打开；匿名 `/p/{token}` 的旧解锁 cookie 按 07 作废。改密是防链接外传，不是把已经收下的人踢掉。要踢人：撤销这条链接。
- 撤销 / 过期 / 源删除：左栏打开与对外页同一套 404 文案。

不把密码、解锁 cookie、token 写进 `saved_shares`。

## 4. 业务规则

1. **指针不是副本。** 不写笔记、不占附件配额、不进双链、不进 AI 索引、不进 MCP。
2. **自动收下是服务端行为。** 公开 GET 在确认「这份内容可以给当前会话看」之后 upsert。失败只记日志，**不得让公开阅读 5xx**。
3. **ACL 已能读则不自动收。** `can_read_note` / 能看见该本的成员打开自己区的 `/p` 或 `/s`，左边已经有树。仍允许手工「保存到已分享」。
4. **移出不级联。** 不撤销 ShareLink、不下线文档站、不改源笔记、不影响其他接收者。
5. **移出后不再自动救活。** 只有手工「重新保存」把 `dismissed` 拉回 `active`。
6. **源失效保留行。** 列表用快照标题 +「已失效」。打开统一「内容不存在或已失效」，不透露是撤销、过期还是删了。
7. **存在性。** 列表接口只回当前用户自己的行。内容接口对「不是你的 id / 已失效」用同一套对外文案。创建者看不到「谁收下了」。
8. **每人最多 200 条 `active`。** 超出新的自动收下静默跳过（公开页仍可读），手工保存回 `QUOTA`，文案「已分享已满，先移出一些」。`dismissed` 不占名额。
9. **Viewer、冻结区、待注销**都可以收——这是个人目录，不写工作区。`banned` 不能登录，收不到新的。
10. **自己发给自己。** 若创建者并不能靠 ACL 读（极少见）则按普通人收；通常创建者能 ACL 读，走规则 3。
11. **附件分享**收一条，打开走原附件预览 / 下载，仍带原 token 鉴权。
12. **主题。** 左栏里读用 App 主题（用户自己的外观）。公开页仍用实例主题（15）。
13. **搜索。** Ctrl+K / 搜索框可搜已分享的**标题快照**，scope=`shares_received`。不把别人的正文写进自己的 FTS。
14. **备份。** 行进实例备份。工作区包不收——它不是区里的对象。包里没有 token、没有正文。
15. **注销。** 宽限到期物理删该用户全部 `saved_shares`。封禁不删行，解封后还在。

## 5. 算法

### 5.1 自动收下（挂在公开读取成功之后）

```
after public_share_or_site_ok(actor, channel):
  if actor is guest: return
  if actor banned: return
  if channel is share and not effective(share): return   # 防御，走到这里本应已拦
  if can_read_via_workspace_acl(actor, channel.target): return
  row = by_user_and_channel(actor, channel)
  if row is dismissed: return
  if row is nil and count_active(actor) >= 200: log; return
  upsert active:
    title_snapshot, kind_snapshot, author_name_snapshot
    last_note_id = 本次打开的篇（若有）
    last_opened_at = now
    created_at 只在插入时写
```

`can_read_via_workspace_acl` 只走 [02](./02-工作区成员与ACL.md) 的 `can_read_note` / 笔记本可见性，**不**把「持有这条分享 token」算进去。

### 5.2 从已分享读内容

```
row = by_id
if row.user_id != me: NOT_FOUND
if row.status != active: NOT_FOUND          # dismissed 不能当后门
if row.source == share:
    share = by_id(row.share_id)
    if not effective(share) or target trashed/purged: NOT_FOUND
    render(share, noteId?)                  # 与 /p/:token 同一套投影
if row.source == site:
    nb = notebook(row.site_notebook_id)
    if not nb.site.published: NOT_FOUND
    render(site, noteId?)                   # 与 /s/... 同一套，只 published
```

这里**不再查密码、不再查解锁 cookie**。授权依据是「active 的 SavedShare + 通道本身仍有效」。

手工保存 / 重新保存：

```
if dismissed: status=active, dismissed_at=null, last_opened_at=now
if nil: 同 5.1 插入；已满则 QUOTA
if 通道当前无效: NOT_FOUND
```

移出：

```
status=dismissed, dismissed_at=now
不删行（重新保存、审计、10 秒撤销都靠它）
```

`dismissed` 行超过 180 天可由 worker 物理删，不影响业务。

### 5.3 打开原页

```
GET /api/v1/me/saved-shares/:id/open  →  302 Location
  share: /p/{当前 token}[?noteId=]
  site:  /s/{当前 ws slug}/{当前 nb slug}[/{noteId}]
若通道已失效：NOT_FOUND，同一套对外文案
```

token 只出现在这一次重定向的 Location 里，不进列表 JSON。

### 5.4 列表投影

```
rows = active saved_shares of me, order by last_opened_at desc
for each:
  live = effective(channel) and target not trashed and (site ⇒ published)
  title = live ? 现标题 : title_snapshot
  不回 token、不回 password、不回源笔记 body
```

## 6. 与其他功能的关联

| 方向 | 关系 |
|---|---|
| ← 01 | 登录 `redirect` 回分享页后，下一次公开 GET 触发自动收下 |
| ← 02 | 用 `can_read_*` 判断「已经是自己库里的」，避免重复收 |
| ← 07 | 通道有效性、投影、密码、撤销、站与链独立，全部沿用；本文只加接收者目录 |
| ← 04 | 右栏公开渲染规则与文档站相同 |
| ← 12 | 源 trash 后已分享标失效；用户注销删行 |
| ← 15 | 公开页仍实例主题；App 内已分享用用户主题 |
| → 05 | 新 scope `shares_received`，只搜标题快照 |
| → 13 | 行进实例备份，不进工作区包，不含 token |
| → 16 | 左栏顺序：笔记本 → **已分享** → 日历 → 今天 |
| → 11 / 10 | MCP、AI 都当这批指针不存在 |

发出：无新领域事件。列表是按用户查表，搜索直接读 `title_snapshot`，没有跨模块订阅方。

## 7. 验收口径（实现时对照）

1. 未登录打开 `/p`、`/s`：不写库。登录后再打开同一条：左栏「已分享」出现一行。
2. 有密码的分享：密码门阶段不收；解锁成功后收。之后从左栏打开不再要密码。
3. 自己库里的笔记再点自己的分享链接：不自动出现在「已分享」。手工保存可以。
4. 整本文档站只出现一行，不是站内每篇一行。再点站内另一篇，还是这一行，只更新上次读到的篇。
5. 移出后刷新列表没有了；再打开原链接也不会自动回来。公开页可以「重新保存」。
6. 撤销链接 / 下线文档站：列表还在，标「已失效」，打开文案与对外 404 相同；移出只删自己的行。
7. 移出确认框、无 `alert`。公开阅读失败不得因为收下逻辑而 5xx。
8. 列表接口不含 token。AI / MCP / 工作区搜索正文都碰不到这些篇。
