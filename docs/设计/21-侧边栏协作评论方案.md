# 21 · 侧边栏协作评论方案

## 1. 目标与边界

编辑页右栏提供工作区内的协作评论。成员可以评论整篇笔记，也可以选中一段正文后带引用发起讨论；讨论支持回复、解决、重新打开和软删除。

它与分享页的公开评论是两条通道：

- 协作评论要求登录并通过笔记读取 ACL，不进入访客审核队列。
- 公开评论仍使用 `target_type = note`；协作评论使用 `target_type = note_thread`，不会互相出现在对方列表里。
- Viewer 可以阅读和参与讨论；线程作者或拥有笔记编辑权的成员可以解决、重开和删除线程。

## 2. 文本锚点

根评论可保存 `from / to / quote / prefix / suffix / version`。定位按以下顺序进行：

1. 当前正文在旧偏移处仍是原文，直接定位；
2. 全文只有一处相同原文，视为内容移动后定位；
3. 有多处相同原文，用前后各 48 个字符的上下文消歧；
4. 找不到或无法唯一确认时显示“原文已变化”，不猜测位置。

偏移采用 JavaScript 字符串与 CodeMirror 共用的 UTF-16 坐标，避免中文、emoji 在前后端之间换算成不同位置。锚点记录的是发表评论时的快照；它不阻止正文继续编辑。

## 3. 存储与接口

复用 `comments` 表，以 `parent_id` 表达一层回复：根行保存锚点，回复行的锚点为空。`visible / resolved / hidden` 分别表示未解决、已解决和软删除。

主要接口：

- `GET /api/v1/notes/:id/discussions`：读取未解决线程；`?resolved=1` 读取已解决线程。
- `POST /api/v1/notes/:id/discussions`：创建整篇或引用评论。
- `POST /api/v1/discussions/:id/replies`：回复未解决线程。
- `PATCH /api/v1/discussions/:id`：作者改正文；作者或编辑者解决/重开。
- `DELETE /api/v1/discussions/:id`、`DELETE /api/v1/discussion-replies/:id`：软删除。

复用现有表的好处是工作区备份、账号注销匿名化和笔记物理销毁链路会自动覆盖协作评论。新增索引覆盖线程回复读取。新评论通知笔记作者；新回复通知本楼参与者，通知深链直接打开评论栏。

## 4. 客户端交互

- 顶栏评论按钮直接打开右栏；若 CodeMirror 中已有选区，首次打开会自动带入引用。
- 评论栏仍提供“引用选区/重新引用”，允许先开侧栏再选正文。
- 引用块点击后切到编辑视图、滚动并选中对应原文。
- 未解决和已解决分栏显示；已解决线程不接受回复，重开后可继续。
- 编辑器以外的正文更新不会让线程消失；只影响锚点是“原位、已移动、已失效”中的哪一种状态。

## 5. 验证重点

- ACL：不可读笔记的用户看不到线程；可读用户可评论；解决和删除按作者/编辑权分别校验。
- 隔离：公开互动审核查询必须显式限定 `target_type = note`。
- 锚点：原位、前插移动、重复文本消歧、原文删除四种情况均有单元测试。
- 限流与输入：每用户每笔记每分钟最多 30 次写入，评论 1–4000 字，引用不超过 2000 字。
