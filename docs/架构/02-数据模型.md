# 02 数据模型

PostgreSQL 16。主键除特别说明外均为 `uuid`。时间全部 `timestamptz`。软删用显式时间戳，不用混在 status 里的魔法值（User 除外，因其状态机更复杂）。

迁移放 `infra/migrations/`，工具可用 `node-pg-migrate` 或 drizzle migrate，但**表结构以本文为准**。

## 10. 全文检索

```sql
note_fts
  note_id pk
  workspace_id, notebook_id
  title, body_plain
  tsv tsvector
  updated_at
CREATE INDEX note_fts_tsv ON note_fts USING gin (tsv);
CREATE INDEX note_fts_trgm ON note_fts USING gin (body_plain gin_trgm_ops);
```

中文：`tsv` 用 simple 配置 + 应用层 bigram 写入辅助列 `ngrams text`，或扩展 `zhparser`（镜像可选）。一期最低：`pg_trgm` 对 title/body 做 `%` 相似 + `ilike` 标题前缀，保证「账本」可搜。

广场：`posts` 上 `body_md` trgm 即可。

## 12. 重建

从文件系统重建（灾难）：扫描 `notes/**/*.md` 的 frontmatter `id`，upsert `notes`，然后全量跑双链解析 + FTS + chunks。ACL 必须来自库备份，单靠文件重建会丢掉成员关系。所以 **实例+工作区逻辑备份不可省**。

来自笔记的日历任务可以从正文块锚重建（跑一遍 `sync_note_tasks`），但 `done_at` / 提醒 / 指派只在库里，同样不可省。

## 13. 日历与任务

业务规则见 [设计 16](../设计/16-日历与任务.md)。task 与 event 同表，用 `kind` 区分，理由见该文 §2.1。

```sql
calendar_items
  id, workspace_id
  kind          text  check (in ('task','event'))
  title, body_md
  all_day       bool default false
  starts_at, ends_at            -- event 必填
  due_at                        -- task；为空 = 只在收件箱
  timezone      text            -- IANA，创建时的时区
  status        text  check (in ('open','done','cancelled')) default 'open'
  done_at, done_by
  priority      smallint default 0
  color         text            -- 语义 token 名，不存 hex
  rrule         text            -- RFC5545 子集，见设计 16 §4.4
  rrule_until
  source        text  check (in ('manual','note','ics','mcp','ai')) default 'manual'
  source_note_id, source_anchor, source_sub_id
  link_state    text  check (in ('linked','detached')) default 'linked'
  notebook_id                   -- 冗余自来源笔记，供 ACL 快速过滤
  assignee_user_id
  created_by, updated_by, created_at, updated_at
  trashed_at
CREATE INDEX ON calendar_items (workspace_id, starts_at);
CREATE INDEX ON calendar_items (workspace_id, due_at);
CREATE INDEX ON calendar_items (source_note_id);
CREATE UNIQUE INDEX ON calendar_items (source_note_id, source_anchor)
  WHERE source_anchor IS NOT NULL;   -- 一个块锚只对一条

calendar_overrides             -- 重复项的单次例外，重复实例本身不落库
  id, item_id, occurrence_start
  action text check (in ('moved','cancelled','done'))
  new_start, new_end, done_at, done_by
UNIQUE (item_id, occurrence_start)

calendar_reminders
  id, item_id
  kind    text check (in ('relative','absolute'))
  offset_min int                -- relative：负数 = 提前
  absolute_at
  channel text check (in ('inapp','email','push'))
  status  text check (in ('pending','scheduled','fired','skipped'))
  fired_at

calendar_subscriptions         -- 外部 ICS 只读订阅
  id, workspace_id, name, url, color, enabled
  etag, last_sync_at, last_error, fail_count
  created_by, created_at

calendar_feed_tokens           -- 对外导出 ICS 的订阅地址
  id, workspace_id, user_id
  token  text unique           -- 32B url-safe，语义同 share_links.token
  scope  text check (in ('mine','workspace')) default 'mine'
  status text default 'active'
  last_used_at, created_at

calendar_templates             -- 一组相对时间的条目，套到某一天（设计 16 §3.12）
  id, workspace_id, name, description
  scope  text check (in ('workspace','private')) default 'private'
  items  jsonb                 -- [{kind,title,body_md,all_day,offset_days,start_min,duration_min,priority,reminders}]
  created_by, created_at, updated_at
  index (workspace_id, scope)

push_subscriptions             -- Web Push 端点，一人多设备（设计 16 §5.7）
  id, user_id
  endpoint text unique         -- 浏览器给的推送端点，不回前端
  p256dh, auth text            -- RFC 8291 的客户端公钥与鉴权密钥
  user_agent text
  status text check (in ('active','gone')) default 'active'
  fail_count integer default 0
  last_ok_at, created_at
  index (user_id, status)

note_collab                    -- 协同房间的 Y.Doc 快照（设计 17 §3.4）
  note_id  uuid pk             -- 一篇一间
  state    bytea               -- Y.encodeStateAsUpdate 的结果，压实后重写而非追加
  updates  integer             -- 自上次压实以来合进来多少个 update
  body_md  text                -- 房间上次落库时写下去的正文，用来认「外面有人改过」
  updated_at
```

`note_collab` 是**可丢的缓存**：删掉它只会让下一个房间从 `notes.body_md` 重新初始化，
不丢任何已落库的内容。事实源永远是 `notes` 与 `note_versions`。

`calendar_templates.items` 只存**相对**偏移，绝不存绝对日期——存了绝对日期的模板只能用一次。
`push_subscriptions.endpoint` 是这台设备的推送凭证，接口只回末 16 位当指纹；VAPID 私钥存
`instance_settings.vapid_private_key`（seal 后入库），**任何接口都不回它**。

`calendar_feed_tokens.token` 与 `share_links.token` 同级别：可复制、可吊销、不可枚举，**是对外泄露面**，在 `/shares` 一起管理。`calendar_subscriptions.url` 只允许 http/https 且解析后 IP 不得落在私有段（SSRF）。
