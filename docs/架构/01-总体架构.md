# 01 总体架构与选型

## 1. 目标与约束

- 单机 Docker Compose 能跑完家庭 / 小团队。
- 一份知识内核，Web 与 MCP 都是 client。
- Markdown 文件可备份、可重建索引；权限/版本/检索在 PostgreSQL。
- 运维部件尽量少：不要一上来上 Kafka、ES、独立对象存储当主盘。
- 开源友好：标准 HTTP、标准 MCP、无商业 SDK 强绑。

规模假设（一期性能基线）：≤ 50 用户、≤ 20 工作区、≤ 10 万篇笔记、附件总量 ≤ 200GB、MCP QPS 个位数。超出再拆。

---

## 2. 推荐选型（锁定）

| 层 | 选择 | 理由 |
|---|---|---|
| 语言 | TypeScript / Node 22 | 官方 MCP SDK、前后端同语、AI HTTP 调用简单 |
| 仓库 | pnpm monorepo | `apps/web` `apps/api` `apps/worker` `packages/core` `packages/mcp` |
| HTTP | Hono | 轻、类型好、能挂 Node 与后续 Bun |
| 前端 | React 19 + TypeScript + Vite + Tailwind CSS + shadcn/ui + Radix UI | Tailwind 承载设计 token 与布局；shadcn/ui 提供可维护的组件源码；Radix 负责复杂交互与无障碍；PWA 后加 |
| 前端路由 | React Router 7 | Public / Site / Share / App 多壳路由与鉴权边界清晰 |
| 前端图标 | Lucide React | 与 shadcn/ui 风格一致，统一线宽与尺寸，避免混用图标库 |
| 编辑器 | CodeMirror 6 | 源码模式、wikilink 插件好写 |
| Markdown | markdown-it + 自研 wikilink 插件 + KaTeX | 编辑器/文档站/MCP 预览共用一套 |
| DB | PostgreSQL 16 | ACL、FTS、任务、后期 pgvector 都在一处 |
| 向量 | pgvector 扩展 | 少一个服务；embedding 调外部或本地 |
| 队列 | 自研 PG `background_jobs` | 与库同命运，少 Redis |
| 缓存 | 进程内 LRU；可选 Redis | 只缓存 embedding。没配 `REDIS_URL` 照样跑 |
| 会话 | httpOnly Cookie + 服务端 session 表 | 自托管安全；MCP 另走 Bearer |
| 密码 | Argon2id | |
| 文件 | 本地磁盘 | 设计约定路径；S3 只作备份目标 |
| 加密备份 | 备份包用 libsodium secretbox，口令 Argon2 派生 | |
| 反向代理 | Caddy 或 Nginx（Compose 可选） | TLS、上传体积 |

不选：微服务、Prisma 强绑（可用 drizzle 或 kysely，便于写复杂 ACL SQL）、Yjs（一期无实时光标）。

## 3. 进程

同一镜像，三个命令：

```
api      对外 :12099   HTTP API + 静态 Web + /mcp + /p /s 公开页 SSR/CSR
worker   对内         索引、抽 PDF、邮件、备份、purge、link_rewrite 批量
migrate  一次性       跑 SQL 迁移
```

开发可把 api+worker 合成一个进程，生产必须分开，避免备份/嵌入堵住保存接口。

`packages/core`：ACL、保存笔记、双链解析、配额。api 与 worker **都只调 core**。

```
┌─────────────┐     ┌──────────────┐
│  apps/web   │     │ Cursor 等    │
└──────┬──────┘     └──────┬───────┘
       │ Cookie            │ Bearer /mcp
       ▼                   ▼
┌──────────────────────────────────┐
│ apps/api  (Hono)                 │
│  /api/*  /mcp  /p /s / 静态      │
└──────────────┬───────────────────┘
               │ core
     ┌─────────┼──────────┐
     ▼         ▼          ▼
  Postgres   本地磁盘    发 job
                     ▼
                apps/worker
```

## 4. 仓库与运行时目录

```
apps/web/
apps/api/
apps/worker/
packages/core/          # ACL / note / wiki / quota
packages/mcp/           # 工具 schema 与 handler，api 挂载
packages/shared/        # 错误码、DTO 类型
infra/docker-compose.yml
infra/migrations/
```

数据根（环境变量 `DATA_DIR`，默认 `/var/lib/knowledge`）：

```
$DATA_DIR/
  workspaces/{workspace_id}/
    notes/{notebook_id}/{note_id}.md
    files/{note_id}/{safe_filename}
  tmp/                  # 导入导出、备份打包
  cache/                # 可选
```

`.md` 内容：YAML frontmatter（id/title/aliases/published/ai_index）+ 正文。  
**数据库是权限与检索的权威；id/version/ACL 以库为准。** 文件是可重建的源码镜像。保存顺序：

1. 事务写库（含 version+1、版本行）
2. fsync 写 `.md`
3. 提交事务
4. 入队 `NoteUpserted`

若 2 失败则回滚事务。启动时「文件有、库无」进修复命令，不自动乱建。

## 5. 请求里的 Actor

```ts
type Actor =
  | { kind: "user"; userId: string; sessionId: string }
  | { kind: "mcp"; userId: string; tokenId: string; workspaceId: string; workspaceIds: string[]; caps: McpCaps }
  | { kind: "guest"; shareId?: string }
```

`core.can_read_note(actor, note)` 唯一入口。MCP handler 先把钥匙变成 Actor，再调和 HTTP 同一函数。

## 6. 安全边界

| 项 | 做法 |
|---|---|
| Cookie | `Secure` `HttpOnly` `SameSite=Lax`，session 存哈希 |
| CSRF | 写操作用 `SameSite` + 自定义头 `X-Requested-With`；公开表单另发 CSRF token |
| 上传 | 类型白名单、杀路径、限额；不执行用户 HTML |
| 分享 token | 高熵；公开错误统一文案 |
| 密钥 | AI key、备份凭据用 `APP_SECRET` AES-GCM 存库；MCP secret 只存哈希 |
| SSRF | 用户填的 OpenAI base_url / WebDAV / S3 endpoint 做私网段拒绝（可配置放行） |
| 限流 | 按 IP+user+token，见设计 01/08/11 |
| 管理面 | `/admin` 仅 instance admin，不靠隐藏 URL |

## 7. 部署

`docker-compose` 服务：`db`（postgres:16 + pgvector 镜像）、`api`、`worker`。卷：`pgdata`、`data`。  
环境变量最小集：

```
APP_SECRET=
PUBLIC_URL=https://notes.example.com
DATABASE_URL=
DATA_DIR=/var/lib/knowledge
```

SMTP、S3 在实例后台配，不强迫进 env。  
健康检查：`GET /api/healthz`（db ping + data dir 可写）。

## 9. 观测
