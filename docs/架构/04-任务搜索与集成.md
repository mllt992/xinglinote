# 04 任务、搜索、邮件与备份

## 1. 事件 → 任务

api 在事务提交后 `enqueue`。worker 只消费。失败指数退避 5 次后进 dead letter，写日志 + 通知 Owner（索引长期失败）。

| job type | 触发 | 并发 | 做什么 |
|---|---|---|---|
| `note.reparse` | NoteUpserted content/title | 按 note_id 串行 | 重写 links；若 title 变则再入 `note.rewrite_links` |
| `note.rewrite_links` | 标题变更 | 全局低并发 | 回写其他篇 raw 标题，source=link_rewrite |
| `note.index` | Upserted / extract_ok | 按 note | 更新 note_fts、ngram |
| `note.embed` | 同上且 ai_index | 低并发（受 embedding API 限） | 切块写 note_chunks |
| `note.deindex` | Trashed / ai_index 关 | | 删 fts+chunks |
| `file.extract` | 上传 PDF | | 抽文本，成功后再 note.index/embed |
| `mail.send` | 验证/找回/邀请 | 限速 | SMTP |
| `import.run` | 用户导入 | 每用户 1 | 建树 |
| `export.run` | 导出 | | 打包到 tmp，发下载通知 |
| `backup.run` | 调度或手动 | 每 target 1 | 见设计 13 |
| `trash.purge` | 每小时 | 1 | purge_at < now |
| `user.finalize_deletion` | 每小时 | 1 | pending_deletion 到期 |
| `notify` | 评论/纠错/备份失败 | | 写 notifications 表 |
| `agent_reply` | 动态/评论变为可见且正文 @ 了智能体 | 每智能体每来源 1 | 调该智能体模型，落一条评论（设计 20） |
| `sync_note_tasks` | NoteUpserted content | 按 note_id 串行 | 差量解析任务行、写块锚、维护 calendar_items（设计 16 §5.1） |
| `calendar_reminder` | 条目创建/改期 | 中 | 到点重校验后写 notifications，email 再入 `mail.send` |
| `calendar_ics_sync` | 定时 30 分钟 | 每订阅 1 | 条件请求拉外部 ICS，按 UID upsert |
| `calendar_rollover` | 每日 00:05（按工作区时区） | 1 | 逾期标记、当日汇总通知、清理失效的推送端点 |

协同房间**不进 job 表**：它活在 api 进程里，落库靠自己的防抖定时器（设计 17 §3.4），
排进队列反而会让「3 秒静默就落一次」变成不可控的延迟。

`sync_note_tasks` 里的勾选回写 **不再** 入 `rewrite_links`，只入 `index/embed`，与 `link_rewrite` 同一条防环规则。日历勾选产生的保存按设计 16 §4.3 合并版本（`source=task_toggle`）。

`link_rewrite` 产生的保存 **不再** 入 `rewrite_links`，只入 `index/embed`，防环。

## 2. 搜索实现

### 2.1 关键词（搜索框 / MCP keyword）

```
1. 解析 q、scope、过滤器
2. 可见笔记本集合 = SQL 按 ACL（membership + visibility + notebook_members）
3. title ILIKE / trgm  OR  body_plain trgm  OR  tag =
4. 设计 05 的打分在 SQL 或应用层重排
5. 截 20 条，snippet 用 ts_headline 或前后 80 字
```

`private` 本：`created_by = actor` 才进集合。  
MCP：集合再交 `token.allowlist`、`allow_private`、`require_ai_index`。

### 2.2 语义 / hybrid

仅 `ai/ask` 与 `search_notes(mode=semantic|hybrid)`。

- 无 embedding 配置：semantic 退化为 keyword 并在响应里 `degraded=true`。
- hybrid：关键词 Top20 + 向量 Top20，RRF `1/(60+rank)` 合并。

向量：`ai_chunks` JOIN `notes`（只要 `ai_index` 且未 trash），`ORDER BY kb_cosine_distance LIMIT 24`，再对候选做 `can_ai_read`。数据大了再考虑先向量后滤（要注意滤光）。

问句和切块的 embedding 走 [设计 10 §5.4](../设计/10-AI与ai_index.md) 的缓存：进程内 LRU 必有，`REDIS_URL` 有则 api / worker 共用。不缓存带 ACL 的命中列表。

### 2.3 中文

最低：`pg_trgm` similarity > 0.15 或 `%q%`。  
增强：worker 把正文切成 bigram 空格串写入 `note_fts.ngrams`，用 `to_tsvector('simple', ngrams)`。  
不要把「没装 zhparser 就搜不到中文」当成可接受。

## 3. 邮件

无 SMTP：注册若要求验证，后台标红；零用户第一人允许跳过验证（设计 01 已有免验证码路径）。  
有 SMTP：`mail.send` 模板：验证邮箱、重置密码、工作区邀请、（可选）纠错结果。  
发信频率按设计 01。失败重试 3 次。

## 4. 备份任务

worker 每 5 分钟扫一遍启用中的目标：`daily` 距上次成功满 24 小时、`weekly` 满 7 天就入队；失败后 30 分钟内不连打。

`backup_workspace` / `backup_instance`：

1. 锁 target（同一目标同时只跑一个）
2. 实例或工作区一致性读
3. JSON 快照 → 可选加密（KBENC1 / AES-256-GCM）→ sha256
4. 上传 S3（path-style + SigV4）或 WebDAV（PUT，缺目录先 MKCOL）
5. 按保留策略列远端并删过期包（至少留 1 个最新成功包）
6. 写 backup_runs；失败给 Owner / 实例管理员发站内信

SSRF：用户填的 endpoint 默认禁回环与链路本地址，实例管理员可开「允许内网」（群晖 WebDAV 需要）。

恢复在 **api 进程同步或单独 job `backup.restore`**：先 `frozen=true`，再解包，重建 fts/chunks/title_index，最后解冻。禁止 worker 与用户写同时进行。

当前恢复器在 API 进程同步执行，口令因此只存在于当前请求内存，不进入 durable job payload。`RestorePlan` 只保存对象名、checksum、范围和预检报告；替换恢复先同步生成远端检查点。数据库写入在事务和 advisory lock 内完成，附件先写内容寻址 staging，失败按 refcount 回收；正文文件、双链与 AI 索引在提交后由数据库正文重建。

## 5. 在场与实时

presence：客户端 20s `POST /notes/:id/presence`，读时 `GET` 同接口返回 60s 内心跳的用户。  
不用 websocket 一期。文档站不需要推送，靠刷新。

## 6. 限流落点

限流中间件仍然 Redis 可免，用内存滑动窗口 + PG 计数双保险（多 api 副本时用 PG）。Redis 只作为 embedding 旁路缓存接入，见上文 2.2 与设计 10 §5.4。

| 键 | 阈值 |
|---|---|
| login:ip | 30/10min |
| login:email | 5/10min |
| register:ip | 10/h |
| comment:ip | 5/10min 访客 |
| mcp:token | 60/min |
| ai:user | 30/h 可配 |
| share_unlock:ip | 10/10min |
