## 1. 开源项目怎么做的

### 1.1 三条技术路线

| 路线 | 事实源 | 代表 | 代价 |
|---|---|---|---|
| **源码型**：文本就是文档，渲染只是装饰 | Markdown 字节 | Obsidian、Joplin、Zettlr、MarkEdit、本项目 | 所见即所得做不到极致（块级件与光标要打架） |
| **结构化型**：解析成 AST 再序列化回去 | 文档树 | Outline、Notesnook、Milkdown、BlockNote、MarkText | 往返归一化：`*`→`_`、表格补空格、软换行折行 |
| **块型自研**：每块一个 contenteditable，直接绑 CRDT | JSON / Y.Doc | 思源（Protyle + Lute）、AFFiNE（BlockSuite）、Logseq、AppFlowy、Anytype | Markdown 降格成导入导出格式；自己养一个编辑器内核 |

### 1.2 逐个看

| 项目 | 内核 | 值得抄的 | 不适用于本项目的原因 |
|---|---|---|---|
| **Obsidian** | CM6 | Live Preview 的判定粒度、软换行悬挂缩进、标题折叠、双链悬停卡片、移动端键盘上方工具条 | 闭源，只能照着效果重做 |
| **Joplin** | CM6（桌面 + 移动同一套） | 「一套 CM6 扩展跑遍桌面与手机」的思路；富文本粘贴转 Markdown 是独立插件 | 无 |
| **Zettlr** | CM6 | 渲染项目**逐项可关**（哪些元素替换成渲染态由用户勾）；raw / preview 双模 | 无 |
| **MarkEdit** | CM6 | 大文件降级策略：超阈值关掉视口外着色与折叠 | 无 |
| **atomic-editor / codemirror-live-markdown** | CM6 | 现成的 Live Preview 装饰清单与踩坑记录（见 §2.3） | 可直接对照补齐 |
| **思源** | Protyle + Lute（Go 内核） | 块级引用、百万字文档；早年用 Vditor 后自研 | 已从 Markdown 换成 JSON 存储——本项目的四个写入方共用一份 Markdown，换不了 |
| **AFFiNE** | BlockSuite | 每块独立 inline editor 直接挂 Y.Text，天生协同；避免「一个巨型 contenteditable」 | 同上，事实源变成 Y.Doc |
| **Logseq / AppFlowy / Anytype** | 各自自研块编辑器 | 大纲式操作手感 | 同上 |
| **Outline / Notesnook / Milkdown / BlockNote** | ProseMirror 系 | 表格、拖块、协同插件生态成熟 | AST 往返会归一化标记，破掉行级 diff 与导回 Obsidian（设计 17 §2） |
| **Standard Notes（Super）** | Lexical | 富文本与 Markdown 并存的产品化取舍 | 同上 |
| **Trilium** | CKEditor 5 + CM | 富文本笔记与代码笔记用两个内核 | 同上 |

### 1.3 结论

设计 17 §2 拒掉 ProseMirror 系与 Lexical 的四条理由（行级 diff、`expected_version`、
zip 导回 Obsidian、`[[wiki]]`/`$math$` 闭集）今天仍然成立，调研没有找到反例——凡是做到
真·所见即所得的，无一例外**放弃了「Markdown 字节是唯一事实源」**。所以：

- **主线不动**：继续 CM6 + 装饰层。
- **差距不在内核，在装饰层的完成度**：Obsidian / Zettlr 在同一个内核上做到的悬挂缩进、
  折叠、粘贴转换、移动端工具条、渲染项开关，本项目一条都还没有。

## 2. 编辑器技术横向要点

### 2.1 文档模型与装饰

CM6 用字符偏移定位，装饰分 `mark`（加样式）/ `replace`（替换成小部件）/ `line`（整行）。
铁规矩两条，本项目都已经遵守：块级与跨行替换**只能走 `StateField`**，替换范围必须严格盖住整行。
被替换的区间要登记进 `atomicRanges`，否则方向键会掉进看不见的字符里。

### 2.2 输入法（IME）与 EditContext

- CM6 自 6.28 起在 Chrome 上走 **EditContext API** 采集输入，Firefox / Safari 仍走
  contenteditable 老路。近两年的变更日志里大量条目是 Android / Safari / CJK 输入法的修补
  （6.38.4 修 Chrome Android 不发 `compositionend`；6.43.1 修 macOS Chrome 部分输入法组词被打断）。
  **保持 `@codemirror/view` 跟版**是最便宜的兼容性投资，现在是 6.43.9，正好在版本上。
- 公认的雷区：**组词期间动光标附近的 DOM 会中断组词**。所以紧挨光标的 `replace` 小部件对
  中文输入是有风险的——这一条直接命中本项目，见 §3 D1。

### 2.3 社区踩坑清单（可直接对照）

来自 codemirror-live-markdown 的设计文档与 CM 论坛：

| 坑 | 说法 |
|---|---|
| 小部件 `eq()` | 不实现就每次重建 DOM，图片闪、mermaid 反复重画 |
| 隐藏标记 | 用 `max-width: 0` / `font-size: .01em` 压扁，比 `display: none` / 直接 replace 对输入法友好 |
| 拖选期间 | 鼠标拖选时先别重建装饰，松手再重建，否则闪 |
| 大文档 | 装饰构建一律限制在 `view.visibleRanges` |

### 2.4 协同与撤销

`yCollab()` **只装** `yUndoManagerFacet` / `yUndoManager` / 一个 `beforeinput` 兜底，
**不装 `yUndoManagerKeymap`**——键位要自己接。而它推远端改动进编辑器时用的是
`view.dispatch({ changes, annotations: [ySyncAnnotation] })`，**没有 `addToHistory: false`**。
所以只要 CM 自己的 `history()` 还在，远端的字就会进本地撤销栈。见 §3 A1。

### 2.5 无障碍

CM6 给 `.cm-content` 设 `role="textbox"`、`aria-multiline="true"`，但**不设 `aria-label`**，
并且写死 `spellcheck="false"`、`autocorrect="off"`、`autocapitalize="off"`。
后三个对代码是对的，**对散文和手机打字是错的**。另外 `indentWithTab` 会吞掉 Tab，
形成键盘焦点陷阱——CM 官方文档专门提醒过这点。

### 2.6 性能

CM6 的解析和渲染本身是惰性的，瓶颈通常在自己写的装饰构建：**是否限制在视口内**、
**是否每次光标移动都全量重建**。另一个常见瓶颈在编辑器之外——分栏预览每敲一个字就全量
重新渲染一遍 Markdown。

## 3. 现状体检

代码位置基于当前 `main`。严重度：🔴 缺陷 / 🟠 体验硬伤 / 🟡 可打磨。

### A. 缺陷

| # | 问题 | 位置 | 说明 |
|---|---|---|---|
| 🔴 A1 | **协同下 Ctrl+Z 能撤销别人的字** | [markdown-editor.tsx:183](../apps/web/src/editor/markdown-editor.tsx#L183) `history()` 常驻 | `yCollab` 推远端改动时没标 `addToHistory: false`，本地 history 照单全收；撤销结果还会经 CRDT 广播回去，等于替所有人回滚 |
| 🔴 A2 | **手机上编辑态点不开双链** | [live-preview.ts:401](../apps/web/src/editor/live-preview.ts#L401) 要求 `ctrlKey \|\| metaKey` | 触摸设备没有这两个键。窄屏默认停在「预览」tab 掩盖了它，一旦切到「编辑」就彻底没有入口 |
| 🟠 A3 | 斜杠菜单有一条死项 | [slash-menu.ts:35](../apps/web/src/editor/slash-menu.ts#L35) `折叠标记` 模板是 `"" + NL + CARET` | 选中后只插一个换行，名字也对不上任何语法 |
| 🟠 A4 | **编辑器正文行宽没有按设计 17 §3.2 收到 46rem** | `styles.css` 里没有 `.cm-line` 的 `max-width` | 预览侧限了（`.markdown > :is(p,ul,…)`），编辑侧没限。宽屏下同一篇笔记，左边一行 1400px、右边一行 46rem，说好的「左边缘对齐同一条线」只对齐了左边 |

| # | 缺什么 | 参照 |

## 4. 方案

### P8 先修错（低风险，建议立刻做）

| 条目 | 做法 | 验收 |
|---|---|---|
| A1 撤销 | `history()` 移进一个新隔间。协同一挂上就换成空扩展并补 `keymap.of(yUndoManagerKeymap)`；断开 / 只读时换回来。**两套撤销不许同时在场** | `verify-collab.mjs` 加：甲乙各打一段，甲按 Ctrl+Z，乙那段必须还在 |
| A2 双链 | `followHandler` 增加触摸分支：`event.pointerType === "touch"` 或 `matchMedia("(pointer: coarse)")` 时，单击 `.cm-md-wiki` / `.cm-md-link` 直接跟随。桌面维持 Ctrl+单击不变 | `verify-editor-cdp.mjs` 加一条 touch 事件断言 |
| A3 斜杠 | 删掉 `折叠标记`；要保留就换成真语法（例如「分割为新段落」= 两个换行） | 现有斜杠菜单用例补一条计数 |
| A4 行宽 | `.cm-line { max-width: var(--measure); }`；块级小部件（表格 / 图 / 块级公式 / 图片）不受限，仍占满 `.editor-measure` | `verify-editor-cdp.mjs` 十点七已有栏宽用例，扩到编辑侧 |

> A4 有个坑：`.cm-content` 若也加 `max-width`，点击右侧空白就落不到行尾了。**只限 `.cm-line`**，
> 保持 `.cm-content` 满宽。

### P9 体验（高价值，中等工作量）

| 条目 | 做法 | 口径与风险 |
|---|---|---|
| B1 粘贴富文本 | `paste` 里读 `text/html`，先 DOMPurify 再交给 **turndown + turndown-plugin-gfm** 转成 Markdown。**按需加载**，和 KaTeX / mermaid 同一条路子，没粘过富文本的用户不下这几十 KB | 只能产出闭集内语法（规格 §9.2）：闭集外的（HTML 表单、iframe、脚注）降级成纯文本。转换结果是普通输入，不违反「装饰不改字节」 |
| B7 纯文本粘贴 | `Ctrl/⌘+Shift+V` 强制走 `text/plain` | — |
| B8 URL 成链接 | 选区非空 + 剪贴板是单个 URL → 替换成 `[选中](url)` | — |
| B2 悬挂缩进 | 一个 ViewPlugin，按行首缩进 + 列表 / 引用标记宽度算出 `padding-left` + 等量负 `text-indent`，挂 `Decoration.line` | 只影响显示。宽度用 `ch` 估算在比例字体下不准，wysiwyg 模式要用 `measure` 量一次真实标记宽度 |
| B3 折叠 | `codeFolding()` + 自写 `foldService`：标题折叠到下一个同级或更高级标题；围栏代码块折叠；`foldGutter` 默认关，命令面板里开 | 折叠状态是本机偏好，不进文档、不进备份（同表格列宽的口径） |
| B4 斜杠匹配 | `CompletionResult` 返回 `filter: false` **自己过滤**，每条 snippet 带 `aliases: ["table","biaoge","bg"]`；显示仍走 `displayLabel` 的中文名 | `@codemirror/autocomplete` 6.20 已有 `displayLabel`，不用升级 |
| B5 预览防抖 | 分栏模式下给 `MarkdownView` 的 `source` 加 120ms 防抖（单独的 `deferredSource` state，或 `useDeferredValue`）。「预览」独占 tab 时不必防抖 | 滚动同步靠 `data-line`，防抖期间行号短暂偏一点，可接受 |
| B6 排版偏好 | 字号（13/14/15/16/18）、行高（1.6/1.8/2.0）、栏宽（46rem / 60rem / 满栏）进 `kb.layout`，命令面板与外观页各一个入口 | 纯本机偏好 |
| B9 双链悬停 | hover `.cm-md-wiki` 300ms → `hoverTooltip` 拉 `/api/v1/notes/:id` 摘要，显示标题 + 前 200 字；未创建的显示「未创建，点击新建」 | 复用现有 wiki 解析；请求要能被 hover 移开时 abort |
| B10 渲染项开关 | 把「图片 / 行内公式 / 块级公式 / 表格 / 图 / 图片」做成一组 facet 开关，默认全开 | 只加开关，不改渲染逻辑 |

### P10 兼容性、无障碍、效果

| 条目 | 做法 |
|---|---|
| D1 输入法 | wysiwyg 下把常驻的 `•` 与复选框从 `Decoration.replace(widget)` 改成 **`Decoration.mark` + 压扁原字符（`font-size:.01em`）+ 行装饰的 `::before` 画符号**。原字符还在 DOM 里，光标前后不再紧邻小部件。复选框仍要可点，改成行装饰上的 `::before` + 行内点击命中判定，或保留小部件但**只在光标不在本行时**替换 |
| D2 手机 | `EditorView.contentAttributes` 在 `(pointer: coarse)` 下改成 `autocapitalize="sentences"`、`autocorrect="on"`；键盘上方加一条工具条（粗体 / 斜体 / 列表 / 任务 / 链接 / 双链 / 代码 / 撤销），用 `visualViewport` 的 `resize`+`offsetTop` 定位，按钮 `mousedown` 里 `preventDefault` 以免收键盘 |
| D3 拼写检查 | `spellcheck` 做成偏好，默认**开**（这是散文编辑器不是代码编辑器），存 `kb.layout` |
| D4 Tab | 去掉无条件的 `indentWithTab`。改成：补全菜单开着 → 补全接管；光标在列表项内 → 缩进/反缩进该项；其余情况**放行让 Tab 移焦**。补一条 `Esc` 后 Tab 一定能出去。`.cm-content` 加 `aria-label="笔记正文"` |
| C1/C2 块感 | 代码块与引用块的首行 / 末行各加一个类（`cm-md-code-first` / `-last`），圆角与上下留白只画在首尾行 |
| C3 活动行 | `highlightActiveLine()` 移进 wysiwyg 隔间，即时渲染下关掉 |
| C4 标题留白 | 标题行的行装饰加 `margin-block`，与预览侧对齐 |
| C5 图片 | `onerror` 换成失败占位（显示 alt + 源地址）；`loading="lazy"`；点击放大复用预览侧的图片查看逻辑 |
| D5 验收 | `verify-editor-cdp.mjs` 补：中文输入法组词（CDP `Input.imeSetComposition`）、触摸点击双链、Tab 移焦、协同撤销 |

### P11 功能（要先改规格）

规格 §9.2 白纸黑字「一期不做：Callout、脚注、自定义 HTML」。下面三条**必须先改规格再动手**，
否则渲染器、文档站、分享页、MCP 返回会不一致：

| 条目 | 代价 |
|---|---|
| Callout `> [!NOTE]` | markdown-it 插件 + CM6 装饰 + 主题变量 + 导出到 Obsidian 原生可读（GitHub 只认 5 种，其余降级成普通引用） |
| 脚注 | 同上，外加「点击跳转 / 回跳」的锚点约定 |
| `==高亮==` | Obsidian 私有语法，导到别处会显示成字面量 `==`。要做就要在导出文档里写清楚 |

另外两条**不需要改规格**，因为改的是合法的 fence 信息串与纯显示：

- 代码块加语言标签 + 复制按钮 + 语言下拉（改 ` ```lang ` 那一行，是合法源码改动）。
- 图片显示宽度可拖：**宽度不进 Markdown**，存 `kb.image-width`，与表格列宽同一条口径（设计 17 §3.5）。

### P12 性能

| 条目 | 做法 |
|---|---|
| E1 | `blockField` 的重建加两道闸：① 语法树没变且文档没变时，只有当**新旧选区与任一块级件范围的相交关系发生变化**才重建；② 用 `RangeSet.map` 先把旧集合跟着改动平移，只重算受影响的那一段 |
| E2 | 记一个 `dragging` 标志（`mousedown`→`mouseup`），拖选期间跳过重建，松手补一次 |
| E3 | 列宽表读一次缓存在模块级，`storage` 事件时失效 |
| — | 补一条大文档基准：5 万字笔记，光标连续移动 100 次与连续输入 100 字的耗时，写进验收脚本，防回归 |

## 5. 明确不做

| 提议 | 为什么不做 |
|---|---|
| 换成 ProseMirror / Tiptap / Lexical / BlockSuite | 设计 17 §2 的四条约束仍然成立，调研没找到反例 |
| 块级 JSON 存储（思源那条路） | 四个写入方共用一份 Markdown，事实源不能变 |
| 独立画布（Excalidraw / draw.io） | 设计 17 §3.0；真要拖拽画布就走附件 |
| 列宽 / 图宽 / 折叠状态写进 Markdown | Markdown 没这些概念，写进去就导不回 Obsidian |
| 自定义 Vim 配置面板 | 设计 17 §3.3 已经拒过：那是另一个产品 |

## 6. 建议的落地顺序

```
P8（半天～一天，纯修错，先上）
  └ A1 协同撤销 → A2 触摸双链 → A4 行宽 → A3 死项

P9（体验，按收益排）
  └ B1 粘贴转换 → B2 悬挂缩进 → B5 预览防抖 → B3 折叠 → B4 斜杠匹配 → B6 排版偏好 → B7/B8 → B9 → B10

P10（兼容性与打磨，D1 要单独排期做实验）
P12（性能，做完 P9 再量，别提前优化）
P11（功能，先改规格）
```

每期做完跑 `node scripts/verify-editor-cdp.mjs` 与 `node scripts/verify-collab.mjs`，
并把生效的条目回写进 [设计 17](./设计/17-编辑器方案.md) 的分期表。
