# 部署

一个镜像三个命令：`api`、`worker`、`migrate`。生产只对外暴露**一个** HTTP 入口——
api 进程同时提供 API、MCP、公开页和前端静态文件，前端不是独立服务。

```
浏览器 / MCP 客户端
        │  https://kb.example.com
        ▼
   反代（Caddy / nginx，TLS 在这里终止）
        │  http://api:12099
        ▼
   api ──┬── /api/*      接口、/api/v1/mcp
         ├── /p /s       分享页与文档站
         └── 其余路径     前端 SPA（apps/web/dist）
   worker（不对外）        索引、抽取、邮件、备份、purge
   db（只绑本机）          Postgres + pgvector
```

## 一、准备 `.env`

```ini
APP_SECRET=用 openssl rand -base64 48 生成，别用默认值
PUBLIC_URL=https://kb.example.com
KB_DOMAIN=kb.example.com
API_PORT=12099
POSTGRES_USER=自己定，别用示例值
POSTGRES_PASSWORD=用 openssl rand -base64 32 生成
POSTGRES_DB=自己定
DATABASE_URL=postgres://${POSTGRES_USER}:${POSTGRES_PASSWORD}@db:5432/${POSTGRES_DB}
DATA_DIR=/data
```

`PUBLIC_URL` 是**唯一的对外地址真源**，下面这些全都读它，配错会连锁出问题：

| 用途 | 位置 |
|---|---|
| 会话 cookie 要不要带 `Secure` | `apps/api/src/lib/session.ts` |
| 验证邮件、重置密码的链接 | `apps/api/src/routes/auth.ts` |
| 设置页给用户复制的 MCP 地址 | `apps/api/src/routes/mcp.ts` |
| CORS 允许的来源 | `apps/api/src/index.ts` |

**不要从请求里猜对外地址**：反代会重写 Host，猜出来的是内网地址。

## 二、起服务

`docker-compose.yml` 里**没有数据库服务**，先决定库从哪来。

**接你自己的数据库**（已有实例、云上托管库）——推荐：

```bash
docker compose --profile app --profile tls up -d --build
```

`.env` 配好 `DATABASE_URL` 就行。若它写的是 `127.0.0.1`（在容器里指的是容器自己，不是宿主机），
另外配一个 `DATABASE_URL_INTERNAL` 指向数据库的实际地址；有真实主机名时不必配，会自动回落。

**用仓库自带的数据库** —— 叠加 [compose.db.yml](../compose.db.yml)：

```bash
docker compose -f docker-compose.yml -f compose.db.yml --profile app --profile tls up -d --build
```

自带库按 `.env` 的 `POSTGRES_USER` / `POSTGRES_PASSWORD` / `POSTGRES_DB` 建库，
叠加时会把三个应用服务的 `DATABASE_URL` 覆盖成 `@db:5432`，所以这条路不用配 `DATABASE_URL_INTERNAL`。

- `migrate` 先跑完（建表是 `CREATE TABLE IF NOT EXISTS`，可重复执行），`api` 和 `worker` 才启动。
- `db` 只绑 `127.0.0.1:${POSTGRES_HOST_PORT:-5432}`，`api` 只绑 `127.0.0.1:12099`，公网只有反代的 80/443。
- 只起数据库做本地开发：`docker compose -f docker-compose.yml -f compose.db.yml --profile db up -d db`
  （就是 `pnpm db:up`）。
- 可选 Redis（embedding 缓存，跨进程 / 重启仍命中）：叠加 [compose.redis.yml](../compose.redis.yml)，
  本地开发用 `pnpm redis:up`，并在 `.env` 写 `REDIS_URL=redis://127.0.0.1:6379`。
  不配也能跑，问答走进程内 LRU。整套容器部署再多 `-f compose.redis.yml`，
  api / worker 会自动拿到 `REDIS_URL=redis://redis:6379`。
  外部已有带密码的 Redis：**不要**再起仓库自带的，只写
  `REDIS_URL=redis://:密码@host:6379`（或 ACL：`redis://用户:密码@host:6379`）。
  密码含 `@` `:` `/` `#` 时改用 `REDIS_PASSWORD`，URL 里只留地址。

> 为什么数据库单独一个文件：compose 的变量插值是**全局**的，不看 profile。
> `POSTGRES_USER` 这些若写成 `${VAR:?}` 必填，哪怕不启用 db 服务也会让 `docker compose config`
> 直接报错，把接外部数据库的人挡在门外。拆开后两条路互不干扰。

### 构建卡在装依赖 / 直接失败

现象是 `pnpm install --frozen-lockfile` 反复 `error (23)` 重试，最后：

```
failed to solve: process "/bin/sh -c pnpm install --frozen-lockfile" did not complete successfully
```

不是配置问题，是到 npm 源的网络太差。在 `.env` 里换源即可（compose 会作为 build arg 传给 Dockerfile）：

```ini
NPM_REGISTRY=https://registry.npmmirror.com
```

在一台国内 NAS 上实测过：官方源 **88 KB/s**、npmmirror **5.5 MB/s**，差 64 倍；换之前装不完，换之后 441 个包 50 秒装完。
默认值仍是官方源——写死镜像源对国外网络反而更慢。

同一层还要从 Debian 源装 `python3 make g++`（`argon2` 是原生依赖要编译）。这步慢但只走一次，
装完就进镜像缓存；只要不动 Dockerfile 里它上面的内容，后续重建都会跳过。

第一个注册的用户是实例管理员。

## 三、反代

仓库自带 [docker/Caddyfile](../docker/Caddyfile)，`KB_DOMAIN` 指向你的域名即可自动签证书。用 nginx 的话：

```nginx
server {
    listen 443 ssl http2;
    server_name kb.example.com;

    ssl_certificate     /etc/letsencrypt/live/kb.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/kb.example.com/privkey.pem;

    client_max_body_size 64m;          # 附件上传

    location / {
        proxy_pass http://127.0.0.1:12099;
        proxy_http_version 1.1;
        proxy_set_header Host              $host;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;

        # AI 问答是流式的，必须关缓冲，否则前端要等整段生成完才动
        proxy_buffering off;
        proxy_read_timeout 300s;
    }
}
```

反代必须原样转发 `Authorization` 头——MCP 靠它认钥匙。Caddy 和 nginx 默认都会转发，
但如果你在中间加了会剥请求头的 WAF 或网关，MCP 会直接 401。

## 四、让云端客户端连上（OAuth）

部署到公网 HTTPS 之后，Claude.ai 连接器这类客户端可以直接填
`https://kb.example.com/api/v1/mcp`，走 OAuth 授权，不用手工贴钥匙明文。发现链路依赖
`/.well-known/oauth-protected-resource` 和 `/.well-known/oauth-authorization-server`
两个根路径端点——**反代不要把 `/.well-known` 截走**（有些 ACME 配置会），否则客户端
找不到授权服务器。细节见 [设计/11-MCP.md](设计/11-MCP.md#33-oauth-接入给云端客户端)。

跑在 `127.0.0.1` 上时云端客户端连不上，只有本机的 Claude Code / Cursor 能用，这是
网络可达性问题，不是配置问题。

## 五、备份

要备份的是两样，缺一不可：

1. **Postgres**：`docker compose exec db pg_dump -U kb knowledge > kb.sql`
2. **`kbdata` 卷**：笔记的 Markdown 原文和附件都在里面（`DATA_DIR`），不在数据库里。

实例内置的 S3 / WebDAV 备份见设置 → 备份，那套备份的是工作区快照，和上面的整机备份是两回事。

### 5.1 生成可恢复的整机备份

建议使用 PostgreSQL custom 格式，并把数据卷打成 tar；两份文件要放在同一批次、分别记录 SHA-256：

```bash
docker compose stop api worker web
docker compose exec -T db pg_dump -U kb -Fc knowledge > postgres.dump
docker run --rm -v knowledge_kbdata:/data:ro -v "$PWD":/backup alpine \
  tar -cf /backup/kbdata.tar -C / data
sha256sum postgres.dump kbdata.tar > disaster.sha256
docker compose start api worker web
```

### 5.2 离线预检与恢复

先停掉 API 和 worker，保留数据库服务；不要在正常写入期间覆盖：

```bash
docker compose stop api worker web
sha256sum -c disaster.sha256

# 先不传 confirm：脚本只检查文件、归档路径、目标 DATA_DIR，并打印确认指纹
DATABASE_URL='postgres://...' DATA_DIR='/绝对路径/kbdata' \
  pnpm restore:disaster ./postgres.dump ./kbdata.tar --maintenance

# 人工核对目标后，追加脚本输出的指纹
DATABASE_URL='postgres://...' DATA_DIR='/绝对路径/kbdata' \
  pnpm restore:disaster ./postgres.dump ./kbdata.tar --maintenance --confirm=<指纹>

pnpm db:push
docker compose --profile app up -d --build
docker compose exec db psql -U kb knowledge -c 'select count(*) from users; select count(*) from notes;'
```

脚本会保留恢复前数据库 dump 和旧数据目录；确认登录、随机笔记正文、附件下载、分享、worker 队列与健康检查均正常后再人工清理。恢复失败时脚本会尝试恢复这两份检查点。内置实例快照不含工作区正文和整个 `kbdata`，不能代替本流程。

## 六、升级

```bash
git pull
docker compose --profile app up -d --build
```

`migrate` 每次都会重跑，幂等。升级前先把上面两样备份做掉。

升级到思维导图二期（issue #62）时，`migrate` 会给 `mind_maps` 补上 `kind / search_text / trashed_at`
等列、新建 `mind_map_versions`，并把一期（mind-elixir 格式）的导图转换成新格式，
每张导图写一条来源为「迁移」的历史版本。重复执行不会重复转换。

### 画板（draw.io）

画板页面把 draw.io 编辑器嵌在 iframe 里，默认从 `https://embed.diagrams.net` 加载。
图的内容只在浏览器和 iframe 之间传递，不经过 diagrams.net 的服务器存储，但用户浏览器必须能访问这个域名。
内网或离线部署建议自建：

```bash
docker run -d --name drawio --restart unless-stopped -p 8080:8080 jgraph/drawio
```

给它单独一个子域名（例如 `drawio.example.com`）反代到 8080，然后在 `.env` 里写
`DRAWIO_URL=https://drawio.example.com` 并重启 api。api 会把这个来源加进 CSP 的 `frame-src`。
不需要画板时写 `DRAWIO_URL=off`。

## 七、常见问题

**登录后立刻掉线** —— `PUBLIC_URL` 的协议或域名和实际访问地址对不上，cookie 的 `Secure`
或 CORS 判断就会错。改完重启 api。

**MCP 客户端 401** —— 反代没转发 `Authorization`，或钥匙已吊销 / 过期。

**AI 回答要等很久才整段蹦出来** —— 反代开了响应缓冲，见上面的 `proxy_buffering off`
和 Caddy 的 `flush_interval -1`。

**页面刷新 404** —— 前端是 SPA，深链由 api 兜底返回 `index.html`。出现 404 说明请求没打到
api（反代路径写错），而不是前端的问题。
